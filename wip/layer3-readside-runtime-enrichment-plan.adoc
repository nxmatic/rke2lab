= Runbook & Doctor — Layer 3 Read-Side part 1: runtime enrichment (plan)
:toc: left

> *For agentic workers:* implement task-by-task; steps use `- [ ]`. Builds/tests runnable by Claude
> (compile/test/`pulumi preview` are dry-runs — CLAUDE.md). Single-dev, sequential, NO compat shims.
> *Docs convention:* prose + diagrams, no Java snippets (the executor has codebase context). Design:
> link:layer3-readside-runtime-enrichment-design.adoc[layer3-readside-runtime-enrichment-design.adoc].

*Goal:* the doctor's diagnosis (`⚕` summary + `℞` prescriptions) appears in the rendered runbook
(`target/runbook/adoc/…`, the VSCode-previewed surface), injected at runtime via the JGiven model;
then the Pulumi log is stripped to reference-pure.

*Architecture:* approach A — set `ScenarioModel.extendedDescription` (verified rendered by JGiven's
AsciiDoc visitor) from the `ConsultationLog`, joined to the scenario by a new
`Checkpoint.scenarioTitle()` identity. No Pulumi output changes (in-memory `ReportModel` only).

*Tech stack:* Java 25 (flox), JGiven 2.0.3 (`ReportModel`/`ScenarioModel`), JUnit5. Build:
`flox activate -- ./mvnw … -pl :seed-master -am -DskipTests=false`.

== Hard guard (do not break)
No Pulumi outputs change (the `extendedDescription` lives on the in-memory `ReportModel`, never in
state). `OutputBuilder` untouched; the write-side per-node `consultationReport` outputs untouched;
`ClusterReadinessProjectionTest` stays green. Scenario TITLES stay byte-identical (only their source
moves to the enum), so `NestedRunbookTest` and `RunbookRenderingTest` title assertions stay valid.

== Task 2: `render(ReportModel, ConsultationLog)` injects the diagnosis (TDD flip)

This is the core task and the TDD entry point. `RunbookRenderer.render` gains the `ConsultationLog`
and, before generating, sets each consulted scenario's `extendedDescription` to the formatted
diagnosis.

*Files:*

* Modify: `seed-master/src/main/java/io/nxmatic/rke2lab/controlplane/bdd/RunbookRenderer.java`
* Modify: `seed-master/src/test/java/io/nxmatic/rke2lab/controlplane/bdd/RunbookRenderingTest.java`

*Behaviour to implement in `render`:*

* New signature `render(ReportModel model, ConsultationLog consultations)` (no old overload kept —
  no-compat). Null-safe: a null/empty log injects nothing (healthy run renders exactly as today).
* For each `ConsultationReport` in the log: resolve its `Checkpoint` from `checkpointId()` (== slug),
  find the `ScenarioModel` in `model.getScenarios()` whose name matches `checkpoint.scenarioTitle()`,
  and set its `extendedDescription` to a formatted block: a "Diagnosis" line (the `⚕`
  `plan.generalistSummary()`) and one "Mitigation" line per prescription (`℞` programRef id + human
  hint + the remediation command from the payload/hint). Keep the formatting simple AsciiDoc text.
* Matching scenario name — VERIFIED: JGiven stores the `startScenario(...)` title VERBATIM in
  `ScenarioModel.getDescription()` (the AsciiDoc generator only capitalizes it for DISPLAY — the
  rendered "Systemd adapter becomes reachable" vs the stored lowercase "systemd adapter becomes
  reachable"). So the join is `scenario.getDescription().equals(checkpoint.scenarioTitle())` on the
  RAW string — derive from `scenarioTitle()`, do not hardcode, and do not account for the display
  capitalization (it is not in the stored value).

*Steps:*

- [ ] *Step 1 — flip the test (write the new expectation first).* Rewrite
  `RunbookRenderingTest.failed_node_records_into_the_shared_model_without_a_doctor` (and rename it to
  reflect the doctor now exists, e.g. `failed_node_renders_the_doctor_diagnosis`). It must: play the
  failing systemd-adapter scenario as today, BUT also build a `ConsultationLog` containing one
  `ConsultationReport` for `Checkpoint.SYSTEMD_ADAPTER.slug()` with a `RemediationPlan` whose
  prescription is `RemediationProgramRef.RESTART_UNIT`; call `render(model, consultations)`; then
  assert the rendered report NOW CONTAINS the diagnosis — the `restart-systemd-unit` text (replacing
  the old `assertFalse(... "Diagnosis")` / `assertFalse(... "Mitigation")` assertions, which become
  `assertTrue` on the diagnosis content). Keep the existing assertions that the FAILED scenario and
  its title still render.
- [ ] *Step 2 — run it, expect FAIL* (current `render` has no `ConsultationLog` param / does not
  inject): `flox activate -- ./mvnw test … -Dtest=RunbookRenderingTest`.
- [ ] *Step 3 — implement the new `render(ReportModel, ConsultationLog)`* per the behaviour above.
  Format the diagnosis from `RemediationPlan.generalistSummary()` and `Prescription` (programRef id +
  humanHint). Null-safe on empty log.
- [ ] *Step 4 — run the test, expect PASS.*
- [ ] *Step 5 — fix the OTHER caller now broken by the signature change.* `RunbookRenderingTest` was
  one caller; the production caller is `BootstrapStage` (Task 3 rewires it). To keep Task 2
  self-contained and green, TEMPORARILY confirm what breaks: run the full suite
  (`flox activate -- ./mvnw package … -DskipTests=false`). If `BootstrapStage` fails to compile
  because it still calls the old `render(model)`, that is expected — fix it minimally HERE by passing
  the `consultations` it already owns (this overlaps Task 3 Step 1; doing it here keeps the build
  green). Confirm 38 tests green, `ClusterReadinessProjectionTest` unchanged.
- [ ] *Step 6 — commit.* `feat(doctor): render the doctor diagnosis into the runbook node (extendedDescription)`.

NOTE: if Step 5 already rewired `BootstrapStage`, Task 3 becomes a verification-only checkpoint
