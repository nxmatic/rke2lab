= Runbook & Doctor — Plan (Increment E, layer 2: persist the consultation report)
:toc: left

> *Workshop:* lives in `wip/` alongside link:spec.adoc[spec.adoc] while `feature/runbook-doctor`
> is in progress; durable substance migrates to `docs/architecture/` before merge.
>
> *Scope:* this plan covers ONLY the stable, next-executable step — layer 2 of Increment E. The
> layer-3 DAG (medical record, node-level Diagnosis/Mitigation, `Doctor` supertype,
> edge-propagated access) and the open tensions (T2/T3/T4 + renderer fork) are DEFERRED until a
> first working doctor version exists (see spec §"Open tensions"). Do not build them here.

== Goal

Make the *consultation report* (today's `Dossier`, re-understood — see spec Increment E) the one
shape every checkpoint produces, and *stop dropping the doctor's plan*. Concretely:

. The `RemediationPlan` computed in `consultDoctor(...)` is no longer logged-then-discarded — it is
  carried on the consultation report.
. The cluster checkpoint's three per-phase dossiers fold into ONE consultation report carrying the
  raised `Set<Symptom>` (bounded by observability — the precondition chain raises ≈1 today).
. `VerificationResult` becomes a *projection* of that report (a view, not a second source of truth);
  `ReadinessOutputMapper` reduces to a thin view or is deleted (no-compat, same change).

NOT in this plan: renaming `Dossier`→`ExamReport` (abandoned — there is no exam layer); the
`Doctor` supertype; opening `Symptom`/`SpecialistDomain`/routing into contributed data (that is the
module-extraction chantier); any runbook-node rendering.

== Hard guard (do not break)

The Stage-B handoff contract must stay *byte-identical*: `handoffReady`→`nextStep`
(`bootstrap-management-cluster-then-apply-stageb-cluster-manifests` / `wait-for-cluster-readiness`),
`bootstrapStatus`, the 7 `cluster*` keys (`asOutputs()` at `ClusterBootstrapReadinessVerifier.java:504`),
and systemd-adapter's flat keys (`Dossier.toOutputMap()`). `ClusterReadinessProjectionTest` is the
pin; `docs/architecture/bootstrap/bootstrap-contract.adoc` documents it; an external Stage-B
orchestrator reads `nextStep` from stack outputs. Preview/up stack outputs unchanged from today.

== Operating context — read first

* *Single-dev, sequential, no compat shims* (link:../.claude/memory/sequential-no-compat-workflow.md[]):
  when a path is superseded, delete it and update all call sites in the same change.
* *Builds/tests run by the user* per CLAUDE.md — the agent proposes the command + expected output:
  `flox activate -- ./mvnw package -Dmaven.build.cache.skipCache=false -pl :seed-master -am -DskipTests=false`.
  NEVER `mvn install` to `~/.m2`.
* *`Dossier` keeps its name and `toOutputMap()`* — only its ROLE is clarified (it is the consultation
  report) and its CONTENT grows (carries the plan; cluster carries a set of symptoms).

== Steps (checkbox = tracking)

- [ ] *1. Carry the plan on the consultation report.* Add the `RemediationPlan` (or its rendered
  summary + prescriptions) to `Dossier` so `consultDoctor(...)` in both `SystemdAdapterStage` and
  `ClusterReadinessStage` stores it instead of only logging `⚕`/`℞`. Keep the inline log (operator
  UX) but stop discarding the data.
- [ ] *2. Cluster: one consultation report, a set of symptoms.* In `ClusterReadinessStage`, fold
  the per-phase `Map<ClusterReadinessPhase, Dossier>` into one consultation report carrying the
  raised `Set<Symptom>` (bounded by observability — the chain stops at the first blocking phase, so
  it is ≈1 today). `consultDoctor` consults on that set, not the first symptom alone.
- [ ] *3. `VerificationResult` → projection.* Build `VerificationResult` from the cluster's
  consultation report (single source of truth = the report). Reduce `ReadinessOutputMapper`/
  `VerificationResult` to thin views or delete the redundant one — no parallel mechanism. Verify the
  hard-guard keys byte-for-byte against `ClusterReadinessProjectionTest`.
- [ ] *4. Tests.* Adapt `NestedRunbookTest` / `DoctorScenarioTest` to the report shape; add a test
  proving the plan is persisted on the report (no longer dropped). `ClusterReadinessProjectionTest`
  stays green *byte-identical* (the guard).
