- [Non-null input rule](non-null-input-rule.md) — **code rule (user, 2026-06-19):** never accept a nullable parameter as input — every method input is non-null by convention, so the codebase is non-null-by-default by discipline (not yet machine-enforced). A null-guard on an input is a smell; represent optionality at the boundary (`Optional` returns, builder defaults, factories), never as a bare null param. IDE null-analysis warnings point at THIRD-PARTY edges (Optional/Framework/JUnit), not rule violations in our code. Machine-enforcing it (`@NonNullByDefault`) is a [[java-cleanup-backlog]] item.
- [A null arg to our API is a rule violation](null-arg-is-a-rule-violation.md) — **feedback (user, 2026-06-20, R4):** a `null` literal passed to OUR OWN API = a non-null-rule VIOLATION (not a smell to weigh); third-party edges + `Optional` are fine.
