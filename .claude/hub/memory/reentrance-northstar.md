**THE PRINCIPLE.** A system applies rules to its domain; re-entrance is the system applying those SAME
rules to ITSELF, with the SAME machinery — the observed subject changes, the mechanism does not. A
system that edicts rules for its domain but exempts itself has a blind spot precisely on itself; that
exemption is the tell, exactly as a write-path/read-path mismatch is the tell in
[[model-substrate-alignment]]. Re-entrance is alignment applied to the whole system: no exception for
self. This is why it is load-bearing, not aesthetic — it closes the blind spot.

**IT IS OBSERVED, NOT SPECULATIVE — 4 instances already at work (the user surfaced the common motif).**

* *units* — the app is a DAG of units AND its state is a DAG of units → self-hosting/reflexive (graved
  in rke2lab `unit-repository/unit-model.adoc`, the recursive-composition axiom). The unit model
  applies to the app that runs the unit model.
* *doctor* — the doctor diagnoses the provisioned system; the accumulating specialist's own memory is
  itself a Pulumi stack folded over history ([[specialist-as-ledger-northstar]]). The diagnostic
  machinery turns on its own substrate.
* *design* — the runbook is a LIVE render of the doctor DSL for the operator; we designers have our own
  DSL (vocabulary-view / capability-sentence / additivity-proof), so we owe ourselves the same: a
  DESIGNER RUNBOOK that renders the design state live (the playable half replayed from the code catches
  the lies a hand-written atlas can hide; the narrated half renders the reasoning). The rules we set
  for the operator, applied to us.
* *vocabulary* — the term-introduction ritual ([[dsl-term-introduction-ritual]]) was applied to its own
  new terms (embodiment, designer-runbook, and "re-entrance" itself): a term earns its place only by
  the sentences it lets us say. The rule submits to itself.

**THE TEST (how to spot a re-entrance debt).** For any rule the system imposes on its domain, ask: do
WE obey it? The hand-written atlas was a debt — it imposed "render live from real state" on the
operator runbook but exempted itself (hand-maintained, free to drift, e.g. the stale "mechanism C" the
spec carried until caught by hand this session). The designer runbook pays that debt.

**RELATION TO THE OTHER NORTH-STARS.** Re-entrance GENERALIZES both: [[model-substrate-alignment]] is
re-entrance on the persist/reconstruct axis (read and write through the same channel = the system not
cheating on itself); [[specialist-as-ledger-northstar]] is re-entrance on the doctor axis (the
specialist's memory obeys the same stack-as-record substrate it diagnoses). Re-entrance is the family
they belong to.

**MATERIALIZATION (the user wants it kept AND made concrete).** The first concrete materialization on
the table is the DESIGNER RUNBOOK — hybrid: a PLAYABLE half replayed from a hard substrate (the code:
grep/jdeps over the reactor, surefire counts, shipped capabilities — "is this green-to-blue true", "did
the walker retire", "how many units in the universe") and a NARRATED half (reasoning about not-yet-built
models, the design horizon). Candidate engine = JGiven, per the already-settled "one engine, two layers"
([[rke2lab:dsl-unification-topic]]): design scenarios as JGiven scenarios over the codebase, the
generated report IS the designer runbook. Open: the exact hard substrate, where the narrated half lives
so it does not rot (regenerated into the atlas?). See [[rke2lab:unitrepo-design-unification-state]]
(the capability-anchoring device the designer runbook renders) and rke2lab
`integration-atlas.adoc` (today hand-written = the re-entrance debt to pay).
