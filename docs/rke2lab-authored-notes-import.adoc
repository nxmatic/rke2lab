== Imported decisions retained

=== Two-phase operating model

Retain the strict split:

* Stage A: external/bootstrap provisioning (outside cluster)
* Stage B: in-cluster lifecycle reconciliation (CAPI/CAPRKE2/CAPN)

=== Stage A minimalism

Retain the principle that Stage A must stay narrow:

* bootstrap only what is needed for management API readiness
* emit deterministic handoff outputs for Stage B
* avoid becoming a long-running general reconciler

=== Canonical infrastructure ownership

Retain the model where foundational Incus host resources are treated as canonical platform inputs (project/network/profile/image), while Stage A manages bootstrap-specific resources (for now: seed instance lifecycle).

=== Phase 2 GitOps scope

Retain that kpt/GitOps guidance belongs to Phase 2 operations and does not need to be a hard dependency for Stage A bootstrap.

=== Next-stage migration note

For upcoming stages, progressively migrate host-mutating `host/systemd-units` workflows into Kubernetes init-container flows that execute via `nsenter` on host namespaces/filesystems.

Constraints to preserve during this migration:

* keep one canonical owner per workflow (no parallel systemd+init implementations)
* keep behavior idempotent and deterministic across reruns
* avoid introducing backward-compatibility aliases unless explicitly requested

=== Node setup StatefulSet/Job migration plan baseline (current repository state)

This note captures the migration baseline after runtime shim packaging and checksum-driven seed renewal updates.

Current implementation facts to preserve:

* host bootstrap scripts and units are still sourced from `manifests/src/main/resources/host/systemd-{scripts,units}` and materialized by `controlplane/incus`
* runtime host mutation already has a proven Kubernetes pattern in `runtime/flox-containerd-shim` using init-container + `nsenter`
* seed replacement is currently tied to Stage A provisioning checksum (`user.rke2lab.provisioningChecksum`) and image build checksum (`user.rke2lab.imageBuildChecksum`)

Phased migration intent:

. introduce a dedicated node-setup Kubernetes workload (start as DaemonSet/Job with init-container `nsenter` execution)
. migrate low-risk/idempotent scripts first (readiness/diagnostics and non-critical one-shot setup)
. migrate ordering-sensitive manifest install flows with explicit Kubernetes ordering and readiness gates
. only after parity, remove corresponding host systemd unit ownership and materialization

Guardrails:

* keep Stage A deterministic and avoid adding compatibility aliases
* maintain one canonical implementation per migrated workflow
* ensure each migrated step has explicit idempotency markers and observable logs

First implementation slice recommendation:

* create a `node-setup` layer with one small, verifiable host-operation script executed through init-container `nsenter`
* validate on `bioskop` with Flox active by compiling `manifests` + `controlplane`, applying generated manifests, and confirming idempotent rerun behavior

=== Runtime shim source model update (worktree-first)

Adopt a worktree-first model for runtime shim package builds:

* avoid hardcoded `git+file://...` source URLs for shim package inputs
* resolve package sources from a local worktree path (`path:` inputs)
* prefer a subtree layout when externalizing shim sources, so node provisioning remains self-contained from `rke2lab` ownership

Canonical execution modes for shim builder:

* `guest`: run directly from repository-owned resources during local iteration (default when omitted)
* `host`: run from `/srv/host/flox-shim.d` during node provisioning
* mode selection is explicit when passed as builder argument, not auto-detected

Guardrail:

* maintain one canonical path contract for both modes (`networking/kdns/src` preferred for subtree mode, optional explicit override via environment variable when needed)

=== Controlnode Stage A flow (policy-first)

The controlnode follows a strict policy-first flow before any Stage A provisioning side effects.

[plantuml,controlnode-stagea-flow,svg]
----
@startuml
title Controlnode Stage A flow (policy-first)

actor Operator
participant "controlplane.Main" as CP
participant "manifests.Main\n(shim-build)" as MF
participant "Pulumi Engine" as Pulumi
participant "ManifestUpdateGate\n(ServiceLoader)" as MUG
participant "ManifestSynthesisService\n(ServiceLoader)" as MSS
participant "Git Policy Checks\n(clean + flake lock)" as GIT
participant "Shim flake worktree" as Flakes
participant "IncusResourceBootstrap" as Incus

alt flake/package inputs changed
	Operator -> MF : run shim-build\n(host/guest as applicable)
	MF -> Flakes : refresh flake.lock/package outputs
	Operator -> Flakes : commit updated lock/package set
else no flake/package changes
	Operator -> Operator : no shim-build refresh required
end

Operator -> CP : run preview/up (or standalone run)
CP -> CP : detect Pulumi monitor env

alt Pulumi monitor present
	CP -> Pulumi : Pulumi.run(...)
else standalone
	CP -> CP : runStandalone()
end

CP -> CP : build BootstrapConfig
CP -> CP : enforceEntryGatePolicies(localWorktreePath)

CP -> MUG : enforce(worktreePath)
MUG -> MSS : load single provider
MUG -> MSS : synthesize(ephemeral request)
MUG -> MUG : validate smoke result\n(file exists, non-empty,\nunit hits > 0, domain count > 0)

CP -> GIT : enforce clean-git-worktree
CP -> GIT : enforce flake-lock-coherence

alt any gate fails
	CP --> Operator : fail fast (no Stage A changes)
else all gates pass
	CP -> CP : validate clusterName == bioskop
	CP -> Incus : apply()
	Incus --> CP : BootstrapResult
	CP -> CP : assemble deterministic outputs
	CP --> Operator : export outputs (Pulumi)\nor print outputs (standalone)
end
@enduml
----
