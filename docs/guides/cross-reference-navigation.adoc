= Cross-Reference Navigation Map
:toc: left
:toclevels: 2

This document visualizes the bidirectional cross-reference network between code
(JavaDoc) and documentation (AsciiDoc).

[NOTE]
====
*Paths are relative to this file* (`docs/guides/cross-reference-navigation.adoc`).
The repository root is two levels up (`../../`), so a link into the code reads
`../../osgi/domains/manifests/manifests-core/src/main/java/…` and a link to an
architecture doc reads `../architecture/<area>/…`. The manifests classes moved from
the old `manifests/src/main/java/…` module root to
`osgi/domains/manifests/manifests-core/src/main/java/…`; `BootstrapIdentity` moved
to the `manifests-contract` bundle (package `io.seedmatic.rke2lab.manifests.contract.profiles`).
====

== Navigation Patterns

=== Pattern 1: Top-Down (Concept → Code)

**Starting point**: Reading architecture documentation

1. Read link:../architecture/manifests/manifests-architecture.adoc[manifests-architecture.adoc] (the canonical model and synthesis flow)
2. Jump to the module's package overview → link:../../osgi/domains/manifests/manifests-core/src/main/java/io/seedmatic/rke2lab/manifests/package-info.java[manifests/package-info.java]
3. Click "See interface" → link:../../osgi/domains/manifests/manifests-core/src/main/java/io/seedmatic/rke2lab/manifests/ManifestsUnit.java[ManifestsUnit.java]
4. Navigate to a concrete registrar → link:../../osgi/domains/manifests/manifests-core/src/main/java/io/seedmatic/rke2lab/manifests/domain/GitopsDomainRegistrar.java[domain/GitopsDomainRegistrar.java] (actual code)

=== Pattern 2: Bottom-Up (Code → Context)

**Starting point**: Working on a specific class

1. Open link:../../osgi/domains/manifests/manifests-core/src/main/java/io/seedmatic/rke2lab/manifests/units/clusterapi/IncusIdentitySecretManifestsUnit.java[units/clusterapi/IncusIdentitySecretManifestsUnit.java] in IDE
2. Read the package's `package-info` → link:../../osgi/domains/manifests/manifests-core/src/main/java/io/seedmatic/rke2lab/manifests/units/clusterapi/package-info.java[units/clusterapi/package-info.java] (domain overview + doc links)
3. Click a "Related Documentation" link → link:../architecture/manifests/manifest-conditional-inclusion.adoc[manifest-conditional-inclusion.adoc] for policy context, or
   link:../architecture/bootstrap/bootstrap-identity-provider.adoc[bootstrap-identity-provider.adoc] for identity access

=== Pattern 3: Lateral (Similar Concepts)

**Starting point**: Understanding one domain, need to implement another

1. Read link:../../osgi/domains/manifests/manifests-core/src/main/java/io/seedmatic/rke2lab/manifests/units/gitops/package-info.java[units/gitops/package-info.java] for the domain shape
2. Compare with a sibling domain's overview, e.g.
   link:../../osgi/domains/manifests/manifests-core/src/main/java/io/seedmatic/rke2lab/manifests/units/clusterapi/package-info.java[units/clusterapi/package-info.java]
3. Both registrars (in `domain/`) return a `ManifestsDomain` whose units are referenced from the domain catalog

=== Pattern 4: Interface → Implementation

**Starting point**: Understanding the contract

1. Read link:../../osgi/domains/manifests/manifests-core/src/main/java/io/seedmatic/rke2lab/manifests/ManifestsDomainRegistrar.java[ManifestsDomainRegistrar.java] (interface with component diagram)
2. See the package overview → link:../../osgi/domains/manifests/manifests-core/src/main/java/io/seedmatic/rke2lab/manifests/domain/package-info.java[domain/package-info.java]
3. IDE "Show Implementations" → all registrars in the `domain/` package
4. Pick one → e.g., link:../../osgi/domains/manifests/manifests-core/src/main/java/io/seedmatic/rke2lab/manifests/domain/GitopsDomainRegistrar.java[domain/GitopsDomainRegistrar.java]

== Benefits of Bidirectional Cross-References

**Discoverability**:
* Developers find architecture docs from code
* Readers find real implementations from docs

**Context Switching**:
* Minimal - one click from code to context
* IDE integration makes it seamless

**Maintenance**:
* Changes to one trigger review of cross-references
* IDEs show broken links (dead code/doc)

**Learning**:
* New developers navigate concept → code → context
* Experienced developers navigate code → similar patterns

**Review**:
* Reviewers verify code matches documented architecture
* Doc updates prompt code verification

== IDE Integration

**IntelliJ IDEA**:
* HTML links in JavaDoc rendered as clickable
* AsciiDoc plugin renders links to Java files
* Ctrl+Click navigates across boundaries

**VS Code**:
* AsciiDoc extension renders `link:` as clickable
* JavaDoc preview renders HTML links
* Mermaid diagrams render inline

**GitHub**:
* Both AsciiDoc and JavaDoc rendered
* Relative links navigate within repository
* Search finds references across docs and code

== Maintenance Checklist

When updating architecture:

- [ ] Update system-level AsciiDoc documentation (start with link:../architecture/manifests/manifests-architecture.adoc[the hub])
- [ ] Update affected `package-info.java` files (`manifests-core` has 21 — 9 in the core tree + 12 under `units/<domain>`; `manifests-contract` has 3)
- [ ] Update affected interface and implementation JavaDoc
- [ ] Verify cross-references are bidirectional
- [ ] Verify relative paths are correct (this doc lives in `docs/guides/`; code is `../../osgi/…`, docs are `../architecture/…`)
- [ ] Update this navigation map if adding new docs
- [ ] Test links in IDE and GitHub preview
