== Navigation Patterns

=== Pattern 1: Top-Down (Concept → Code)

**Starting point**: Reading architecture documentation

1. Read link:manifests-architecture.adoc[manifests-architecture.adoc] (the canonical model and synthesis flow)
2. Jump to the module's package overview → link:../manifests/src/main/java/io/nxmatic/rke2lab/manifests/package-info.java[manifests/package-info.java]
3. Click "See interface" → link:../manifests/src/main/java/io/nxmatic/rke2lab/manifests/ManifestsUnit.java[ManifestsUnit.java]
4. Navigate to a concrete registrar → link:../manifests/src/main/java/io/nxmatic/rke2lab/manifests/domain/GitopsDomainRegistrar.java[domain/GitopsDomainRegistrar.java] (actual code)

=== Pattern 2: Bottom-Up (Code → Context)

**Starting point**: Working on a specific class

1. Open link:../manifests/src/main/java/io/nxmatic/rke2lab/manifests/units/clusterapi/IncusIdentitySecretManifestsUnit.java[units/clusterapi/IncusIdentitySecretManifestsUnit.java] in IDE
2. Read the package's `package-info` → link:../manifests/src/main/java/io/nxmatic/rke2lab/manifests/units/clusterapi/package-info.java[units/clusterapi/package-info.java] (domain overview + doc links)
3. Click a "Related Documentation" link → link:manifest-conditional-inclusion.adoc[manifest-conditional-inclusion.adoc] for policy context, or
   link:bootstrap-identity-provider.adoc[bootstrap-identity-provider.adoc] for identity access

=== Pattern 3: Lateral (Similar Concepts)

**Starting point**: Understanding one domain, need to implement another

1. Read link:../manifests/src/main/java/io/nxmatic/rke2lab/manifests/units/gitops/package-info.java[units/gitops/package-info.java] for the domain shape
2. Compare with a sibling domain's overview, e.g.
   link:../manifests/src/main/java/io/nxmatic/rke2lab/manifests/units/clusterapi/package-info.java[units/clusterapi/package-info.java]
3. Both registrars (in `domain/`) follow the `new ManifestsDomain(catalog id, deps, List.of(ManifestsUnit.lazy(...)))` shape

=== Pattern 4: Interface → Implementation

**Starting point**: Understanding the contract

1. Read link:../manifests/src/main/java/io/nxmatic/rke2lab/manifests/ManifestsDomainRegistrar.java[ManifestsDomainRegistrar.java] (interface with component diagram)
2. See the package overview → link:../manifests/src/main/java/io/nxmatic/rke2lab/manifests/domain/package-info.java[domain/package-info.java]
3. IDE "Show Implementations" → all registrars in the `domain/` package
4. Pick one → e.g., link:../manifests/src/main/java/io/nxmatic/rke2lab/manifests/domain/GitopsDomainRegistrar.java[domain/GitopsDomainRegistrar.java]

== Benefits of Bidirectional Cross-References

**Discoverability**:
* Developers find architecture docs from code
* Readers find real implementations from docs

**Context Switching**:
* Minimal - one click from code to context
* IDE integration makes it seamless

**Maintenance**:
* Changes to one trigger review of cross-references
* IDEs show broken links (dead code/doc)

**Learning**:
* New developers navigate concept → code → context
* Experienced developers navigate code → similar patterns

**Review**:
* Reviewers verify code matches documented architecture
* Doc updates prompt code verification

== IDE Integration

**IntelliJ IDEA**:
* HTML links in JavaDoc rendered as clickable
* AsciiDoc plugin renders links to Java files
* Ctrl+Click navigates across boundaries

**VS Code**:
* AsciiDoc extension renders `link:` as clickable
* JavaDoc preview renders HTML links
* Mermaid diagrams render inline

**GitHub**:
* Both AsciiDoc and JavaDoc rendered
* Relative links navigate within repository
* Search finds references across docs and code

== Maintenance Checklist

When updating architecture:

- [ ] Update system-level AsciiDoc documentation (start with link:manifests-architecture.adoc[the hub])
- [ ] Update affected `package-info.java` files (the manifests module has 15 — 5 core + 10 `units/<domain>`)
- [ ] Update affected interface and implementation JavaDoc
- [ ] Verify cross-references are bidirectional
- [ ] Verify relative paths are correct
- [ ] Update this navigation map if adding new docs
- [ ] Test links in IDE and GitHub preview
