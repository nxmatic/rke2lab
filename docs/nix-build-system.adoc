*Deprecated Architecture*: The systemd service-based build system documented below has been superseded by initContainer-based builds in the Flox runtime installer DaemonSet. Builds now run automatically as pods start, eliminating the need for separate systemd orchestration.

== Overview

This document describes the *legacy descriptor-driven* build system for RKE2 that:

* Defines build jobs in a single Nix build descriptor file (`flox-builds.yaml`)
* Uses a generic systemd service and build script
* Eliminates the need for package-specific services
* Scales easily to multiple packages and clusters

== Architecture

=== Files

. *Descriptor*: link:../rke2.d/bioskop/master/flox-builds.yaml[rke2.d/bioskop/master/flox-builds.yaml]
** Defines all Nix build jobs
** YAML format with version control
** Mounted in Incus container at `/srv/host/flox-builds.yaml`

. *Generic Build Script*: link:../make.d/incus/scripts/rke2lab-flox-build.sh[make.d/incus/scripts/rke2lab-flox-build.sh]
** Parses the descriptor with `yq`
** Iterates through all enabled jobs
** Builds packages and logs results
** Input: descriptor file path (default: `/srv/host/flox-builds.yaml`)

. *Generic Systemd Service*: ~~link:../make.d/incus/systemd/rke2lab-flox-build.service[make.d/incus/systemd/rke2lab-flox-build.service]~~ *DEPRECATED*
** ❌ No longer used - reference only
** ✅ Replaced by initContainer builds in Flox runtime DaemonSet
** Kept for historical reference only

. *Incus Mount*: `nix-builds.descriptor` in instance config
** Binds descriptor file to `/srv/host/flox-builds.yaml`
** Allows single source of truth

== Descriptor Format

[source,yaml]
----
version: "1"

jobs:
  - name: mesh                          # Job identifier
    description: "..."                  # Human-readable description
    enabled: true                       # Enable/disable without removing
    flakePath: /srv/host/git/.../      # Absolute path to flake directory
    outputDir: /tmp/mesh-build         # Where to symlink built packages
    logFile: /var/log/rke2-mesh-...    # Build log location
    packages:
      - name: headplane                # Package name (for symlink)
        attr: "packages.aarch64-linux.headplane"  # Nix attribute path
      - name: headplane-agent
        attr: "packages.aarch64-linux.headplane-agent"
----

== Adding New Build Jobs

=== Step 1: Create/verify flake in catalog

[source,bash]
----
ls rke2.d/bioskop/master/catalog/{component}/flake.nix
----

=== Step 2: Add job to descriptor

Edit link:../rke2.d/bioskop/master/flox-builds.yaml[flox-builds.yaml]:

[source,yaml]
----
jobs:
  # ... existing jobs ...
  - name: mycomponent
    description: "Build mycomponent from custom flake"
    enabled: true
    flakePath: /srv/host/git/nxmatic/rke2lab/rke2.d/bioskop/master/catalog/mycomponent
    outputDir: /tmp/mycomponent-build
    logFile: /var/log/rke2-mycomponent-build.log
    packages:
      - name: mycomponent
        attr: "packages.aarch64-linux.mycomponent"
----

=== Step 3: Update manifest install service (if needed)

Only if you have a manifest install service that depends on this package:

[source,ini]
----
[Unit]
...
After=rke2lab-flox-builds-complete.target
Requires=rke2lab-flox-builds-complete.target
----

=== Step 4: Test

. Restart the master node
. Check logs: `journalctl -u rke2lab-flox-build.service -f`
. Verify outputs: `ls -la /tmp/mycomponent-build/`

== Service Execution Flow (LEGACY)

[IMPORTANT]
====
This section documents the *legacy architecture*. 

**Current Architecture**: Nix builds now run as initContainers within pod lifecycle, triggered automatically by the Flox containerd shim when it encounters `flox.dev/environment` annotations. This eliminates the need for systemd orchestration.
====

[source]
----
RKE2 Server Started
  ↓
Manifest services apply custom resources (pods, deployments, etc.)
  ↓
Flox containerd shim intercepts pod creation
  ↓
For each pod with flox.dev/environment annotation:
  ├─ InitContainer runs nix build for Flox environment
  ├─ Each package built and installed into pod environment
  └─ Main container starts with all packages available
  ↓
No systemd service coordination needed
----

=== Legacy Flow (systemd-based, deprecated)

[source]
----
RKE2 Server Started
  ↓
rke2lab-mesh-manifests-install.service (and others)
  ↓
Kubernetes pods start with flox.dev/environment annotations

In parallel (non-blocking):
local-fs.target
  ↓
rke2lab-flox-build.service ❌ DEPRECATED
    │
    ├─ Read /srv/host/flox-builds.yaml
    │
    ├─ For each enabled job:
    │  ├─ Verify flake.nix exists
    │  ├─ For each package in job:
    │  │  └─ nix build .#packages.aarch64-linux.{package}
    │  └─ Create symlinks in outputDir
    │
    └─ Log results to journal + per-job log file
    ↓
Flox shim resolves environment to packages in /tmp/*-build/
----

== Key Features

=== 1. Centralized Configuration

* Single YAML file for all builds
* No need to create new systemd services
* Easy to review all build jobs at once

=== 2. Dynamic Job Discovery

* Script uses `yq` to parse jobs
* No hardcoding of job names
* Jobs can be disabled/enabled without deletion

=== 3. Detailed Logging

* Per-job log files
* Journal entries for systemd integration
* Build summaries with success/failure counts

=== 4. Error Handling

* Continues building other packages if one fails
* Reports failed jobs at end
* Non-zero exit if any job fails

=== 5. Extensibility

* One descriptor format for all clusters (bioskop, alcide, etc.)
* Can override `/srv/host/builds.yaml` per cluster
* Script is system-agnostic (works with any flake)

== Troubleshooting

[WARNING]
====
This section applies to the *legacy systemd-based build system* which is no longer active.

For the current DaemonSet-based approach, debug builds by:
1. Examining pod logs: `kubectl logs <pod> -c nix-builder` (initContainer logs)
2. Checking Flox containerd shim logs: `journalctl -u flox-containerd-shim -f`
3. Verifying environment annotations on pods: `kubectl get pod <pod> -o yaml | grep flox.dev`
====

== Multi-Cluster Support

For multiple clusters (bioskop, alcide, etc.):

=== Option A: Shared descriptor (preferred)

* Single `flox-builds.yaml` in rke2.d catalog root
* All clusters use the same build jobs
* Mount at `/srv/host/flox-builds.yaml` on each cluster

=== Option B: Cluster-specific descriptors

* `rke2.d/bioskop/master/flox-builds.yaml`
* `rke2.d/alcide/master/flox-builds.yaml`
* Mount each cluster's descriptor separately

=== Option C: Build aggregation

* Build packages once on central node
* Push to cachix.org or OCI registry
* All clusters pull from cache instead of building

== Migration to DaemonSet-Based Builds

=== What Changed

The systemd service approach has been superseded by a more elegant solution:

* **Old**: Separate systemd service runs `nix build` jobs before pods start
* **New**: Flox containerd shim runs `nix build` as initContainers when pods start
* **Benefit**: Builds happen just-in-time, no pre-execution needed

=== Backward Compatibility

The legacy systemd service (`rke2lab-flox-build.service`) has been removed. If you still reference it:

* ❌ Do *not* activate or enable the service
* ❌ Do *not* mount `flox-builds.yaml` for systemd service
* ✅ Instead, use Flox environment annotations on pods: `annotations: { flox.dev/environment: "namespace/environment-name" }`
* ✅ The Flox containerd shim will handle building automatically

=== Migration Steps

If you have existing pods using the legacy descriptor-based builds:

1. Create Flox environments for your packages (e.g., `nxmatic/kdns`)
2. Add `flox.dev/environment` annotation to pod specs
3. Remove any `After=rke2lab-flox-builds-complete.target` dependencies
4. Deploy updated manifests
5. Flox shim will automatically build environments via initContainers
