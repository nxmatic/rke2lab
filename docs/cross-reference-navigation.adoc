== Navigation Patterns

=== Pattern 1: Top-Down (Concept → Code)

**Starting point**: Reading architecture documentation

1. Read link:manifest-conditional-inclusion.adoc[manifest-conditional-inclusion.adoc] (system-level understanding)
2. Click "See implementation" link → link:../manifests/src/main/java/io/nxmatic/rk2lab/manifests/layers/common/LayerDomainRegistrar.java[LayerDomainRegistrar.java] (interface + component diagram)
3. Click "See example" link → link:../manifests/src/main/java/io/nxmatic/rk2lab/manifests/layers/gitops/package-info.java[gitops/package-info.java] (domain architecture)
4. Navigate to implementation → link:../manifests/src/main/java/io/nxmatic/rk2lab/manifests/layers/gitops/GitopsDomainRegistrar.java[GitopsDomainRegistrar.java] (actual code)

=== Pattern 2: Bottom-Up (Code → Context)

**Starting point**: Working on a specific class

1. Open link:../manifests/src/main/java/io/nxmatic/rk2lab/manifests/layers/clusterapi/IncusIdentitySecretManifestUnit.java[IncusIdentitySecretManifestUnit.java] in IDE
2. Read JavaDoc → see package-info reference
3. Click → link:../manifests/src/main/java/io/nxmatic/rk2lab/manifests/layers/clusterapi/package-info.java[clusterapi/package-info.java] (domain architecture with diagram)
4. See "Related Documentation" link
5. Click → link:manifest-conditional-inclusion.adoc[manifest-conditional-inclusion.adoc] (system-level understanding)

=== Pattern 3: Lateral (Similar Concepts)

**Starting point**: Understanding one domain, need to implement another

1. Reading link:../manifests/src/main/java/io/nxmatic/rk2lab/manifests/layers/gitops/package-info.java[gitops/package-info.java]
2. See cross-reference to link:manifest-conditional-inclusion.adoc[manifest-conditional-inclusion.adoc]
3. In doc, see cross-reference to link:../manifests/src/main/java/io/nxmatic/rk2lab/manifests/layers/clusterapi/package-info.java[clusterapi/package-info.java]
4. Compare patterns across domains

=== Pattern 4: Interface → Implementation

**Starting point**: Understanding the contract

1. Read link:../manifests/src/main/java/io/nxmatic/rk2lab/manifests/layers/common/LayerDomainRegistrar.java[LayerDomainRegistrar.java] (interface with component diagram)
2. IDE "Show Implementations" → list of all registrars
3. Pick one → e.g., link:../manifests/src/main/java/io/nxmatic/rk2lab/manifests/layers/gitops/GitopsDomainRegistrar.java[GitopsDomainRegistrar.java]
4. See package-info reference
5. Click → link:../manifests/src/main/java/io/nxmatic/rk2lab/manifests/layers/gitops/package-info.java[gitops/package-info.java] (domain context)

== Benefits of Bidirectional Cross-References

**Discoverability**:
* Developers find architecture docs from code
* Readers find real implementations from docs

**Context Switching**:
* Minimal - one click from code to context
* IDE integration makes it seamless

**Maintenance**:
* Changes to one trigger review of cross-references
* IDEs show broken links (dead code/doc)

**Learning**:
* New developers navigate concept → code → context
* Experienced developers navigate code → similar patterns

**Review**:
* Reviewers verify code matches documented architecture
* Doc updates prompt code verification

== IDE Integration

**IntelliJ IDEA**:
* HTML links in JavaDoc rendered as clickable
* AsciiDoc plugin renders links to Java files
* Ctrl+Click navigates across boundaries

**VS Code**:
* AsciiDoc extension renders `link:` as clickable
* JavaDoc preview renders HTML links
* Mermaid diagrams render inline

**GitHub**:
* Both AsciiDoc and JavaDoc rendered
* Relative links navigate within repository
* Search finds references across docs and code

== Maintenance Checklist

When updating architecture:

- [ ] Update system-level AsciiDoc documentation
- [ ] Update affected package-info.java files
- [ ] Update affected interface JavaDoc
- [ ] Verify cross-references are bidirectional
- [ ] Verify relative paths are correct
- [ ] Update this navigation map if adding new docs
- [ ] Test links in IDE and GitHub preview
