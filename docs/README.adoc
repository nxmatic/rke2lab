= RKE2Lab Documentation

Documentation for the RKE2Lab project - multi-cluster Kubernetes bootstrap via Pulumi, Incus, and Cluster API.

**Implementation Status Legend:**

* ✅ Complete - Fully implemented and operational
* 📋 Planned - Designed but not yet implemented
* ⚠️ Design Only - Design document, implementation not started
* ⚠️ Historical Reference - Archived documentation, may be outdated

== Core Architecture

=== Build & Packaging

* link:flake-build-entry-point.adoc[Flake as Build Entry Point] - Flake as the authoritative deploy build (Maven=dev loop, flake=release); store-built seed-master + manifests + NRI plugin
* link:netplan-blueprint-single-source.adoc[Netplan Blueprint Single Source] - Cross-repo single source of truth for the network underlay; the flake runs the netplan jar (IFD) and exposes a flat `lib.networkBlueprint` that nix-darwin-home consumes via `deriveMacs`
* link:systemd-resource-provisioning.adoc[Systemd Resource Provisioning] - Cross-module build pattern: manifests module owns systemd units/scripts, seed-master unpacks via manifests-d.zip

== Contributing

When adding new documentation:

1. **Use AsciiDoc format** (`.adoc`) for consistency
2. **Include Mermaid diagrams** for architecture visualization
3. **Add cross-references** - link to related docs AND code in both directions
4. **Update this index** - add your document to the appropriate section
5. **Follow the pattern**: Overview → Architecture → Usage → Troubleshooting
6. **Add package-info.java** for domain-level architecture co-located with code

=== Cross-Reference Checklist

When you document a new concept:

- [ ] Add forward links FROM your doc TO related docs
- [ ] Add backward links FROM related docs TO your doc
- [ ] **Add links FROM docs TO code** (interfaces, implementations, package-info)
- [ ] **Add links FROM code (JavaDoc) TO docs** (architecture, patterns)
- [ ] Update this README with your doc in the appropriate section
- [ ] Add to the "By Concern" or "By Development Phase" navigation section if applicable
- [ ] Add package-info.java with architecture diagram if documenting a domain/package
