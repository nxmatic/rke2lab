=== Doctor & Runbook (BDD diagnostic model)

The doctor is the diagnosis engine the bootstrap checkpoints consult on failure; the runbook is the
living-doc the medical record materializes. Increments A–D and Increment E (layers 2 + 3) are
implemented; the medical-model extensions are Design Only. All docs live in `architecture/doctor/`.

Proves each new model *additive* via monotone before/after figures.

* link:architecture/doctor/practitioners-as-components-design.adoc[Every actor a component — practitioner vs consultation] (⚠️ Design Only, not built) - Correcting the system so every actor declares itself as a component: the one knot is the Generalist's per-run `ClinicalAccess` (closed over the admitted patient). * link:architecture/doctor/efficacy-and-medecin-conseil-design.adoc[Efficacy & the médecin-conseil] (⚠️ Design Only, not built) - The `DriftSpecialist` reframed as a pure-reader efficacy analyst (the Sécu's médecin-conseil): produces a bounded, dated `EfficacyReport` referencing (not copying) the problem consultations + resolved symptoms, keeping the "why". Three verdicts (effective / ineffective / confounded-declared); external-change INFERENCE dropped (writes nothing → purity dissolved); the unexplained case is a renvoi to recruitment. Governs the drifted-out `TreatmentEfficacy` / `ProblemReview` types
* link:architecture/doctor/vocabulary-and-live-record-design.adoc[Vocabulary + Live-Record Wiring — Design] - The clinical-vocabulary refactor (Dossier→Observation et al.) + wiring the live doctor to retrieve the patient's record (held registry).

=== OSGi runtime & test substrate

* link:architecture/osgi/jgiven-osgi-testkit-handoff.adoc[jGiven-in-OSGi testkit — host handoff] (✅ Shipped) - **START HERE** to run BDD scenarios in-container. The `osgi/jgiven/` kit: `jgiven-wrap` (jGiven as a first-class bundle), `JGivenTestkit.felix()` boot helper + the shared `jgiven-fragment.bnd` include, and the probe host/`-test` fragment that is the template a host like doctor copies. The fragment-test model = white-box in OSGi.
* link:architecture/osgi/pulumi-edge-handoff.adoc[pulumi-edge — the first realised external edge] (✅ Shipped) - The reference template for extracting a `<target>-edge` per the link:architecture/patterns/frontier-playability-model.adoc[frontier-playability model]: `host/pulumi-edge` consolidates every Pulumi contact (both port faces, read+write) into one mutualised host module; the stray `PulumiInterventionLedgerWriter` rapatriated; ports unchanged. The recipe the five remaining edges replicate.
* link:architecture/osgi/osgi-boot-single-source-handoff.adoc[OSGi boot single-source — the embedded-bundle capability scan] (✅ Shipped) - Kills the hand-list of embedded model bundles (the "boot trap"): each model bundle self-declares `Provide-Capability: io.nxmatic.rke2lab.embed; type=model` in its `bnd.bnd`, and `OsgiRuntime.boot()` scans `META-INF/bundles/` and installs the carriers — boot-stack jars lack the marker, excluded objectively. Zero Java bundle-name literals; adding a bundle = one pom `artifactItem` + one capability line. The packaging prerequisite for `ssh-to-age-edge`.
* link:architecture/osgi/osgi-boot-decomposition-spec.adoc[OSGi boot decomposition — plan vs launch, one grammar] (✅ Shipped) - Dissolves the blurry `OsgiRuntime`/`SeedRuntime` pair into four phase-roles: the pure *decision* (`BootPlanner` → `BootPlan`) told apart from the effectful *act* (`FrameworkLauncher` → `BootedFramework`), expressed in the fluent pipeline grammar (`BootPipeline.embedded()`, the one entry the three exec apps use). A follow-on pax/JCL volet makes the seam law declarative: the boot stack is `optional` in `osgi/runtime` (a bundle on the flat host classpath is a wrong classpath), re-resolved by coordinate to stage it; the felix.scr import closure is one shared `BundleIndex.closeOverImports` frame with the per-jar action contributed as a handler.
* link:architecture/osgi/staging-gates-governance-spec.adoc[Staging gates & their governance] (📐 Design) - The build-time *staging laws* the `staging-extension` enforces from bundle bytecode (RECORD_PURITY, SPEC_COVERAGE, INSTANCE_DISCIPLINE) and the one repeatable annotation that governs how each reports: `@GovernedBy(Gate, EnforcementLevel)` per `package-info`, default `ERROR` (locked), opt down to `WARN`/`IGNORE` per gate. Fail-AT-end (collect all, fail once); read via ASM into the extension's mirror enums (build-order safe, no dependency on `domain-annotations`). A discipline becomes a gate seen at every build, not a review reminder.
* link:architecture/patterns/port-edge-domain-ownership.adoc[Port, edge, domain — told apart] (📐 Design) - The three roles by their one verb each: domain *calls*, port *declares* (the interface of call — passive, exported, NOT resolved), edge *provides* (the capability SCR resolves — the door). Who owns the port (the consumer, never the edge), why a pure point of contact like ssh-to-age has an edge but no `-core` and no port of its own, and the two resolution regimes (OSGi capability vs host assembly).
* link:architecture/osgi/ssh-to-age-edge-handoff.adoc[ssh-to-age-edge — the first edge in the OSGi world] (✅ Shipped) - The realisation of worked example B: `osgi/ssh-to-age-edge` converts an SSH key to an age key (`ProcessBuilder`), `@Component`-providing the consumer-owned `SshToAgeConverter` seam in `manifests-contract`. `DefaultManifestSynthesisService` resolves the age key in a pre-synthesis step and binds it on `ManifestSynthesisContext`, so `SopsAgeSecretManifestsUnit` only renders — synthesis takes its prerequisites, it does not fetch them (regex + inline `ProcessBuilder` gone). First external edge in OSGi: explicit frontier + inherited SCR IoC + free fail-fast (mandatory `@Reference`). First new client of the boot capability scan.
* link:architecture/osgi/cluster-edge-spec.adoc[cluster-edge — the kubectl contact, put in its place] (📐 Design) - The fourth external edge, mirroring dbus-systemd-edge. The cluster domain already has its core (`ClusterSpecialist`, distributed to its domain); this extracts the missing *port* and *edge*: a `cluster-contract` (the readiness probe + `ClusterReadinessPhase` rapatriated from doctor-contract + a phase↔`SchemaRef` enum), and a `cluster-edge` `@Component` shelling `kubectl` (pure ProcessBuilder, zero embedded jars). The host (seed-master) keeps the bootstrap gates, kubeconfig poll, policy projection and orchestration. Carries the one open design choice (the grain of the contact seam) as two C4 options for arbitration.
* link:architecture/osgi/bbox-edge-spec.adoc[bbox-edge — the router-reconciliation contact, put in its place] (✅ Shipped) - The sixth external edge, second sweep extraction. Makes `java-bbox-api-client` an OSGi bundle (bnd, imported not embedded — gson too) and puts the DHCP-reservation contact behind `bbox-contract`'s `BboxReconciler` verb over a home vocabulary (`BboxReservationRequest`/`BboxRowOutcome`/`BboxAction`, no library type crosses). Purified 5 host files off `io.nxmatic.bbox.*`; the Pulumi resource graph now mirrors flat outcomes the edge produced. `BboxStage` resolves the reconciler from the registry and threads it through the probe/orchestrator.
* link:architecture/osgi/incus-edge-spec.adoc[incus-edge — the Incus-host contacts, put in their place] (✅ Shipped) - One domain, one bundle pair, TWO contacts (an Incus instance needs an Incus image — the same concern). `incus-contract` declares both: `IncusInstanceContact` (`isReachable(IncusExecRequest)`, satisfied by `ssh … incus exec`, extracted from the host `SeedSystemdAdapterEndpointGate` — the first sweep extraction, which validated the working unit: one contact extracted atomically, port + edge + consumer re-wiring) and `ImageBuilder` (`build(ImageBuildRequest)` + `recipeDigest()`, satisfied by `distrobuilder build-incus` locally / an ssh recipe remotely, the heaviest and LAST extraction — a build entangled with a Pulumi resource). `incus-edge` publishes both @Components (pure ProcessBuilder, the remote recipe as a single-source bundle resource). The host keeps the readiness orchestration and the Pulumi `Image` resource + artifact cache, and folds `recipeDigest()` into its cache key where the script bytes used to hash — preserving cache-invalidation without holding the script.
* link:architecture/osgi/auth-edge-spec.adoc[auth-edge — the credential-CLI token contact, put in its place] (✅ Shipped) - The seventh external edge, third sweep extraction, mirroring incus-edge's bare `ProcessBuilder` shape. `auth-contract` declares `AuthTokenContact` (`tokenFor(AuthTokenSource) → Optional<String>`) over a flat `GITHUB`/`FLOXHUB` enum; `auth-edge` maps each source to `gh auth token` / `flox auth token`. The host `IncusResourceBootstrap.LaunchSecretsUpdater` keeps the env-var precedence and the comment-preserving YAML upsert, drops its inlined `captureCommandOutput`, and composes the contact from the registry (`singleSpiProvider` on the held `BootedFramework`). Reading `System.getenv` crosses no frontier — it stays host.
* link:architecture/osgi/controlplane-to-osgi-migration-spec.adoc[control-plane → OSGi — the external-contact sweep] (✅ Shipped) - The index and rationale of the completed sweep. The criterion (learned the hard way, after an "87 Pulumi-free files" framing was tried and reverted): a type migrates only if a bundle `@Component` contacts an external system (→ `-edge`) or rides its verb (→ `-port`) — placeability is necessary, not sufficient. The real surface was a handful of external contacts, each extracted atomically (port + edge + consumer re-wiring + boot proof): ssh-to-age, dbus-systemd, cluster (kubectl), incus (reachability + image-build), bbox (library-backed), auth (gh/flox). Orchestration, config input, the Pulumi resource graph and the scenario spine are placeable yet stay host — they are not contacts. Cross-references every edge spec.
