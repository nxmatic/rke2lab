= Systemd Target Ordering Improvements
:toc: left
:toclevels: 2

== Overview

This document describes the target ordering and dependency improvements made to create a proper startup sequence and ensure correct systemd behavior.

== Changes Implemented

=== 1. Target Creation Order and Dependencies

Targets are now created in dependency order with explicit `After=` and `Requires=`/`Wants=` relationships:

[source,text]
----
network → tools → bootstrap → rke2-server → manifests → secrets
----

==== Network Target (base)

[source,systemd]
----
[Unit]
Description=RKE2 Lab Network Infrastructure Target
After=network-online.target
Wants=network-online.target
PartOf=rke2lab.target

[Install]
WantedBy=rke2lab.target
----

**Purpose**: Base networking setup (route cleanup, config, wait, debug).

**Dependencies**: Only depends on system `network-online.target`.

==== Tools Target

[source,systemd]
----
[Unit]
Description=RKE2 Lab Tools and Utilities Target
After=rke2lab-network.target
Wants=rke2lab-network.target
PartOf=rke2lab.target

[Install]
WantedBy=rke2lab.target
----

**Purpose**: Install Nix, Flox, Cachix (needs network).

**Dependencies**:
- `After=rke2lab-network.target` → waits for network
- `Wants=rke2lab-network.target` → pulls in network (weak dependency)

**Rationale**: Tools need network to download packages, but use `Wants=` not `Requires=` so tools target can proceed even if network has issues (may fail later, but systemd won't block the target).

==== Bootstrap Target

[source,systemd]
----
[Unit]
Description=RKE2 Lab Early Bootstrap (pre-server)
After=rke2lab-network.target rke2lab-tools.target
Requires=rke2lab-network.target rke2lab-tools.target
PartOf=rke2lab.target

[Install]
WantedBy=rke2lab.target
Also=rke2lab-network.target
Also=rke2lab-tools.target
----

**Purpose**: Pre-server setup (bootstrap-env, config, install, systemd-link, containerd config).

**Dependencies**:
- `After=rke2lab-network.target rke2lab-tools.target` → waits for both
- `Requires=rke2lab-network.target rke2lab-tools.target` → strict dependency (fail if they fail)
- `Also=...` → enabling bootstrap automatically enables network and tools

**Rationale**: Bootstrap absolutely requires both network and tools to succeed (uses Flox commands, needs files from host), so `Requires=` is appropriate. The `Also=` ensures you can't accidentally enable bootstrap without its prerequisites.

==== Manifests Target

[source,systemd]
----
[Unit]
Description=RKE2 Lab Manifest Installers (post-server)
After=rke2lab-bootstrap.target rke2-server.service
Requires=rke2-server.service
PartOf=rke2lab.target

[Install]
WantedBy=rke2lab.target
----

**Purpose**: Install Kubernetes manifests after RKE2 server starts.

**Dependencies**:
- `After=rke2lab-bootstrap.target rke2-server.service` → waits for bootstrap completion and server
- `Requires=rke2-server.service` → fails if server fails (can't install manifests without API server)

**Rationale**: Manifests installation requires the Kubernetes API server to be available. Note we use `After=` for bootstrap but not `Requires=` - bootstrap failure already killed the server (via its dependencies), so we don't need duplicate hard dependency.

==== Secrets Target

[source,systemd]
----
[Unit]
Description=RKE2 Lab Secrets Installers (post-server)
After=rke2lab-bootstrap.target rke2lab-manifests.target rke2-server.service
Requires=rke2-server.service
PartOf=rke2lab.target

[Install]
WantedBy=rke2lab.target
----

**Purpose**: Apply secrets after manifests are installed.

**Dependencies**:
- `After=rke2lab-bootstrap.target rke2lab-manifests.target rke2-server.service` → waits for all three
- `Requires=rke2-server.service` → strict server dependency

**Rationale**: Secrets may reference namespaces/resources created by manifests, so we order after manifests target. Some secrets might work without manifests being complete, so we don't make manifests a hard `Requires=`, just ordering via `After=`.

=== 2. Main Target Explicit Dependencies

The `rke2lab.target` now explicitly declares all its sub-targets and the server:

[source,systemd]
----
[Unit]
Description=RKE2 Lab Bootstrap Target
Documentation=https://github.com/nxmatic/rke2lab
After=rke2lab-network.target rke2lab-tools.target rke2lab-bootstrap.target rke2-server.service
Wants=rke2lab-network.target rke2lab-tools.target rke2lab-bootstrap.target rke2lab-manifests.target rke2lab-secrets.target rke2-server.service

[Install]
WantedBy=multi-user.target
----

**Purpose**: Make the full hierarchy visible and ensure all components are pulled in.

**Dependencies**:
- `After=...` → defines ordering (network → tools → bootstrap → server, then manifests/secrets)
- `Wants=...` → pulls in all sub-targets and server (visible in `list-dependencies`)

**Rationale**: The `Wants=` makes `systemctl list-dependencies rke2lab.target` show the complete tree. The `After=` ensures systemd knows the startup order. We use `Wants=` not `Requires=` because:

1. We want best-effort startup - if manifests fail, that shouldn't kill the whole target
2. Individual services already have their own failure handling
3. The main target should reach "active" state even if some optional services fail

=== 3. Service Corrections

==== vip-kubeconfig Service

**Before**:
[source,systemd]
----
[Install]
WantedBy=rke2-server.service  # Wrong - services shouldn't be wanted by other services
----

**After**:
[source,systemd]
----
[Unit]
...
PartOf=rke2lab.target

[Install]
WantedBy=rke2lab.target
----

**Rationale**: Services should be wanted by targets, not by other services. The `PartOf=` ensures it stops when the main target stops. The service still has `Requires=rke2-server.service` so it won't run without the server.

=== 4. Special Cases (Unchanged)

These services are intentionally NOT part of `rke2lab.target`:

==== remount-shared.service

[source,systemd]
----
[Unit]
DefaultDependencies=false
Before=local-fs.target

[Install]
WantedBy=local-fs.target
----

**Purpose**: Very early boot - remount root as shared for container runtimes.

**Why not part of rke2lab**: Runs during early boot, before multi-user.target. Must be part of `local-fs.target` (filesystem initialization).

==== zfs-early-umount.service

[source,systemd]
----
[Unit]
DefaultDependencies=false
Before=umount.target
Conflicts=umount.target

[Install]
WantedBy=umount.target
----

**Purpose**: Shutdown phase - unmount ZFS filesystems cleanly.

**Why not part of rke2lab**: Runs during shutdown, after everything else stops. Must be part of `umount.target` (filesystem shutdown).

== Startup Sequence

With these changes, the startup sequence is:

[source,text]
----
1. multi-user.target starts
   └─> rke2lab.target starts

2. rke2lab.target pulls in sub-targets:
   a. rke2lab-network.target
      └─> network services (route-cleanup, network-config, network-wait, network-debug)

   b. rke2lab-tools.target (waits for network)
      └─> tool installs (nix-install, flox-install, cachix-watch-store)

   c. rke2lab-bootstrap.target (waits for network + tools)
      └─> bootstrap services (bootstrap-env, config-install, install, systemd-link, containerd-config)

   d. rke2-server.service (waits for bootstrap)
      └─> RKE2 Kubernetes server starts

   e. rke2lab-manifests.target (waits for server)
      └─> manifest installers (cluster, storage, replication, gitops, networking, etc.)

   f. rke2lab-secrets.target (waits for server + manifests)
      └─> secrets installers (domain-specific secrets)

3. All sub-targets reach active state
   └─> rke2lab.target reaches active state
----

== Dependency Types Reference

=== After= (Ordering Only)

**Effect**: "Start after X completes".

**Does NOT**:
- Pull in the unit (need `Wants=` or `Requires=` for that)
- Fail if the unit fails
- Affect enable/disable

**Use when**: You need ordering but the dependency is already pulled in by something else, OR you want conditional ordering (if X runs, I run after it, but I don't require X to run).

=== Wants= (Weak Dependency)

**Effect**: "Pull in X when I start, but don't fail if X fails".

**Does NOT**:
- Define ordering (need `After=` for that)
- Prevent the unit from starting if X is missing
- Fail this unit if X fails

**Use when**: You want to start related services together, but each can succeed/fail independently.

=== Requires= (Strong Dependency)

**Effect**: "Pull in X and fail if X fails or can't start".

**Does NOT**:
- Define ordering (need `After=` for that)

**Use when**: This unit cannot function without X. If X fails, this unit should fail too.

**Note**: If X is stopped manually, this unit is also stopped.

=== PartOf= (Lifecycle Binding)

**Effect**: "Stop/restart me when X stops/restarts".

**Does NOT**:
- Define ordering
- Pull in the unit
- Affect startup dependencies

**Use when**: This unit is part of a larger system and should stop when that system stops.

**Note**: Only affects stop/restart propagation, not start.

=== Also= (Enable/Disable Propagation)

**Effect**: "When enabling/disabling me, also enable/disable X".

**Does NOT**:
- Affect runtime behavior
- Create dependencies
- Affect ordering

**Use when**: Units that should be enabled/disabled together (e.g., enabling a target should enable its prerequisite targets).

== Testing

=== Verify Target Order

[source,bash]
----
# Check that targets are ordered correctly
systemctl show rke2lab-bootstrap.target | grep "After="
# Should show: After=rke2lab-network.target rke2lab-tools.target

systemctl show rke2lab-tools.target | grep "After="
# Should show: After=rke2lab-network.target
----

=== Verify Dependency Tree

[source,bash]
----
systemctl list-dependencies rke2lab.target
# Should show hierarchical tree with all sub-targets
----

=== Test Startup Sequence

[source,bash]
----
# Start the target and watch the order
systemctl restart rke2lab.target
journalctl -u rke2lab.target -u 'rke2lab-*.target' -u 'rke2lab-*.service' -f

# Should see:
# 1. network services
# 2. tools services
# 3. bootstrap services
# 4. rke2-server
# 5. manifest installers
# 6. secrets installers
----

=== Test Failure Propagation

[source,bash]
----
# Stop the main target - should stop all services
systemctl stop rke2lab.target
systemctl status 'rke2lab-*.service' | grep Active
# All should show "inactive (dead)"

# Check PartOf relationships
systemctl show rke2lab-bootstrap-env.service | grep PartOf
# Should show: PartOf=rke2lab-bootstrap.target
----

=== Test Enable Propagation

[source,bash]
----
# Disable all, then enable bootstrap
systemctl disable rke2lab-bootstrap.target rke2lab-network.target rke2lab-tools.target

systemctl enable rke2lab-bootstrap.target

# Check that network and tools were also enabled (via Also=)
systemctl is-enabled rke2lab-network.target
systemctl is-enabled rke2lab-tools.target
# Both should show "enabled"
----

== Benefits

### Predictable Startup Order

Services start in the correct order: network → tools → bootstrap → server → manifests → secrets.

### Visible Hierarchy

`systemctl list-dependencies` shows the actual architecture, not a flat list.

### Failure Containment

- Network failure stops tools (which needs network)
- Tools failure stops bootstrap (which needs tools)
- Bootstrap failure stops server (which needs bootstrap)
- Server failure stops manifests and secrets (which need API server)

### Clean Shutdown

Stopping `rke2lab.target` cleanly stops all services in reverse order via `PartOf=`.

### Correct Enablement

Enabling bootstrap automatically enables its prerequisites (network, tools) via `Also=`.
