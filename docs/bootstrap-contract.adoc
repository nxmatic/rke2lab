= Stage A Bootstrap Contract
:toc: left
:toclevels: 3

This document defines the first executable contract for Pulumi-based management-cluster bootstrap.

== Scope

Stage A provisions and validates the management cluster seed (`bioskop`) and emits deterministic handoff outputs.

Stage A is intentionally limited to bootstrap responsibilities and is *not* the long-running node reconciler.

After Stage A reaches readiness, Stage B controllers (CAPI + CAPN + CAPRKE2) own lifecycle management for additional control-plane and worker nodes.

== Sequencing decision (Mar 2026)

Stage A completion is the current delivery priority.

Stage B requirements are intentionally deferred until Stage A bootstrap behavior is fully validated end-to-end.

The Stage B entry point is already established through exported Stage A handoff/orchestration outputs (`nextStep`, readiness status, registry summary, and image build summary), which are expected to be consumed by a later Stage B manifest producer/apply flow.

== Future integration note (NixOS host deployment resources)

Planned direction after Stage A stabilization:

* Integrate NixOS host deployment into cluster bootstrap as explicit resources (instead of ad-hoc host-side imperative orchestration).
* Keep Pulumi as top-level orchestrator for dependency ordering, readiness gates, and output contracts.
* Introduce a new adapter module that maps NixOps4 components/resources into Pulumi-managed resources for bootstrap-time host deployment convergence.

This is a forward-looking plan and does not change current Stage A delivery scope.

== Non-goals

The following are explicitly out of scope for Stage A:

* Ongoing reconciliation of non-seed nodes
* Horizontal scaling workflows for management or workload clusters
* Replacement/rolling updates for post-bootstrap nodes

== Required inputs

[cols="1,3",options="header"]
|===
|Input |Description
|`clusterName` |Management cluster identifier (default: `bioskop`)
|`incusProfile` |Incus profile set for management seed node
|`networkProfile` |Network profile/selector used for seed node
|`sshHost` |NixOS VM endpoint used for orchestration and probes
|`readinessTimeout` |Max wait duration for API readiness
|===

== Required outputs

[cols="1,3",options="header"]
|===
|Output |Description
|`managementClusterName` |Resolved management-cluster name
|`apiEndpoint` |Control-plane endpoint for API access
|`kubeconfigRef` |Path or secret reference for bootstrap kubeconfig
|`seedNodeId` |Provider-specific identifier for the seed node
|`seedImageFingerprint` |Immutable image fingerprint used for seed provisioning
|`seedProvisioningChecksum` |SHA-256 fingerprint of Stage A provisioning inputs materialized for seed bootstrap
|`seedImageBuildChecksum` |SHA-256 fingerprint of Incus image build inputs
|`incusProject` |Resolved Incus project used during seed provisioning
|`handoffReady` |Boolean flag indicating Stage B installation prerequisites are satisfied
|`bootstrapPhase` |Terminal phase (`Ready` or `Failed`)
|===

== Stage B handoff contract

A successful Stage A run must provide enough information to install and reconcile CAPI management-plane components:

. Management API endpoint and kubeconfig reference are valid.
. Seed infrastructure identity is emitted (`seedNodeId`, project, image fingerprint).
. Seed drift identity is emitted (`seedProvisioningChecksum`, `seedImageBuildChecksum`).
. Handoff marker is explicit (`handoffReady=true`).
. Re-run safety is preserved (idempotent bootstrap with deterministic seed replacement when checksum inputs change).

== Readiness gates

. Seed node provisioned and reachable.
. Seed host systemd preconditions converged (environment mount present, no pending jobs, no failed units).
. RKE2 server active and healthy on seed.
. Kubernetes API reachable and responsive.
. Minimum bootstrap manifests applied successfully.
. **Verification stage** (added 2026-06-04): BDD diagnostic scenarios run post-provisioning to verify infrastructure health and publish actor-specific reports.

Operator observability improvement:

* Stage A exports `systemdRuntimeStatusSummary` as an explicit runtime-status contract so operators can see why readiness is blocked without ad-hoc host shelling.
* **Diagnostic reports** (added 2026-06-04): Stage A publishes BDD scenario results as ConfigMap (YAML for system), stack outputs (JSON for orchestrator), and filesystem reports (AsciiDoc for operator). See link:bdd-diagnostic-pattern.adoc[BDD Diagnostic Pattern] for details.

== Verification Stage

**Added:** 2026-06-04

The verification stage runs after infrastructure provisioning completes. It executes BDD diagnostic scenarios embedded in production code to verify deployment health and capture targeted diagnostics on failure.

=== Integration Point

The verification stage follows the fluent pipeline grammar:

[source,java]
----
.then()
.during("verification", verify -> verify
    .runDiagnosticScenarios()
    .publishReports())
.then()
.during("outputs", outputs -> outputs.exportOrPrint())
----

=== Verification Flow

. Infrastructure resources provisioned (Incus instance, systemd units, manifests)
. Verification stage invokes embedded diagnostic scenarios
. Scenarios probe infrastructure using production code methods
. Success: clean report (checkmarks only)
. Failure: targeted diagnostic capture (systemd status, journal logs, port checks, remediation steps)
. Reports published in three formats for three actors

=== Actor-Specific Publication

[cols="1,2,2",options="header"]
|===
|Actor |Format |Channel
|System |YAML metrics |ConfigMap `rke2lab-diagnostic-reports`
|Orchestrator |JSON decision data |Stack output `diagnosticReports`
|Operator |AsciiDoc troubleshooting guide |Filesystem `/var/lib/rke2lab/reports/`
|===

=== Report Contents by Actor

**System (YAML):**
```yaml
status: healthy
metrics:
  dbusProbeLatencyMs: 45
  dbusEndpointReachable: true
  requiredServicesActive: [rke2-server, containerd]
```

**Orchestrator (JSON):**
```json
{
  "status": "healthy",
  "shouldRollback": false,
  "canProceedToNextStage": true,
  "scenariosPassed": 5
}
```

**Operator (AsciiDoc):**
```asciidoc
= Diagnostic Report

== Scenario: systemd_adapter_becomes_reachable
✓ Given incus instance exists
✓ When systemd adapter probe runs
✓ Then dbus endpoint responds

Status: HEALTHY
```

Or on failure:
```asciidoc
✗ When systemd adapter probe runs

=== Diagnostic: dbus-probe
Connection refused at port 12434

==== systemd-units
rke2lab-dbus-tcp-system-bus.service: inactive (dead)

==== Remediation
1. Check if socat is installed
2. Verify script exists at /srv/host/systemd-scripts.d/
```

See link:bdd-diagnostic-pattern.adoc[BDD Diagnostic Pattern] for full implementation details.

== Failure semantics

* Fail fast with explicit reason code and message.
* Emit last successful phase for resumability.
* Preserve diagnostics references for break-glass operations.
* **Diagnostic scenarios** (added 2026-06-04): On verification failure, AsciiDoc reports contain targeted diagnostics (systemd status, logs, port checks) and remediation steps specific to the failure mode.

== Acceptance criteria (Slice 1)

* `pulumi up` reaches `bootstrapPhase=Ready` on a clean environment.
* Re-run is idempotent (no destructive drift for unchanged config).
* Outputs are sufficient for Stage B CAPI management-plane install.
* Stage A implementation does not provision non-seed nodes after handoff.
