= ContextRegistry Architecture
:toc: left
:toclevels: 3
:sectanchors:
:sectlinks:

[.lead]
Type-safe registry pattern for computed records in the bootstrap pipeline, eliminating constructor parameter explosion and enabling fail-fast precondition validation.

*Status*: Implemented (2026-05-31, commits `b71ed00f`, `4a921d61`)

== Overview

=== The Problem

The bootstrap pipeline creates multiple metadata records during execution that need to be shared across stages:

* `DeploymentMetadata` - git context and timestamp
* `ProvisioningMetadata` - target checksums and paths
* `BuildMetadata` - image and manifest checksums
* `RuntimeMetadata` - environment and systemd summaries

Passing these through stage constructors created a **5+ parameter anti-pattern**:

[source,java]
----
// ❌ BEFORE: Parameter explosion
ProviderStage(ApplyState state, BootstrapConfig config,
              PulumiIncusImageProvider imageProvider,
              DeploymentMetadata deployment,
              ProvisioningMetadata provisioning)
----

=== The Solution

The `ContextRegistry` provides type-safe storage and retrieval of computed records:

[source,java]
----
// ✅ AFTER: Context + State pattern
ProviderStage(BootstrapContext context, ApplyState state)

// Type-safe record access
BuildMetadata build = state.registry.require(BuildMetadata.class);
----

**Benefits:**

* *Type safety* - No casting, compile-time type checking
* *Explicit lifecycle* - `register()` calls visible in pipeline flow
* *Fail-fast* - `require()` throws immediately on missing preconditions
* *Reduced complexity* - Constructor params 5+ → 2

==== Layer 1: BootstrapContext (Immutable)

Contains configuration and service instances that don't change during bootstrap:

[source,java]
----
record BootstrapContext(
  BootstrapConfig config,
  PulumiIncusImageProvider imageProvider,
  HostMountSourceVerifier hostMountSourceVerifier,
  NodeConfigRegenerator nodeConfigRegenerator,
  RuntimeEnvControlplaneOverlayWriter runtimeEnvControlplaneOverlayWriter,
  IncusImportLookup incusImportLookup,
  LaunchSecretsUpdater launchSecretsUpdater
) {}
----

*Created once* at pipeline start, *passed to every stage constructor*.

==== Layer 2: ApplyState (Mutable)

Shared mutable state across all pipeline stages:

[source,java]
----
class ApplyState {
  // Immutable reference
  BootstrapContext bootstrapContext;

  // Type-safe record registry
  final ContextRegistry registry = new ContextRegistry();

  // Pipeline coordination
  OnFailure onFailure;
  ControlplanePolicy controlplanePolicy;

  // Frequently accessed direct fields
  BootstrapPaths localPaths;
  BootstrapPaths nixosPaths;

  // Provider-specific Pulumi resources
  IncusProviderContext providerContext;
  Project ensuredProject;
  Output<String> ensuredProjectName;
  Output<String> ensuredProfileName;
  Output<String> ensuredImageFingerprint;
  Instance instance;
}
----

*Design decision:* Why some fields direct vs registry?

* *Direct fields* - Accessed frequently (10+ times), simple lifecycle, Pulumi resources
* *Registry* - Computed records, multi-stage lifecycle, type-safe sharing

*Operations:*

* `register(Class<T>, T)` - Add new record, throws if duplicate
* `update(Class<T>, T)` - Replace existing, throws if missing (only BuildMetadata)
* `require(Class<T>)` - Get with fail-fast, throws if missing (precondition check)
* `lookup(Class<T>)` - Get as Optional (truly optional records)

*Key insights:*

. *BuildMetadata register-then-update* - Only record that needs enrichment after Pulumi resources resolve
. *Synchronous checksum* - `imageProvider.buildChecksum()` reads local state (nix store), not from Pulumi Output
. *Pulumi Output decoupling* - Output tracks resource creation, not build artifact metadata
. *Fail-fast validation* - `require()` throws if records not available in correct order

=== Individual Record Lifecycles

==== DeploymentMetadata

* *Registered:* HostStage.captureDeploymentMetadata() after targets materialized
* *Content:* Git SHA, branch, timestamp
* *Consumers:* InstanceDone.toResult(), HostSlotManifest

[source,java]
----
state.registry.register(
  DeploymentMetadata.class,
  DeploymentMetadata.capture());
----

==== ProvisioningMetadata

* *Registered:* HostStage.captureDeploymentMetadata() after target checksums computed
* *Content:* Static/dynamic target checksums, host paths
* *Consumers:* InstanceStage.create() (instance config), HostSlotManifest

[source,java]
----
state.registry.register(
  ProvisioningMetadata.class,
  new ProvisioningMetadata(provisioningTargets, paths));
----

==== BuildMetadata

* *Registered:* HostStage.captureDeploymentMetadata() with null image, manifests summary
* *Updated:* ProviderStage.ensureImage() with actual image checksum
* *Content:* Image checksum (null → actual), manifests summary
* *Consumers:* InstanceStage.create() (instance config), HostSlotManifest

[source,java]
----
// HostStage: Register with null image
state.registry.register(
  BuildMetadata.class,
  new BuildMetadata(null, manifests));

// ProviderStage: Update with actual checksum
final BuildMetadata existing = state.registry.require(BuildMetadata.class);
state.registry.update(
  BuildMetadata.class,
  new BuildMetadata(
    new Image(imageProvider.buildChecksum()),
    existing.manifests()));
----

NOTE: BuildMetadata is the *only* record that uses `update()` - it's enriched after Pulumi resolves the image resource.

==== RuntimeMetadata

* *Registered:* HostStage.captureDeploymentMetadata() after env + systemd materialized
* *Content:* Layer environment registry, systemd provisioning summaries
* *Consumers:* InstanceDone.toResult(), HostSlotManifest

[source,java]
----
state.registry.register(
  RuntimeMetadata.class,
  new RuntimeMetadata(environment, systemd));
----

== Pulumi Output Interaction Pattern

=== Critical Design: Register Early, Update Late

BuildMetadata is registered *before* Pulumi Outputs resolve, then *updated* after:

[source,java]
----
// HostStage: Register with incomplete data
state.registry.register(
  BuildMetadata.class,
  new BuildMetadata(null, manifests));  // <1>

// ProviderStage: Update after Output resolves
state.ensuredImageFingerprint = imageProvider.ensure...();  // <2>
final BuildMetadata existing = state.registry.require(BuildMetadata.class);
state.registry.update(
  BuildMetadata.class,
  new BuildMetadata(
    new Image(imageProvider.buildChecksum()),  // <3>
    existing.manifests()));
----
<1> Image null - not yet resolved
<2> Returns `Output<String>` (async resource identifier)
<3> `buildChecksum()` is **synchronous** - reads local state immediately

*Why this works:*

* `imageProvider.buildChecksum()` is a **synchronous method** reading from local state
* Pulumi's `Output<String>` represents the *resource identifier* (async), not the build checksum
* Checksum comes from the image build process (nix store path hash), available immediately
* The Output only tracks whether the Incus resource was created, not the build artifact hash

==== ❌ Anti-Pattern: Async Registry Write

[source,java]
----
// WRONG - race condition
state.ensuredImageFingerprint.applyValue(fingerprint -> {
  state.registry.register(...);  // BAD: runs async
  return fingerprint;
});
----

*Why it fails:*

. *Race condition* - `applyValue()` callback executes asynchronously during Pulumi apply phase
. *Ordering violation* - InstanceStage may call `require()` before callback runs
. *Fail-fast breaks* - Registry throws immediately, but error surfaces only at runtime

==== ✅ Correct Pattern: Sync Registry Write

[source,java]
----
// CORRECT - synchronous registration
state.ensuredImageFingerprint = imageProvider.ensure...();
state.registry.update(...);  // Happens immediately
----

*Why it works:*

. *Synchronous execution* - `buildChecksum()` returns immediately from local state
. *Sequential guarantee* - `update()` completes before InstanceStage starts
. *Fail-fast safety* - If BuildMetadata missing, `require()` throws at correct location

== Design Decisions

=== Why Not Service Locator?

ContextRegistry is *not* a service locator anti-pattern because:

[cols="1,1",options="header"]
|===
| Service Locator (Anti-Pattern)
| ContextRegistry (Good Design)

| Hides service dependencies
| *Data*, not services

| Implicit lifecycle
| *Explicit* `register()` calls

| Global scope
| *Narrow* scope (bootstrap pipeline only)

| Alternative is better
| Alternative is worse (5+ params)
|===

=== What Goes Where?

[cols="1,2",options="header"]
|===
| Storage Location
| Usage Guidelines

| *BootstrapContext*
| Immutable config + services, created once, passed read-only

| *ApplyState direct fields*
| Frequently accessed (10+ times), simple lifecycle, Pulumi resources

| *ContextRegistry*
| Computed records, multi-stage lifecycle, type-safe sharing, fail-fast preconditions
|===

*Examples:*

* *Direct:* `localPaths`, `nixosPaths` (accessed 10+ times), `ensuredProject` (Pulumi resource)
* *Registry:* `DeploymentMetadata`, `BuildMetadata` (multi-stage lifecycle, type-safe sharing)

=== Stage Constructor Pattern

==== Before: Parameter Explosion

[source,java]
----
ProviderStage(
  ApplyState state,
  BootstrapConfig config,
  PulumiIncusImageProvider imageProvider,
  DeploymentMetadata deployment,
  ProvisioningMetadata provisioning)
----

*Problems:*

* 5+ parameters per constructor
* Every stage needs every metadata record
* No clear separation of concerns

==== After: Context + State

[source,java]
----
ProviderStage(BootstrapContext context, ApplyState state)
----

*Benefits:*

* 2 parameters - clear separation
* Access via `context.config()`, `state.registry.require()`
* Type-safe, fail-fast, explicit lifecycle

== Testing Implications

Records in registry are:

. *Testable* - Mock registry, inject test records
. *Observable* - `registry.size()` shows pipeline progress
. *Fail-fast* - `require()` throws immediately if sequencing bug

[source,java]
----
// Test example: Verify BuildMetadata lifecycle
@Test
void buildMetadata_registeredWithNull_thenUpdated() {
  ContextRegistry registry = new ContextRegistry();

  // HostStage behavior
  registry.register(BuildMetadata.class,
    new BuildMetadata(null, manifests));

  // ProviderStage behavior
  BuildMetadata existing = registry.require(BuildMetadata.class);
  assertNull(existing.image());

  registry.update(BuildMetadata.class,
    new BuildMetadata(new Image("checksum"), existing.manifests()));

  // InstanceStage behavior
  BuildMetadata updated = registry.require(BuildMetadata.class);
  assertEquals("checksum", updated.image().checksum());
}
----
