= Script Ownership
:toc: left
:toclevels: 2

This file is the canonical ownership map for shell-script assets in this repository.

Ownership now splits along the *substrate boundary*:

* *Node/host provisioning* — dissolved into declarative NixOS modules
  (`nixos/*.nix`). There is no host script tree, no `/srv/host` materialisation, no
  stow step. See <<node>>.
* *In-cluster workload scripts* — still authored by the OSGi *manifests domain*, as
  ConfigMap data or packaged resources owned by a `ManifestsUnit`. See <<cluster>>.

[NOTE]
====
*History (dissolved).* This file used to map ~28 `rke2lab-*.sh` HOST scripts under
a *layer-owns-script* model: `manifests/src/main/resources/host/systemd-scripts` +
`host/systemd-units` materialised onto `/srv/host/*` by `controlplane/incus`
(`IncusResourceBootstrap`), then stowed into `/etc/systemd/system` by
`rke2lab-systemd-link.sh` / activated by `rke2lab-activate.sh`. That whole
host-script world — and the `*Layer` classes that owned the in-cluster scripts
(`EnvoyGatewayLayer`, `KdnsLayer`, `HeadscaleLayer`, `HeadplaneLayer`) — is gone.
The NixOS node-substrate bake replaced it: *the closure IS the config*, and the
in-cluster scripts moved onto the `ManifestsUnit` model. The host-script rows below
are superseded by link:architecture/nixos-substrate/concern-ownership.adoc[concern
ownership].
====

[[node]]
== Node / host provisioning — owned by NixOS modules

The old host chain (distrobuilder image, cloud-init, ~28 host systemd scripts
materialised onto `/srv/host` then stowed) redistributes into declarative
`nixos/*.nix` modules. The delivery MECHANISM itself
(`rke2lab-systemd-link` + `rke2lab-activate`) dissolves — there is no tree to
materialise, no stow. The authoritative old→new map lives in
link:architecture/nixos-substrate/concern-ownership.adoc[concern ownership]; the
essentials:

[cols="2,2",options="header"]
|===
| Old script/responsibility | New home

| `rke2lab-nix-install.sh` / `rke2lab-flox-install.sh`
| native NixOS + `flox` input (`nixos/nix-env.nix`)

| `rke2lab-network-config.sh` / `-wait` / `-route-cleanup` / `-debug`
| declarative networkd + resolved (`nixos/host-access.nix`)

| `rke2lab-configure-containerd-zfs-mount.sh`, containerd NRI/ZFS/registries
| `virtualisation.containerd` / `services.rke2` (`nixos/containerd.nix`)

| `rke2lab-install*.sh` (RKE2 install/pre/post)
| `services.rke2` (`nixos/rke2.nix`)

| `rke2lab-systemd-link.sh` / `rke2lab-activate.sh` (stow + activate)
| `systemd.services.*` — the mechanism *disappears*

| `rke2lab-config-install.sh`, `-env-load.sh`, secrets
| sops-nix (`nixos/sops.nix`) + `nixos/identity.nix` (devlxd `user.rke2lab.*` → `/run/rke2lab/node.env`)

| `rke2lab-manifests-install.sh`, `-layer-ready.sh`, `-layer-secrets-apply.sh`
| *Flux GitOps* — GitRepository + root Kustomization on the rendered branch (no on-node install)

| the flox containerd runtime shim (built at runtime on host)
| a nix derivation baked into `rke2lab-node-base` (`nixos/containerd.nix` + `nixos/flox-runtime.nix`)

| CNI + GitOps bootstrap (cilium, Flux operator/root, bootstrap Secrets)
| node-side bootstrap lane over devlxd before rke2-server (`nixos/bootstrap-manifests.nix`)
|===

Per-node residue (name/kind, join token, ZFS dataset) is *bootstrap config*, not a
script: generated by CAPRKE2 for peers/workers, a small seed for master, reaching
each instance over devlxd (`user.rke2lab.*`), read at boot by `nixos/identity.nix`.
The former `RKE2LAB_MANIFESTS_PUBLISH_*` env→symlink flags are re-plumbed to Flux
`Kustomization`s enabled/absent on the rendered branch.

[[cluster]]
== In-cluster workload scripts — owned by manifest units

The scripts a workload needs INSIDE the cluster are authored by the OSGi manifests
domain and shipped as ConfigMap data (or a packaged resource) by a `ManifestsUnit`
in `osgi/domains/manifests/manifests-core/.../units/<domain>/`. They ride the
rendered branch and are reconciled by Flux like any other resource — there is no
host materialisation.

Ownership rules:

* Each script has exactly one owning `ManifestsUnit`.
* A unit consumes another owner's script only through an explicit mounted artifact
  boundary (a dedicated ConfigMap volume).
* Do not add backward-compatibility aliases for script locations unless explicitly
  requested.

[cols="1,2,2",options="header"]
|===
| Script | Owner (domain / manifest unit) | Source

| `install.sh`
| `networking/envoy-gateway` — `EnvoyGatewayManifestsUnit`
| inline ConfigMap data in the unit

| `kdns-dlv.sh`
| `networking/kdns` — `KdnsManifestsUnit` / `KdnsAssets`
| resource `osgi/domains/manifests/manifests-core/src/main/resources/runtime/networking/kdns/kdns-dlv.sh`

| `agent-sync.sh`
| `mesh/headplane` — `HeadplaneManifestsUnit`
| inline ConfigMap data in the unit

| `config-init.sh`, `bootstrap.sh`, `tailscale-client.sh`, `wait-for-headscale.sh`, `gateway.sh`
| `mesh/headscale` — `HeadscaleManifestsUnit`
| inline ConfigMap data in the unit
|===

NOTE: the mesh flox runtimes (headscale/tailscale/headplane toolchains) are
delivered as `FloxEnv` CRs realised by the flox-controller, NOT as baked closures or
host scripts — see
link:architecture/patterns/daemonset-host-assets-architecture.adoc[Workload Flox
Runtime Delivery]. The scripts above are the workloads' own in-cluster glue, distinct
from their flox toolchain.

== Notes

* The container runtime uses the NRI (Node Resource Interface) plugin, baked into
  the node base; there is no custom containerd shim installer and no
  daemonset-policy script surface (`daemonset-*.sh`, `shim-installer.sh`) any more —
  those were deleted with the `/srv/host` dissolution.
* `kdns` source resolution is worktree-based (`path:` input), subtree mode preferred
  at `networking/kdns/src`, explicit override via `KDNS_SRC_WORKTREE`.
* Keep this registry updated whenever a manifest-owned script is added, moved, or
  deleted.
