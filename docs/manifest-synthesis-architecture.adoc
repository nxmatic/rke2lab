= Manifest Synthesis Architecture
:toc: left
:toclevels: 3

This document defines the architecture of the manifest synthesis system in the `manifests` module, which generates both Kubernetes manifests and systemd units for the bootstrap layer via cdk8s and cdk8s-systemd.

== Overview

Manifest synthesis transforms domain-specific configuration into both Kubernetes YAML manifests and systemd unit files through a declarative, context-aware pipeline. The system uses:

* **cdk8s framework** for type-safe K8s object creation
* **cdk8s-systemd extension** for type-safe systemd unit creation
* **Domain registrars** for organizing related manifest units
* **ThreadLocal context** for runtime configuration injection
* **Construct tree pattern** for object collection and serialization
* **Unified layer architecture** where each domain emits BOTH K8s resources AND systemd support units

== Key Components

[cols="1,3",options="header"]
|===
|Component |Description
|`DefaultManifestSynthesisService` |Orchestrates the entire synthesis process

|`LayerDomainRegistry` |Registry of all manifest domains

**Key Relationships:**

1. **Entry**: `IncusResourceBootstrap` creates request with runtime config and calls service
2. **Context Binding**: Service binds context to ThreadLocal for duration of synthesis
3. **cdk8s Setup**: Service creates App + Chart + SystemdChart
4. **Domain Registry**: Service builds registry from all DomainRegistrars
5. **K8s Synthesis**: Service invokes each unit's `apply(chart)` method
6. **Systemd Synthesis**: Service invokes each unit's `synthesizeSystemdUnits(systemdChart)` method
7. **Context Access**: Units read runtime config via `ManifestSynthesisContext.current()`
8. **K8s Object Creation**: Units create `ApiObject` instances in the chart
9. **Systemd Unit Creation**: Units create `SystemdService`/`SystemdTarget` instances in systemd chart
10. **Dual Synthesis**: cdk8s emits YAML, SystemdChart emits .service/.target files

== Component Details

=== Entry Point: IncusResourceBootstrap

Location: `seed-master/src/main/java/io/nxmatic/rke2lab/controlplane/incus/IncusResourceBootstrap.java`

|===
|Field |Description
|`floxDebugPolicy` |Per-domain debug toggles for development
|`bootstrapIdentity` |Cluster name, ID, token, node identity
|`networkTopology` |CIDRs, interface names, gateway addresses
|`componentVersions` |Version pins for all bootstrap components
|`manifestDomainPolicy` |Which domains to enable/disable
|`synthOutdir` |Temporary synthesis directory
|`synthManifestFile` |Final manifest file path
|===

=== Orchestrator: DefaultManifestSynthesisService

Location: `manifests/src/main/java/io/nxmatic/rke2lab/manifests/DefaultManifestSynthesisService.java`

Central orchestration logic (lines 62-147):

[source,java]
----
public ManifestSynthesisResult synthesize(ManifestSynthesisRequest request) {
    // 1. Build context from request
    final ManifestSynthesisContext context = ManifestSynthesisContext.of(
        request.floxDebugPolicy(),
        request.bootstrapIdentity(),
        request.networkTopology(),
        request.componentVersions());

    // 2. Bind context to ThreadLocal for unit access
    try (var ignored = ManifestSynthesisContext.bind(context)) {

        // 3. Create cdk8s App + Chart
        final App app = new App(AppProps.builder().outdir(synthOutdir.toString()).build());
        final Chart chart = new Chart(app, "manifests");

        // 4. Build domain registry from DomainRegistrars
        final LayerDomainRegistry registry = buildDomainRegistry();

        // 5. Apply policy to filter domains
        final LayerDomainRegistry filteredRegistry = applyPolicy(request, registry);

        // 6. For each ManifestUnit: call apply(chart)
        for (ManifestUnit unit : filteredRegistry.manifestUnits()) {
            unit.apply(chart);
        }

        // 7. Synthesize YAML via cdk8s
        app.synth();  // Writes to synthOutdir/manifests.k8s.yaml

        // 8. Post-process (enforce literal block style for ConfigMap scripts)
        enforceLiteralBlockStyleForConfigMapScripts(synthesizedFile);

        // 9. Move to final location
        Files.move(synthesizedFile, synthManifestFile);
    }
}
----

==== ManifestUnit

Interface: `manifests/src/main/java/io/nxmatic/rke2lab/manifests/layers/common/ManifestUnit.java`

Generates BOTH Kubernetes resources AND systemd units via cdk8s.

[source,java]
----
public interface ManifestUnit {
    String manifestUnitId();
    List<String> dependsOnManifestUnitIds();

    // K8s manifest synthesis
    void apply(Chart chart);

    // Systemd unit synthesis (default: no units)
    default void synthesizeSystemdUnits(SystemdChart systemdChart) {
        // Override to emit systemd installer services, targets, etc.
    }
}
----

**Design Rationale:**

* **Single source of structure**: No duplication between K8s and systemd layer definitions
* **Policy-driven**: Enabled domains emit BOTH K8s manifests AND their systemd installers
* **Optional systemd**: Not all units need systemd support (default no-op)
* **Domain-level installers**: `synthesizeSystemdUnits()` emits services like `rke2lab-{domain}-manifests.service`

=== Resource Generation: ManifestUnit + cdk8s

Manifest units create Kubernetes resources using cdk8s `ApiObject`:

[source,java]
----
@Override
public void apply(Chart chart) {
    // 1. Read runtime config from context
    String version = componentVersions().clusterApiOperator();

    // 2. Create K8s object using cdk8s
    ApiObject provider = new ApiObject(
        chart,
        "coreprovider-cluster-api",
        ApiObjectProps.builder()
            .apiVersion("operator.cluster.x-k8s.io/v1alpha2")
            .kind("CoreProvider")
            .metadata(
                ApiObjectMetadata.builder()
                    .name("cluster-api")
                    .namespace("capi-system")
                    .build())
            .build());

    // 3. Add spec via JsonPatch
    provider.addJsonPatch(JsonPatch.add("/spec", Map.of("version", version)));
}
----

**Key points:**

1. Units are **statically instantiated** by DomainRegistrars
2. Units access **runtime configuration** via `ManifestSynthesisContext.current()`
3. Units **create K8s objects** using cdk8s `ApiObject` + `JsonPatch`
4. cdk8s **registers objects** in the Chart's internal construct tree
5. `app.synth()` **walks the tree** and emits YAML

=== Systemd Unit Generation: ManifestUnit + cdk8s-systemd

Manifest units can also create systemd units using the `cdk8s-systemd` extension:

[source,java]
----
@Override
public void synthesizeSystemdUnits(SystemdChart systemdChart) {
    // Create installer service for this domain's manifests
    new SystemdService(systemdChart, "rke2lab-cluster-api-manifests")
        .description("Install RKE2Lab Cluster API manifests from host share")
        .requiresMountsFor("/srv/host/systemd-units.d", "/srv/host")
        .after("local-fs.target", "rke2-server.service", "rke2lab-cluster-manifests.service")
        .requires("rke2-server.service", "rke2lab-cluster-manifests.service")
        .conditionPathExists(
            "/srv/host/systemd-scripts.d/rke2lab-manifests-install.sh",
            "/srv/host/rke2-manifests.d/clusterapi")
        .type(ServiceType.ONESHOT)
        .execStart("/srv/host/systemd-scripts.d/rke2lab-manifests-install.sh clusterapi")
        .remainAfterExit(true)
        .standardOutput(StandardStream.JOURNAL)
        .standardError(StandardStream.JOURNAL)
        .wantedBy("rke2lab.target");
}
----

**Key points:**

1. **Same Construct pattern**: `SystemdService` extends `software.constructs.Construct`
2. **Fluent API**: Type-safe method chaining for unit directives
3. **Automatic registration**: `SystemdChart` tracks units via construct tree
4. **Synthesis**: `SystemdChart.synthesize(outdir)` writes `.service` files
5. **Domain correlation**: Unit references domain ID (e.g., `clusterapi` → `/srv/host/rke2-manifests.d/clusterapi`)

**Unified Synthesis Example:**

A single ManifestUnit emits BOTH K8s manifests AND the systemd service that installs them:

[source,java]
----
public class ClusterApiOperatorManifestUnit extends AbstractManifestUnit {

    @Override
    public void apply(Chart chart) {
        // Emit K8s manifests (operator, providers, secrets)

    @Override

            ...;
    }
}
----

Result: One domain definition produces BOTH the YAML to install AND the systemd unit that installs it.

=== cdk8s Construct Tree Pattern

**Question**: "cdk8s do not provide itself references to the manifests built, they're registered somewhere from the Construct base class. but then?"

**Answer**: cdk8s maintains an internal tree structure via the `Construct` base class:

1. **Object Creation**: When you create `new ApiObject(chart, "id", props)`
   * `ApiObject` extends `Construct`
   * Construct constructor registers itself in parent's children list
   * `chart` is the parent, so chart tracks all created ApiObjects

2. **Synthesis**: When you call `app.synth()`
   * App walks the tree starting from root
   * Visits each Chart
   * Chart visits each child Construct (ApiObject)
   * Serializes each ApiObject to YAML
   * Writes single YAML file with all documents

3. **No Reference Storage Needed**
   * ManifestUnits just create objects in the chart
   * cdk8s framework handles collection + serialization
   * One-way data flow: create → register → synthesize

This is why ManifestUnits can be statically instantiated and just call `new ApiObject(chart, ...)` without storing references - the chart itself tracks everything via the Construct parent-child tree.

                    .namespace("capi-system")
                    .annotations(packageProfile.packageAnnotations(...))
                    .build())
            .build());

  }

  // ... similar for infrastructure and control plane providers ...
}

== cdk8s-systemd Module

The `cdk8s-systemd` module extends CDK8s Constructs pattern to systemd units, enabling type-safe programmatic definition alongside K8s manifests.

=== Architecture

[source,text]
----
software.constructs.Construct (AWS CDK core)
  ↓
SystemdChart extends Construct (container)
  ↓
SystemdUnit extends Construct (abstract base)
  ├─ SystemdService (adds [Service] section)
  └─ SystemdTarget (grouping units)
----

=== Core Classes

[cols="1,3",options="header"]
|===
|Class |Purpose
|`SystemdChart` |Container for systemd units (like `org.cdk8s.Chart` for K8s)
|`SystemdUnit` |Abstract base with [Unit] and [Install] section builders
|`SystemdService` |Service unit with [Service] section, type-safe enums
|`SystemdTarget` |Target unit (grouping, no execution)
|===

=== Usage Pattern

[source,java]
----
// Same App synthesizes BOTH K8s and systemd
App app = new App(AppProps.builder().outdir(...).build());

// K8s manifests
Chart k8sChart = new Chart(app, "manifests");
new DeploymentUnit(k8sChart, "my-app");

// Systemd units
SystemdChart systemdChart = new SystemdChart(app, "systemd");
new SystemdService(systemdChart, "my-installer")
    .description("Install manifests")
    .type(ServiceType.ONESHOT)
    .execStart("/path/to/install.sh");

// ONE call synthesizes BOTH
app.synth();  // → manifests.k8s.yaml + my-installer.service
----
