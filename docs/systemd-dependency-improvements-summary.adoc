= Systemd Dependency Improvements - Implementation Summary
:toc: left
:toclevels: 2

== Changes Implemented

We've enhanced the systemd unit dependency structure to create a clear hierarchical tree visible in `systemctl list-dependencies` and proper lifecycle binding using `PartOf=`, `Wants=`, and `Also=` directives.

== Code Changes

=== 1. cdk8s-systemd Module Enhancements

==== SystemdUnit.java
Added two new methods for lifecycle management:

[source,java]
----
/** Adds PartOf directive (lifecycle binding - stop/restart propagation). */
public SystemdUnit partOf(String... units)

/** Adds Also directive (enable/disable propagation). */
public SystemdUnit also(String... units)
----

==== SystemdChart.java
Added service-to-target registration mechanism:

[source,java]
----
private final Map<String, List<String>> targetWantsRegistry = new LinkedHashMap<>();

/** Registers a service with a target for automatic Wants= directive. */
public void registerServiceWithTarget(String serviceName, String targetName)

/** Finalizes target dependencies by adding Wants= directives for registered services. */
public void finalizeTargetDependencies()
----

==== SystemdService.java
Auto-registration when `wantedBy()` is called:

[source,java]
----
@Override
public SystemdService wantedBy(String... targets) {
    super.wantedBy(targets);

    // Auto-register with SystemdChart for reciprocal Wants= in targets
    var scope = getNode().getScope();
    if (scope instanceof SystemdChart chart) {
        for (String target : targets) {
            chart.registerServiceWithTarget(getUnitFileName(), target);
        }
    }

    return this;
}
----

Added fluent API overrides for `partOf()` and `also()`.

==== SystemdTarget.java
Added fluent API overrides for `partOf()` and `also()`.

    new SystemdTarget(systemdChart, "rke2lab")

== How It Works

=== Automatic Wants= Registration

1. **Service creation**: When a service calls `.wantedBy("some.target")`:
   - The service adds `WantedBy=some.target` to its `[Install]` section
   - The service auto-registers itself with `SystemdChart.registerServiceWithTarget()`

2. **Finalization**: After all units are synthesized, `systemdChart.finalizeTargetDependencies()`:
   - Walks the registration map
   - Adds reciprocal `Wants=some.service` to each target
   - Creates bidirectional relationship

3. **Result**:
   - Services have `WantedBy=<target>` → enable symlink creation
   - Targets have `Wants=<service>` → runtime dependency, visible in `list-dependencies`

=== Lifecycle Binding with PartOf=

All services now have `PartOf=<target>`:

- When a target is stopped, all its `PartOf=` services stop too
- When a target is restarted, all its `PartOf=` services restart too
- Creates proper lifecycle coupling

Example:
[source,bash]
----
systemctl stop rke2lab.target
# → Stops ALL rke2lab-* services and sub-targets
----

=== Enable/Disable Propagation with Also=

The `rke2lab-bootstrap.target` has:
[source,systemd]
----
[Install]
WantedBy=rke2lab.target
Also=rke2lab-network.target
Also=rke2lab-tools.target
----

Result:
[source,bash]
----
systemctl enable rke2lab-bootstrap.target
# → Also enables rke2lab-network.target and rke2lab-tools.target
----

== Benefits

=== Visibility
`systemctl list-dependencies` now shows the actual architecture, not a flat list.

=== Lifecycle Management
Stopping `rke2lab.target` cleanly stops all related services via `PartOf=`.

=== Maintainability
Adding a new service automatically registers it with its target via `wantedBy()`.

=== Enable/Disable Propagation
Enabling bootstrap target automatically enables network and tools targets via `Also=`.

=== Debugging
Clear grouping makes it easy to see which services belong to which phase (tools → network → bootstrap → server → manifests → secrets).
