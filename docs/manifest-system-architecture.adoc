= Manifest System Architecture
:toc: left
:toclevels: 3

== Overview

The manifest system generates Kubernetes YAML manifests and systemd unit files for the RKE2Lab bootstrap and runtime infrastructure through a declarative, context-aware pipeline. It uses CDK8s for type-safe K8s object creation and a custom cdk8s-systemd extension for systemd unit generation.

The system transforms high-level domain specifications (networking, storage, GitOps, etc.) into both the infrastructure definitions (K8s manifests) and the bootstrap machinery (systemd services) needed to deploy them, all synthesized from the same source definitions.

== Nomenclature and Structure

**Deployment Layers** are bootstrap stages for the cluster:

|**seed-layer1**

|**seed-layer2**
|`seed-layer2/`

|**seed-layer3**
|`seed-layer3/`

=== Manifest Level: Domain → Component → ManifestUnit

**Manifest Organization** defines how Kubernetes resources are structured and synthesized:

[cols="2,3,3"]
|===
|Term |Location |Purpose

|**Domain**
|`manifests/components/<domain>/`
|Functional grouping (networking, mesh, storage, platform, cicd, runtime, gitops, clusterapi, cluster, ha)

|**Component**
|`manifests/components/<domain>/<Name>Component.java`
|CDK8s reusable Construct that generates K8s YAML directly

|**ManifestUnit**
|`manifests/components/<domain>/<Name>ManifestUnit.java`
|Wrapper that adds metadata, dependencies, policy control, and optional systemd unit generation

|`manifests/charts/layer<N>/`
|Aggregation boundary that selects which components to synthesize together

== Component vs ManifestUnit Pattern

This is the KEY architectural pattern that often causes confusion. Understanding the relationship between these two abstractions is essential.

=== The Two-Layer Abstraction

The manifest system uses a two-layer pattern:

1. **Component** (CDK8s layer): Pure Construct that generates YAML
2. **ManifestUnit** (rke2lab layer): Wrapper that adds deployment concerns

[source,java]
----
// COMPONENT: CDK8s Construct - generates YAML directly
public final class CiliumConfigComponent extends Construct {
  public CiliumConfigComponent(Construct scope, String id) {
    super(scope, id);
    // Creates K8s ApiObjects directly in the construct tree
    new ApiObject(this, "helmchartconfig-rke2-cilium", ...);
    new ApiObject(this, "configmap-clustermesh-remote-users", ...);
  }
}

// MANIFEST UNIT: rke2lab wrapper - adds metadata, dependencies, policy
public final class CiliumConfigManifestUnit extends AbstractManifestUnit {

  public CiliumConfigManifestUnit() {
    super(MANIFEST_UNIT_ID, List.of(/* dependencies */));
  }

  @Override
  public void apply(Chart chart) {
    // Delegates to Component
    new CiliumConfigComponent(chart, "layer-networking-cilium-config");
  }

  @Override
  public void synthesizeSystemdUnits(SystemdChart systemdChart, SystemdSynthesisContext context) {
    // Optionally create systemd installer service
    new SystemdService(systemdChart, "rke2lab-cilium-config-manifests")
        .execStart("/srv/host/systemd-scripts.d/rke2lab-manifests-install.sh networking/cilium-config")
        ...;
  }
}
----

=== Why Both Exist

[cols="2,3,3"]
|===
|Concern |Component (CDK8s) |ManifestUnit (rke2lab)

|**Purpose**
|Generate K8s resources
|Control when/how/if they're deployed

|**Extends**
|`software.constructs.Construct`
|`AbstractManifestUnit`

|**Knows about**
|K8s API, resource structure
|Dependencies, policy, systemd bootstrap

|**Creates**
|`ApiObject` instances in Chart
|Component + optional systemd units

|**When used**
|During synthesis (`apply()`)
|During synthesis orchestration

|**Reusability**
|Can be used directly in any Chart
|Bound to rke2lab deployment model

|**Testing focus**
|Generated YAML correctness
|Dependency order, policy filtering
|===

=== When Each Is Used

**Component** is instantiated:

* BY a ManifestUnit's `apply()` method (most common)
* OR directly in a Chart (for custom deployments)

**ManifestUnit** is instantiated:

* BY the synthesis service via LayerDomain
* NEVER directly by user code

=== Code Examples

**Creating ONLY a Component (directly usable in any Chart):**

[source,java]
----
public class CustomChart extends Chart {
  public CustomChart(Construct scope, String id) {
    super(scope, id);

    // Direct Component usage - no ManifestUnit wrapper
    new TailscaleComponent(this, "tailscale");
    new CiliumConfigComponent(this, "cilium");
  }
}
----

**Creating Component + ManifestUnit (standard rke2lab pattern):**

[source,java]
----
// 1. Component - CDK8s Construct
public final class TailscaleComponent extends Construct {
  public TailscaleComponent(Construct scope, String id) {
    super(scope, id);
    // Create K8s resources
    new ApiObject(this, "helmchart-tailscale-operator", ...);
    new ApiObject(this, "connector-controlplane", ...);
  }
}

// 2. ManifestUnit - rke2lab wrapper
public final class TailscaleManifestUnit extends AbstractManifestUnit {

  public static final String MANIFEST_UNIT_ID = "mesh/tailscale";

  public TailscaleManifestUnit() {
    super(MANIFEST_UNIT_ID, List.of("mesh/system-namespace"));  // Dependencies
  }

  @Override
  public void apply(Chart chart) {
    // Instantiate Component
    new TailscaleComponent(chart, "layer-mesh-tailscale");
  }

  // No systemd units for this component - default implementation does nothing
}
----

=== Decision Guide: Component or ManifestUnit?

**Create ONLY a Component when:**

* Building a reusable K8s resource template
* The resource has no rke2lab-specific deployment concerns
* You might use it in different deployment contexts
* Example: A generic HelmChart wrapper

**Create Component + ManifestUnit when:**

* Deploying into rke2lab's bootstrap pipeline
* Need dependency ordering (must come after namespace creation)
* Need policy control (enable/disable per environment)
* Need systemd installer service (bootstrap pre-server or post-server)
* Example: All infrastructure components (Cilium, Flux, Cluster API)

**In practice:** Almost all rke2lab components follow the Component + ManifestUnit pattern because they're part of the bootstrap pipeline.

=== Common Confusion Points

[IMPORTANT]
====
**"Do I need to reference the Component from the ManifestUnit?"**

Yes, always. The ManifestUnit's `apply()` method MUST instantiate the Component. This is the delegation that makes the pattern work.

**"Can I put K8s resource creation directly in the ManifestUnit?"**

No. Keep K8s logic in the Component. The ManifestUnit should only:

* Instantiate the Component
* Optionally create systemd units
* Declare dependencies and metadata

**"Why not merge them into one class?"**

Separation of concerns:

* Component = WHAT resources to create (pure CDK8s)
* ManifestUnit = WHEN/IF/HOW to deploy them (rke2lab orchestration)

This allows reusing Components in different contexts (testing, custom Charts) without dragging in rke2lab dependencies.
====

**Key Relationships:**

1. **Entry**: `IncusResourceBootstrap` creates request and calls synthesis service
2. **Context Binding**: Service binds context to ThreadLocal for synthesis duration
3. **CDK8s Setup**: Service creates App + Chart + SystemdChart
4. **Domain Registry**: Service builds registry from all LayerDomainRegistrars
5. **K8s Synthesis**: Service invokes each unit's `apply(chart)` method
6. **Component Instantiation**: ManifestUnit creates Component in apply()
7. **Systemd Synthesis**: Service invokes each unit's `synthesizeSystemdUnits()`
8. **Context Access**: Units and Components read runtime config via `ManifestSynthesisContext.current()`
9. **Dual Output**: cdk8s emits YAML, SystemdChart emits .service/.target files

=== Component Details

==== Entry Point: ManifestSynthesisRequest

Built in `seed-layer1/IncusResourceBootstrap.synthesizeAndExplodeManifests()`, contains:

[cols="2,4"]
|===
|Field |Description

|`floxDebugPolicy`
|Per-domain debug toggles for development

|`bootstrapIdentity`
|Cluster name, ID, token, node identity

|`networkTopology`
|CIDRs, interface names, gateway addresses

|`componentVersions`
|Version pins for all bootstrap components

|`manifestDomainPolicy`
|Which domains to enable/disable

|`synthOutdir`
|Temporary synthesis directory

|`synthManifestFile`
|Final manifest file path
|===

==== Orchestrator: DefaultManifestSynthesisService

Central orchestration logic:

[source,java]
----
public ManifestSynthesisResult synthesize(ManifestSynthesisRequest request) {
    // 1. Build context from request
    final ManifestSynthesisContext context = ManifestSynthesisContext.of(
        request.floxDebugPolicy(),
        request.bootstrapIdentity(),
        request.networkTopology(),
        request.componentVersions());

    // 2. Bind context to ThreadLocal for unit access
    try (var ignored = ManifestSynthesisContext.bind(context)) {

        // 3. Create cdk8s App + Chart + SystemdChart
        final App app = new App(AppProps.builder().outdir(synthOutdir.toString()).build());
        final Chart chart = new Chart(app, "manifests");
        final SystemdChart systemdChart = new SystemdChart(app, "systemd");

        // 4. Build domain registry from LayerDomainRegistrars
        final LayerDomainRegistry registry = buildDomainRegistry();

        // 5. Apply policy to filter domains
        final LayerDomainRegistry filteredRegistry = applyPolicy(request, registry);

        // 6. For each ManifestUnit: call apply(chart)
        for (ManifestUnit unit : filteredRegistry.manifestUnits()) {
            unit.apply(chart);  // ← ManifestUnit instantiates Component here
        }

        // 7. For each ManifestUnit: call synthesizeSystemdUnits(systemdChart)
        for (ManifestUnit unit : filteredRegistry.manifestUnits()) {
            unit.synthesizeSystemdUnits(systemdChart, systemdContext);
        }

        // 8. Synthesize YAML via cdk8s
        app.synth();  // Writes to synthOutdir/manifests.k8s.yaml

        // 9. Synthesize systemd units
        systemdChart.synthesize(synthOutdir);  // Writes *.service, *.target

        // 10. Post-process (enforce literal block style for ConfigMap scripts)
        enforceLiteralBlockStyleForConfigMapScripts(synthesizedFile);

        // 11. Move to final location
        Files.move(synthesizedFile, synthManifestFile);
    }
}
----

**LayerDomain** (class):

Groups related ManifestUnits with dependency information:

[source,java]

public class LayerDomain {

  private final List<String> dependsOnDomainIds;      // Domain dependencies
  private final List<? extends ManifestUnit> layers;  // Historical name, actually units

  // Synthesizes systemd units for this domain
  public void synthesizeSystemdUnits(SystemdChart systemdChart, SystemdSynthesisContext context) {
    for (ManifestUnit unit : layers) {
      unit.synthesizeSystemdUnits(systemdChart, context);
    }
  }
}

=== CDK8s Construct Tree Pattern

**How cdk8s tracks objects without explicit references:**

1. **Object Creation**: When you create `new ApiObject(chart, "id", props)`
   * `ApiObject` extends `Construct`
   * Construct constructor registers itself in parent's children list
   * `chart` is the parent, so chart tracks all created ApiObjects

2. **Synthesis**: When you call `app.synth()`
   * App walks the tree starting from root
   * Visits each Chart
   * Chart visits each child Construct (Components)
   * Components visit each child Construct (ApiObjects)
   * Serializes each ApiObject to YAML
   * Writes single YAML file with all documents

3. **No Reference Storage Needed**
   * ManifestUnits just create Components in the chart
   * Components just create ApiObjects in themselves
   * cdk8s framework handles collection + serialization
   * One-way data flow: create → register → synthesize

This is why ManifestUnits and Components can be statically instantiated and just call `new ApiObject(this, ...)` without storing references - the construct tree tracks everything via parent-child relationships.

== Chart Pattern

**Chart** is a CDK8s synthesis boundary that produces a separate output file.

[IMPORTANT]
====
**Critical Rule**: All Component classes MUST extend `Construct`, NEVER `Chart`.

The only Charts in the codebase should be:

* `Chart(app, "manifests")` in `DefaultManifestSynthesisService`
* `SystemdChart(app, "systemd")` in `DefaultManifestSynthesisService`
* Optional custom Charts in test code or deployment-layer-specific synthesis
====

=== Single-Chart Architecture

RKE2Lab uses a **single-Chart model** where all domains feed into one consolidated Chart, then an exploder splits the output by annotations.

**Why Single-Chart?**

[cols="2,3,3"]
|===
|Aspect |Single-Chart Model |Chart-per-Domain Alternative

|**Cross-domain deps**
|Natural - all in same construct tree
|Requires CDK8s export/import pattern

|**Ordering**
|ManifestUnit dependency graph ensures correct order
|Would need explicit Chart ordering

|**Flexibility**
|Annotations create any directory structure
|One Chart = one file = one directory

|**Output**
|Single `manifests.k8s.yaml` - easy to checksum
|11 separate files need consolidation

|**Simplicity**
|One synthesis → one explode → domain dirs
|Synthesis → per-Chart processing → merge
|===

**Current reality:**

* Atomic deployment (single host asset bundle)
* Repo-level versioning (git commit hash in `MANIFEST.yaml`)
* Synthesis is fast (~1-2s for all domains)
* Cross-domain dependencies exist (e.g., namespace must exist before HelmChart)

}
----

**Note**: The current architecture doesn't use this pattern - it uses a single Chart with all domains synthesized into it.

=== Anti-Pattern: Component Extends Chart

[source,java]
----
// ❌ WRONG - Do not do this
public final class CiliumConfigComponent extends Chart {  // ← WRONG base class
  public CiliumConfigComponent(Construct scope, String id) {
    super(scope, id);
    // ...
  }
}
----

**Why this fails:**

* Creates a nested Chart in the construct tree
* CDK8s synthesizes it to a separate `.k8s.yaml` file with numeric prefix
* Exploder's pattern matching doesn't find it (only looks for `*-manifests.k8s.yaml`)
* Resources never reach `rke2-manifests.d/`
* Systemd services fail with `ConditionPathExists=/srv/host/rke2-manifests.d/<domain>`

**Correct pattern:**

[source,java]
----
// ✅ CORRECT - Component extends Construct
public final class CiliumConfigComponent extends Construct {  // ← CORRECT
  public CiliumConfigComponent(Construct scope, String id) {
    super(scope, id);
    // ...
  }
}
----

== Systemd Unit Generation

ManifestUnits can create systemd units using the `cdk8s-systemd` extension.

=== Unified Synthesis Pattern

A single ManifestUnit emits BOTH K8s manifests AND the systemd service that installs them:

[source,java]
----
public class CiliumConfigManifestUnit extends AbstractManifestUnit {

    @Override
    public void apply(Chart chart) {
        // Emit K8s manifests (HelmChartConfig, ConfigMap)
        new CiliumConfigComponent(chart, "layer-networking-cilium-config");
    }

    @Override
    public void synthesizeSystemdUnits(SystemdChart systemdChart, SystemdSynthesisContext context) {
        // Emit systemd installer for those manifests
        new SystemdService(systemdChart, "rke2lab-cilium-config-manifests")
            .description("Install RKE2Lab Cilium config manifests before server start")
            .requiresMountsFor("/srv/host/systemd-units.d", "/srv/host")
            .after("local-fs.target", "rke2lab-install.service")
            .before("rke2-server.service")  // Special: runs BEFORE server
            .conditionPathExists(
                "/srv/host/systemd-scripts.d/rke2lab-manifests-install.sh",
                "/srv/host/rke2-manifests.d")
            .type(ServiceType.ONESHOT)
            .execStart("/srv/host/systemd-scripts.d/rke2lab-manifests-install.sh networking/cilium-config")
            .remainAfterExit(true)
            .standardOutput(StandardStream.JOURNAL)
            .standardError(StandardStream.JOURNAL)
            .partOf(context.rke2labTarget().getUnitFileName())
            .wantedBy(context.rke2labTarget().getUnitFileName());
    }
}
----

**Result**: One domain definition produces BOTH:

* The K8s YAML to install (via Component)
* The systemd unit that installs it (via ManifestUnit)

=== cdk8s-systemd Architecture

[source,text]
----
software.constructs.Construct (AWS CDK core)
  ↓
SystemdChart extends Construct (container)
  ↓
SystemdUnit extends Construct (abstract base)
  ├─ SystemdService (adds [Service] section)
  └─ SystemdTarget (grouping units)
----

**Core Classes:**

[cols="2,4"]
|===
|Class |Purpose

|`SystemdChart`
|Container for systemd units (like `org.cdk8s.Chart` for K8s)

|`SystemdUnit`
|Abstract base with [Unit] and [Install] section builders

|`SystemdService`
|Service unit with [Service] section, type-safe enums

|`SystemdTarget`
|Target unit (grouping, no execution)
|===

**Type-Safe API:**

[source,java]
----
new SystemdService(systemdChart, "my-installer")
    .description("Install manifests")
    .type(ServiceType.ONESHOT)              // Service types
    .execStart("/path/to/install.sh")
    .after("network.target")                // Ordering
    .requires("other.service")              // Dependencies
    .conditionPathExists("/srv/host/data")  // Conditions
    .standardOutput(StandardStream.JOURNAL) // Streams
    .restart(RestartPolicy.ON_FAILURE)      // Restart
    .wantedBy("multi-user.target");         // Install
----

== Data Flow Summary

```
IncusResourceBootstrap (seed-layer1)
  ↓ creates ManifestSynthesisRequest with runtime config
DefaultManifestSynthesisService
  ↓ binds ManifestSynthesisContext to ThreadLocal
  ↓ creates cdk8s App + Chart + SystemdChart
  ↓ builds LayerDomainRegistry from LayerDomainRegistrars
  ↓   ↳ each registrar provides LayerDomain with ManifestUnits
  ↓ applies ManifestDomainPolicy to filter domains
  ↓ for each ManifestUnit:
  ↓   unit.apply(chart)
  ↓     ↳ unit instantiates new Component(chart, id)
  ↓     ↳ component reads ManifestSynthesisContext.current()
  ↓     ↳ component creates new ApiObject(this, ...)
  ↓       ↳ cdk8s registers object in construct tree
  ↓ for each ManifestUnit:
  ↓   unit.synthesizeSystemdUnits(systemdChart, context)
  ↓     ↳ unit creates new SystemdService(systemdChart, ...)
  ↓       ↳ SystemdChart registers unit in construct tree
  ↓ app.synth()
  ↓   ↳ cdk8s walks construct tree, emits manifests.k8s.yaml
  ↓ systemdChart.synthesize(outdir)
  ↓   ↳ SystemdChart walks construct tree, emits *.service/*.target files
  ↓ post-process YAML (enforce literal block style for ConfigMap scripts)
  ↓ move to final location
ManifestSynthesisResult
```

=== Adding a New Component + ManifestUnit

**Step 1: Create the Component** (CDK8s Construct)

[source,java]
----
// manifests/components/storage/MinioComponent.java
package io.nxmatic.rke2lab.manifests.components.storage;

import io.nxmatic.rke2lab.manifests.profiles.PackageMetadataProfile;
import org.cdk8s.ApiObject;
import software.constructs.Construct;

public final class MinioComponent extends Construct {

  private final PackageMetadataProfile packageProfile =
      new PackageMetadataProfile("storage", "minio");

  public MinioComponent(Construct scope, String id) {
    super(scope, id);

    // Create K8s resources
    ApiObject namespace = new ApiObject(this, "namespace-minio", ...);
    ApiObject helmChart = new ApiObject(this, "helmchart-minio", ...);
    // ... more resources
  }
}
----

**Step 2: Create the ManifestUnit** (rke2lab wrapper)

[source,java]
----
// manifests/components/storage/MinioManifestUnit.java
package io.nxmatic.rke2lab.manifests.components.storage;

import io.nxmatic.rke2lab.manifests.AbstractManifestUnit;
import io.nxmatic.rke2lab.manifests.ManifestDomainCatalog;
import java.util.List;
import org.cdk8s.Chart;

public final class MinioManifestUnit extends AbstractManifestUnit {

  public static final String MANIFEST_UNIT_ID = ManifestDomainCatalog.STORAGE + "/minio";

  public MinioManifestUnit() {
    super(MANIFEST_UNIT_ID, List.of(/* dependencies */));
  }

  @Override
  public void apply(Chart chart) {
    new MinioComponent(chart, "layer-storage-minio");
  }

  // Optional: systemd installer service
  @Override
  public void synthesizeSystemdUnits(SystemdChart systemdChart, SystemdSynthesisContext context) {
    new SystemdService(systemdChart, "rke2lab-minio-manifests")
        .execStart("/srv/host/systemd-scripts.d/rke2lab-manifests-install.sh storage/minio")
        ...;
  }
}
----

Add to the appropriate domain registrar in `DefaultManifestSynthesisService`:

[source,java]
----
private static class StorageDomainRegistrar implements LayerDomainRegistrar {
  @Override
  public LayerDomain domain() {
    return new LayerDomain(
        ManifestDomainCatalog.STORAGE,
        List.of(),  // Dependencies
        List.of(
            new OpenebsZfsManifestUnit(),
            new MinioManifestUnit()  // ← Add here
        )
    );
  }
}

=== Extending ManifestSynthesisContext

To add new runtime configuration, choose one of three patterns:

**Option 1: Extend Existing Slice** (if data fits an existing concern)

[source,java]
----
public record BootstrapIdentity(
    String clusterName,
    String clusterId,
    String incusRemoteAddress  // NEW
) { }
----

**Option 2: Add New Orthogonal Slice** (if data is a distinct concern)

[source,java]
----
// 1. Create new record
public record IncusConfig(String remoteAddress, Path configDir) { }

// 2. Add field to ManifestSynthesisContext
private final IncusConfig incusConfig;
public IncusConfig incusConfig() { return incusConfig; }

// 3. Update ManifestSynthesisContext.of() factory
public static ManifestSynthesisContext of(..., IncusConfig incusConfig) { ... }

// 4. Add helper to AbstractManifestUnit
protected final IncusConfig incusConfig() {
    return ManifestSynthesisContext.current().incusConfig();
}
----

**Option 3: Read from Filesystem/Environment** (if data is truly static)

[source,java]
----
@Override
public void apply(Chart chart) {
    Path configDir = Path.of(System.getProperty("user.home"), ".config", "incus");
    // ...
}
----

== Troubleshooting

=== Domain Directory Missing in rke2-manifests.d/

**Symptom:**

```bash
$ tree .local.d/bioskop/master/host.preview/rke2-manifests.d/
...
├── networking
├── gitops
# storage/ is missing!
```

**Check 1: Does Component extend Construct (not Chart)?**

```bash
$ grep "extends Chart" manifests/src/main/java/io/nxmatic/rke2lab/manifests/components/storage/*.java
# Should return nothing (or only test files)
```

**Check 2: Are annotations present?**

Components must stamp `PackageMetadataProfile` annotations on all resources:

[source,java]
----
private final PackageMetadataProfile packageProfile =
    new PackageMetadataProfile("storage", "minio");

.annotations(packageProfile.packageAnnotations("|Namespace||minio"))
----

**Check 3: Is domain enabled in policy?**

```bash
$ cat .local.d/bioskop/master/host/.rke2lab-manifest.yaml | grep storage
storage: true  # ← Should be true
```

=== Systemd Service Skipped with ConditionPathExists

**Symptom:**

```bash
$ journalctl -u rke2lab-storage-manifests.service
Condition check failed: ConditionPathExists=/srv/host/rke2-manifests.d/storage
```

**Root cause**: The manifests weren't exploded to that directory (see previous section).

=== Multiple .k8s.yaml Files in synthOutdir

**Symptom:**

```bash
$ ls .local.d/bioskop/master/host.preview/manifests/
1-manifests.k8s.yaml
2-layer-storage.k8s.yaml  # ← Extra files indicate nested Charts
```

**Diagnosis**: Some Component incorrectly extends `Chart` instead of `Construct`.

**Fix**: Change all Component classes to extend `Construct`.
