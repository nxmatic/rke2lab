== Config subsystem — per-subsystem view

Step 2's second subsystem to adopt the ritual. The OSGi bench (four modules under `osgi-bench/`)
proved, on the real Felix framework, the *schema/resolution* half of the crossing contract: the
`Require osgi.extender` contract (P1) and an introspectable Metatype `ObjectClassDefinition`
retrieved by PID (P2). The *value/`SectionReader`* half (inverting `Rke2labConfig → ConfigLoader`)
stays stage 3, and Config Admin delivery / DS activation are stages 3–4, gated.

The bench is disposable scaffolding — it proved the principles without touching production config
code (`InfraDomain`, `InfraConfigRegistry`, `Rke2labConfig` all unchanged). Real config will adopt
these patterns by MOVE in later increments, never by duplication.

=== Verdict — does it hold?

An honest reading:

. *Monotone: yes.* No built box erased or rewired from BEFORE to AFTER. The three boxes
  (`InfraDomain` loop, `InfraConfigRegistry`, `Rke2labConfig`) are unchanged because the bench is
  separate scaffolding — it proved the contract without touching production. The three green
  additions (the Require/Provide extender pair + the Metatype OCD) are NEW, not rewrites.

. *Honest scope:* only the *schema/resolution* half is proven here. The `Require osgi.extender` +
  `Provide osgi.extender` contract is resolved by the REAL Felix framework (P1:
  `ExtenderContractSpikeTest`), and the Metatype `ObjectClassDefinition` is introspectable by PID
  (P2: `MetatypeIntrospectionSpikeTest`). The *value* channel (`SectionReader`, inverting
  `Rke2labConfig → ConfigLoader`) is stage 3, and Config Admin delivery / DS activation are stages
  3–4, deferred.

. *The proof is on the REAL engine, not asserted.* Both tests run on the real embedded Felix
  framework (via `OutOfContainerFrameworkExtension`, a JUnit5 extension), installing real bundles built by
  `bnd-maven-plugin`. P1 proved the framework refuses to resolve when the host is absent
  (`BundleException`). P2 proved typed access (no reflection) by having the framework export
  `org.osgi.service.metatype` from the system bundle (`system.packages.extra`) so the test and
  felix.metatype share one API copy.

. *Metatype is a NEW box.* The atlas previously defined the crossing contract as `Require
  osgi.extender` + `SectionReader` (value channel); Metatype (schema) is the new addition this slice
  introduced. Its additivity is proven above: it connects to the existing `InfraConfigRegistry` by
  describing its shape, but does not rewrite any existing box.

Conclusion: the config constellation holds, and the extender + Metatype additions are monotone. The
bench is disposable scaffolding that graduates these principles to the durable atlas.

*Confirmed in code.* The bench shipped on `refactor/config-extender` with four modules

=== Verdict — does the value-channel half hold?

. *Additive core.* `InfraDomain` / `InfraConfigRegistry` / `Rke2labConfig`'s record shape, the shipped
  extender + Metatype (E/F), and `BootstrapIdentity` (`manifests-contract`) are unchanged. The value
  channel is the seed-broker amendment mechanism (`AmendmentContributor` / `AmendmentAssembler` in
  `seed-broker-port`, the domain reflector in `-core`) — additive, no production island touched.

. *Named erasure #1 — the crossing inversion.* `Rke2labConfig` no longer needs `ConfigLoader` on the
  synth path: the host reads its config verbatim and pushes it as an amendment (a serialized JSON
  `String`, the seam rule), decoded OSGi-side by the domain's own codec. The value crosses the
  frontier as data, not as a host reference — the "wrong-direction crossing … to invert" the L0
  two-spaces frame named.

. *Named erasure #2 — the hardcoded leak collapses.* The `bioskop` constant in `DefaultNodeEnvContext`
  and its copy in `CloudConfigManifestsUnit` are gone; identity flows from the WORKTREE amendment into
  one `NodeEnvContext` that projects three view records (identity / topology / paths). Deleting the
  duplication IS the fix. *(SHIPPED — commit `e9bf9656`.)*

. *`ClusterConfiguration` dissolved, not built.* The pulled `ClusterConfiguration` service +
  `RuntimeConfigRegistry` + per-domain Config-Admin PID (now discarded — see the guard note) were
  SUPERSEDED by the amendment channel: PULL (a consumer `@Reference`s a service and asks) became PUSH
  (the host contributes at the door; the value arrives pre-bound on the wire-record). The push shape
  is location-transparent by the seam rule and invents no new service type.

Conclusion: the value-channel half shipped as the seed-broker amendment channel — the leak fix (State
A) is live; the `ClusterConfiguration` service is superseded, not pending.

[NOTE]
====
*State A shipped; the mechanism is the amendment channel, not a `ClusterConfiguration` service.* The
`bioskop` leak is dead (one `NodeEnvContext`, three view records). The pulled `ClusterConfiguration`
service was discarded — see link:../config/runtime-config-projection-design.adoc[the guard note] and
link:../osgi/seed-broker-spec.adoc[the seed-broker spec] (§ @Amendment) for the realized push channel.
====

=== Design scenarios — the config capabilities as DSL sentences

The third movement (see <<the-scenario-map>>) for the config seam. GIVEN the enum island shipped,
WHEN the extender contract / schema lands, THEN the capability AND its additivity. The two proven
halves are playable on the OSGi bench; the value channel is narrated.

. *The framework refuses to resolve a config bundle without its host* — `[playable]` green +
.. GIVEN `InfraDomain` / `InfraConfigRegistry` / `Rke2labConfig` shipped as a pure record island
.. WHEN the config bundle declares `Require osgi.extender` and no host provides it
.. THEN the real Felix framework refuses to resolve (a `BundleException`, P1) — AND the production
   island is untouched, the contract is a new box.

. *Config keys are introspectable by PID, typed, no reflection* — `[playable]` green +
.. GIVEN the registry's fragments and their key shapes
.. WHEN a Metatype `ObjectClassDefinition` describes them, retrieved by PID (P2)
.. THEN config keys (name, type, required) are introspectable by PID without reflection — AND the OCD
   describes the existing registry without rewriting it.

. *A pure config record reads its values through a SectionReader, not ConfigLoader* — `[narrated]`
  amber +
.. GIVEN the wrong-direction crossing `Rke2labConfig → ConfigLoader` the two-spaces frame flags
.. WHEN the `SectionReader` value channel inverts it (stage 3)
.. THEN a pure config record reads its values across the bundle/host contract, not by reaching into
   host code — AND the crossing is inverted, not duplicated (real config adopts by MOVE).

. *Config is delivered and activated by the running framework* — `[narrated]` amber +
.. GIVEN the resolved extender contract and the introspectable schema
.. WHEN Config Admin delivery + DS activation land (stages 3–4)
.. THEN config values are delivered to components and activate them through the framework — AND this
   composes onto the shipped registry, additive.

. *Each domain receives its config as an amendment bound onto its wire-record* — `[shipped]` green +
.. GIVEN the host holds the operator config (`rke2lab:manifests:`) and the cluster identity it derives
.. WHEN it contributes the FACET as a standing `AmendmentContributor` and sows the WORKTREE / SOIL roles
.. THEN the domain's amend reflector merges them and binds them onto `ManifestsRunbookInput` — the
   handler receives an already-filled input, naming no config field. (commit `8f9b3e95`)

. *A consumer reads a narrow view, not the fat context* — `[shipped]` green +
.. GIVEN `NodeEnvContext` once exposed every path, node, cluster and network accessor at once
.. WHEN it is segregated into three view records (identity / topology / paths) it composes
.. THEN each consumer reads only the view it needs (interface segregation) — AND the per-context path
   adaptation stays the shipped `incus-contract-host` `BootstrapPaths.asHostView`, ungeneralised (YAGNI).
   (commit `75627e53`)

. *One NodeEnvContext projection replaces the hardcoded identity* — `[shipped]` green +
.. GIVEN `DefaultNodeEnvContext` hardcoded `CLUSTER_NAME = "bioskop"`, copied in `CloudConfigManifestsUnit`
.. WHEN identity flows from the WORKTREE amendment into one `NodeEnvContext` projecting the identity view
.. THEN cluster identity has a single source and the `bioskop` leak cannot recur — AND no
   `DefaultBootstrapNodeEnvContext` twin ever existed; the duplication was the constant, now deleted.
   (commit `e9bf9656`)

*Coverage of this view:* 7 capabilities, 7 scenarios — complete per <<scenario-completeness>>. Two
playable-green (proven on the bench); three shipped-green (the runtime-config projection, in
production — commits `e9bf9656` / `75627e53` / `8f9b3e95`); two narrated-amber (the value/activation
half, design, gated).
