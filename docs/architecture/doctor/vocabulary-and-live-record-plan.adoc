*Goal:* correct the doctor's domain vocabulary to American clinical English (atomic, no-compat),
then wire the live doctor to retrieve the patient's `MedicalRecord` from a registry it holds.

*Architecture:* two sequenced chantiers on branch `feature/doctor-live-record`. Chantier 1 is a
pure rename refactor guarded by the existing doctor test suite (zero behavior change). Chantier 2
adds a `MedicalRecordRegistry` the `Generalist` holds and a lazy, file-backend-backed
`LiveMedicalRecordRegistry`; the doctor retrieves the record as the first act of a consultation.

*Tech stack:* Java 25 (records, sealed), JUnit 5, Maven (flox toolchain), Pulumi Java Automation
API (`pulumi-automation-ext`), kroki/mermaid for docs.

*Source of truth:* design at link:vocabulary-and-live-record-design.adoc[vocabulary-and-live-record-design.adoc].

== Conventions in force (read before any task)

* *Build verification* — a green build LIES by default (root `.mvn` forces `-DskipTests`; the
  build cache replays). The ONLY trustworthy verification command is:
+
[source,console]
----
flox activate -- ./mvnw -pl :seed-master -am clean test \
    -Dmaven.build.cache.skipCache=true -DskipTests=false
----
+
After it runs, COUNT the surefire reports and read `Tests run:` — never trust `BUILD SUCCESS`
alone. `pulumi-automation-ext` is a sibling; `-am` builds it from source.

* *No-compat* — old names, old methods, and the old output key are DELETED in the same change
  that introduces the new ones. No aliases, no `@Deprecated`, no dual-key shims.

* *Uniformity* — a rename is atomic: every site (main + test + the live `.adoc` docs) moves in
  one commit. A half-migrated name is a bug, not a follow-up.

* *Commits* — one commit per task; end the message with the Co-Authored-By trailer.

=== Task 10 — `LiveMedicalRecordRegistry` — coordinate derivation + degrade-to-empty

*Files:* create `LiveMedicalRecordRegistry.java`; test
`LiveMedicalRecordRegistryTest.java`.

Design: holds nothing patient-specific; on `recordFor(patient)` it builds
`StackHandle.forBackend(backendDir, patient.project(), patient.stack())` →
`StackHandleSnapshotSource` → `MedicalRecordReader.read(patient)`, MEMOIZED per patient for the
instance's lifetime (a `Map<Patient, MedicalRecord>` computed-once). Backend dir comes from
`PULUMI_BACKEND_URL` (strip `file://`); if the env var is absent or not a `file://` URL, OR
`read` throws `MedicalRecordReconstructionException`, return the empty record and log the reason
via an injected `Consumer<String>` logger. Constructor:
`LiveMedicalRecordRegistry(Path backendDir, Consumer<String> logger)` plus a static factory
`fromEnvironment(Consumer<String> logger)` that parses `PULUMI_BACKEND_URL` and returns a registry
whose `recordFor` degrades to empty when the URL is unusable.

* [ ] *Step 1 — failing test: file:// parse.* In `LiveMedicalRecordRegistryTest`, assert
  `fromEnvironment` given `PULUMI_BACKEND_URL=file:///tmp/x/.pulumi-state` (inject via a parsing
  helper that takes the raw string, to avoid mutating real env) resolves `backendDir` to
  `/tmp/x/.pulumi-state`. Run: expect FAIL (class/method absent).
* [ ] *Step 2 — failing test: degrade-to-empty on absent backend.* Construct the registry over a
  `backendDir` that does not exist; assert `recordFor(PATIENT)` returns a record with
  `visits().isEmpty()` AND the injected logger received one non-blank line. Expect FAIL.
* [ ] *Step 3 — failing test: real reconstruction over a seeded backend.* Reuse the
  `SeededMedicalHistoryTest`/`RealGraphInjectionTest` fixture (file backend with ≥2 seeded visits);
  point the registry at `fixture.backendDir()` and assert `recordFor(seededPatient).visits()` is
  non-empty and `historyOf(seededSymptom)` sees the prior occurrence. Expect FAIL.
* [ ] *Step 4 — implement.* Write `LiveMedicalRecordRegistry` per the design above (memoized map,
  `file://` strip, try `read` / catch `MedicalRecordReconstructionException` → log + empty,
  catch a non-file URL → log + empty). Reuse package-private `MedicalRecordReader` +
  `StackHandleSnapshotSource` directly.
* [ ] *Step 5 — verify.* Trustworthy command, the 3 new tests PASS; total count = Task 8 + 3.
* [ ] *Step 6 — commit.* `feat(doctor): LiveMedicalRecordRegistry — lazy, file-backend, degrade-to-empty`.
