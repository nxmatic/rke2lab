**Context**: Phase 1 complete (master node + CAPI/Flux operators installed). This plan details how to transition to the gitops-mgmt vCluster pattern while maintaining operational infrastructure.

== Executive Summary

**Goal**: Establish a reentrant GitOps architecture where Flux manages the cluster from within a dedicated `gitops-mgmt` vCluster, enabling upgrade testing and isolation.

**Key Decision**: Use **Option A - Bootstrap Minimal via RKE2 Auto-Deploy**, then transition to Flux management. This pragmatic approach:

* ✅ Reuses existing RKE2 auto-deploy infrastructure for critical bootstrap
* ✅ Maintains infrastructure dependencies (CNI, storage, networking)
* ✅ Minimizes systemd complexity while keeping essential components
* ✅ Enables clean transition to Flux-managed workloads

**Architecture**:
```
Layer 1: RKE2 Auto-Deploy (infrastructure critical)
    ↓ Enables
Layer 2: Pulumi Creates gitops-mgmt vCluster
    ↓ Enables
Layer 3: Flux Manages Everything Else
```

== Architecture Decision: Three-Layer Bootstrap

=== Layer 1: RKE2 Auto-Deploy (Infrastructure Critical)

**Purpose**: Install ONLY the components required for Layer 2 to function.

**Criterion**: "Without this, Flux or gitops-mgmt vCluster cannot start."

**Components**:

[cols="2,3,3"]
|===
|Domain |Components |Rationale

|**Bootstrap**
|VClusterOperatorComponent +
FluxOperatorComponent +
ClusterApiOperatorComponent
|Required to create gitops-mgmt vCluster and enable CAPI-based peer provisioning

|**Networking**
|CiliumConfigComponent +
CiliumAdvancedComponent +
KdnsComponent +
KubeVipComponent
|CNI is blocking - no pods work without Cilium. DNS and VIP required for control plane access.

|**Mesh**
|TailscaleComponent +
HeadscaleComponent
|VPN access to cluster required for `kubectl` and operator access to control plane

|**Storage**
|OpenebsZfsComponent
|PersistentVolumes required for infrastructure components (Flux state, etcd if external)

|**Platform**
|ReplicatorComponent
|Cross-namespace secret replication required for bootstrap credentials

|**Runtime**
|RuntimeRke2ConfigComponent +
RuntimeEnvConfigComponent
|Master node configuration (NOT peer nodes - those via CAPI cloud-init)
|===

**Systemd Units**: 6 services

```
rke2lab-manifests.target
├─ rke2lab-bootstrap-manifests.service    (operators)
├─ rke2lab-networking-manifests.service   (Cilium, DNS, VIP)
├─ rke2lab-mesh-manifests.service         (Tailscale, Headscale)
├─ rke2lab-storage-manifests.service      (OpenEBS ZFS)
├─ rke2lab-platform-manifests.service     (Replicator only)
└─ rke2lab-runtime-manifests.service      (master config only)
```

**What's REMOVED from Layer 1** (compared to current architecture):
* ❌ CI/CD domain (Tekton) → Layer 3
* ❌ CertManagerComponent → Layer 3
* ❌ FluxInstance CR → Not needed (Flux lives in gitops-mgmt)
* ❌ RuntimeCloudConfigComponent for peers → Layer 3 (via CAPI)
* ❌ Envoy Gateway → Layer 3

=== Layer 2: Pulumi Creates gitops-mgmt vCluster

**Purpose**: Bootstrap the management vCluster with Flux inside.

**Prerequisites**: Layer 1 complete, all operators Ready.

**Steps**:

1. **Pulumi waits for Layer 1 readiness**:
   ```java
   // Wait for vCluster Operator
   // Wait for Flux Operator
   // Wait for Cilium (CNI ready)
   // Wait for OpenEBS (storage ready)
   ```

2. **Create VCluster CR: gitops-mgmt**:
   ```java
   new KubernetesManifest(scope, "gitops-mgmt-vcluster",
     KubernetesManifestOptions.builder()
       .manifest(List.of(Map.of(
         "apiVersion", "vcluster.loft.sh/v1",
         "kind", "VCluster",
         "metadata", Map.of(
           "name", "gitops-mgmt",
           "namespace", "gitops-mgmt"
         ),
         "spec", Map.of(
           "sync", Map.of(
             "toHost", Map.of(
               "pods", Map.of("enabled", true),
               "secrets", Map.of("enabled", true)
             )
           )
         )
       )))
       .build());
   ```

3. **Bootstrap Flux in gitops-mgmt** (via Command resource):
   ```bash
   # Get vCluster kubeconfig
   vcluster connect gitops-mgmt -n gitops-mgmt --print > /tmp/gitops-mgmt.kubeconfig

   # Bootstrap Flux
   flux bootstrap github \
     --kubeconfig=/tmp/gitops-mgmt.kubeconfig \
     --owner=nxmatic \
     --repository=rke2lab \
     --branch=main \
     --path=gitops/flux-system
   ```

4. **Inject parent-cluster-kubeconfig Secret**:
   ```bash
   kubectl --kubeconfig=/tmp/gitops-mgmt.kubeconfig \
     create secret generic parent-cluster-kubeconfig \
     -n flux-system \
     --from-file=kubeconfig=$HOME/.kube/config
   ```

**Output**: gitops-mgmt vCluster with Flux watching GitHub, ready to manage parent cluster.

package io.nxmatic.rke2lab.manifests.domains.bootstrap;

import io.nxmatic.rke2lab.manifests.api.ManifestDomainCatalog;
import io.nxmatic.rke2lab.manifests.api.ManifestSynthesisRequest;
import io.nxmatic.rke2lab.manifests.domains.bootstrap.components.*;
import software.constructs.Construct;
import java.util.List;

/**
 * Bootstrap domain - operators required for Layer 2 bootstrap.
 *
 * <p>Components:
 * <ul>
 *   <li>VCluster Operator: Creates and manages vClusters
 *   <li>Flux Operator: Manages Flux instances
 *   <li>Cluster API Operator: Manages CAPI providers
 * </ul>
 */
public final class BootstrapDomain {
  private static final ManifestDomainCatalog CATALOG =
      ManifestDomainCatalog.builder().addDefaultDomains().build();

  private List<Class<?>> selectedComponents = null;
  private boolean allComponents = false;

  public BootstrapDomain withAllComponents() {
    this.allComponents = true;
    return this;
  }

  @SafeVarargs
  public final BootstrapDomain withComponents(Class<?>... components) {
    this.selectedComponents = Arrays.asList(components);
    return this;
  }

  public void synthesize(Construct scope, ManifestSynthesisRequest request) {
    List<ManifestUnit> units = allComponents || selectedComponents == null
        ? getAllUnits()
        : getSelectedUnits();

    for (ManifestUnit unit : units) {
      unit.apply(scope, request);
    }
  }

  private List<ManifestUnit> getAllUnits() {
    return List.of(
        new VClusterOperatorComponent(),
        new FluxOperatorComponent(),
        new ClusterApiOperatorComponent()
    );
  }

  private List<ManifestUnit> getSelectedUnits() {
    // Instantiate selected components
    return selectedComponents.stream()
        .map(this::instantiate)
        .toList();
  }
}
```

public class GitopsMgmtVClusterLayer extends ComponentResource {
  public GitopsMgmtVClusterLayer(String name, ComponentResourceOptions options) {
    super("rke2lab:vcluster:GitopsMgmt", name, options);

    // Wait for vCluster Operator to be ready
    var vclusterCrd = CustomResource.get("vcluster-crd",
      Output.of("vclusters.vcluster.loft.sh"));

    // Create namespace
    var namespace = new Namespace("gitops-mgmt",
      NamespaceArgs.builder()
        .metadata(ObjectMetaArgs.builder()
          .name("gitops-mgmt")
          .build())
        .build(),
      CustomResourceOptions.builder()
        .parent(this)
        .dependsOn(vclusterCrd)
        .build());

    // Create VCluster CR
    var vcluster = new CustomResource("gitops-mgmt-vcluster",
      CustomResourceArgs.builder()
        .apiVersion("vcluster.loft.sh/v1")
        .kind("VCluster")
        .metadata(ObjectMetaArgs.builder()
          .name("gitops-mgmt")
          .namespace("gitops-mgmt")
          .build())
        .otherFields(Map.of(
          "spec", Map.of(
            "sync", Map.of(
              "toHost", Map.of(
                "pods", Map.of("enabled", true),
                "secrets", Map.of("enabled", true)
              )
            )
          )
        ))
        .build(),
      CustomResourceOptions.builder()
        .parent(this)
        .dependsOn(namespace)
        .build());

    // Bootstrap Flux (via local Command)
    var fluxBootstrap = new Command("flux-bootstrap",
      CommandArgs.builder()
        .create(vcluster.id().apply(id -> String.format("""
          set -e
          # Get vCluster kubeconfig
          vcluster connect gitops-mgmt -n gitops-mgmt --print > /tmp/gitops-mgmt.kubeconfig

          # Bootstrap Flux to GitHub
          flux bootstrap github \
            --kubeconfig=/tmp/gitops-mgmt.kubeconfig \
            --owner=nxmatic \
            --repository=rke2lab \
            --branch=main \
            --path=gitops/flux-system \
            --personal=false

          # Inject parent-cluster-kubeconfig
          kubectl --kubeconfig=/tmp/gitops-mgmt.kubeconfig \
            create secret generic parent-cluster-kubeconfig \
            -n flux-system \
            --from-file=kubeconfig=$HOME/.kube/config \
            --dry-run=client -o yaml | \
            kubectl --kubeconfig=/tmp/gitops-mgmt.kubeconfig apply -f -

          # Cleanup temp kubeconfig
          rm /tmp/gitops-mgmt.kubeconfig

          echo "Flux bootstrap complete"
          """)))
        .build(),
      CustomResourceOptions.builder()
        .parent(this)
        .dependsOn(vcluster)
        .build());

    this.registerOutputs();
  }
}
```

== Critical Decision Points

Throughout implementation, these decisions may require adjustment:

=== 1. CAPI Operators Placement

**Current decision**: Layer 1 (RKE2 auto-deploy) with vCluster Operator.

**Rationale**: CAPI may be needed for gitops-mgmt infrastructure itself (if vCluster uses CAPI underneath).

**Alternative**: Move to Layer 3 (Flux) if only needed for peer provisioning.

**Validation**: During Phase 2, verify whether gitops-mgmt vCluster creation requires CAPI.

=== 2. Storage for gitops-mgmt

**Current decision**: Layer 1 (OpenEBS ZFS).

**Rationale**: Flux may need PersistentVolumes for state.

**Validation**: During Phase 2, check if gitops-mgmt vCluster requests PVs. If not, consider moving storage to Layer 3.

=== 3. Mesh Access Requirements

**Current decision**: Layer 1 (Tailscale + Headscale).

**Rationale**: VPN required for operator access to cluster.

**Alternative**: If VPN only for workloads, move to Layer 3.

**Validation**: Confirm that `kubectl` access requires Tailscale/Headscale running.
