== Architecture: Flox Environment Injection for Pods

=== Three-Tier Environment Model

**Goal**: Pods in bioskop use flox-provided executables from nix store via annotation-based injection.

[mermaid]
----

    subgraph Operator["Operator Environment (dev machine)"]
        OpTools[pulumi, cdk8s-cli, incus-client<br/>+ fleet/git, jdk, k8s, pulumi, shell<br/>+ ADD: fleet/keyhole]
    end

    subgraph BootstrapNode["Bootstrap Node (master host)"]
        RKE2[RKE2 server binary]
        NixStore[Nix store with flox environments]
        DaemonSet[Flox NRI DaemonSet<br/><i>trampolines environments</i>]
    end

    subgraph Pods["Cluster Workloads (pods)"]
        Annotation[flox.dev/environment: fleet/k8s]
        Webhook[Mutating Webhook<br/><i>injects volumes + env</i>]

    end

    OpTools -.->|synthesizes| BootstrapNode
    DaemonSet -->|materializes| NixStore
    Annotation -->|triggers| Webhook
    Webhook -->|mounts + env vars| NixStore
    NixStore -->|provides| Executables

=== Tier 2: Bootstrap Node (Master Host)

**Components**:

- RKE2 server binary (installed by RKE2 install script)
- Nix store with flox environments
- Flox NRI plugin DaemonSet (existing pattern)

**DaemonSet responsibilities**:

- Materialize flox environments to `/srv/host/k8s-daemonset.d/runtime/flox/environment.d/`
- Update nix store on nodes
- Publish environment metadata via ConfigMap (nix store paths)

**Pattern**: Reuses existing flox NRI plugin architecture.

=== Tier 3: Cluster Workloads (Pods)

**NEW ARCHITECTURE**: Pods use flox annotations for executable injection.

**Annotation format**:

[source,yaml]
----
apiVersion: v1
kind: Pod
metadata:
  annotations:
    flox.dev/environment: "fleet/k8s"  # or "fleet/keyhole"
spec:
  containers:
  - name: app
    image: alpine:latest  # minimal base image
    command: ["/nix/store/xxx-kubectl/bin/kubectl", "version"]
----

**Mutating admission webhook** injects:

1. **Volume mounts** - nix store read-only:
+
[source,yaml]
----
volumeMounts:
- name: nix-store
  mountPath: /nix/store
  readOnly: true
volumes:
- name: nix-store
  hostPath:
    path: /nix/store
    type: Directory
----

2. **Environment variables** - flox environment:
+
[source,yaml]
----
env:
- name: PATH
  value: "/nix/store/xxx-kubectl/bin:/nix/store/yyy-helm/bin:..."
- name: FLOX_ENV
  value: "fleet/k8s"
----

3. **Init container** (optional) - environment verification

**Webhook implementation** (future):

- Deployed in `flox-system` namespace
- Cluster-wide scope with opt-in annotation
- Reads ConfigMap for nix store paths (published by DaemonSet)
- Failure policy: Fail (missing tools should block pod creation)
- Certificate: cert-manager managed TLS

=== Environment Availability

**How environments reach nodes**:

1. Flox NRI plugin DaemonSet materializes environments to host
2. Nix store paths available for volume mounting
3. ConfigMap publishes environment metadata (paths, versions)
4. Webhook reads ConfigMap to inject correct paths

**Phase 1 scope**: Verify these environments exist and are suitable.

**Future work**: Implement webhook injection based on annotations.

== Benefits of Flox Injection Architecture

**Single source of truth**:

- Tool versions defined in flox environments
- No version drift between dev and cluster
- Update once, applies cluster-wide

**Minimal container images**:

- Base images (alpine, busybox) sufficient
- No need for kubectl/helm/etc in every image
- Smaller image sizes, faster pulls

**Consistent with existing patterns**:

- Reuses flox NRI plugin DaemonSet pattern
- Same nix store maintenance
- Unified environment management

**Easy updates**:

- Update flox environment
- Refresh DaemonSet
- All pods get new tool versions

**Developer experience**:

- Same tools locally and in-cluster
- Annotate pod, get tools
- No Dockerfile changes for new tools
