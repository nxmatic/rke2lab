= Staging gates & their governance model
:toc: left
:icons: font

== Overview

The OSGi bundle staging is driven by a Maven extension (`maven-embed-staging-ext/staging-extension`)
that, beyond wiring the shade/dependency-plugin lists, enforces a set of *staging laws* — build-time
invariants read from bundle bytecode. A law that finds violations can fail the build. This is the
project's answer to a recurring problem: a discipline asked for at review time silently rots between
reviews. A *gate* is seen at every build (impossible to forget) and, once a bundle's debt is cleared,
its default level locks the rule so the anti-pattern can never silently reappear.

This document specifies the six gates and the single annotation that governs how each reports.

[NOTE]
====
The gate enum is named `StagingGate` (in `osgi/domain-annotations`), not `Gate` — the bare word
collides with the project's two *runtime* gate senses (readiness gates like
`SeedSystemdAdapterEndpointGate` / `ConfigEntryGate` / `ManifestUpdateGate`, and network *gateways*).
`StagingGate` says the build-time sense explicitly and aligns with the subsystem name
(`maven-embed-staging-ext`, "staging laws"). The extension carries a mirror enum of the same name
(it reads the annotation via ASM and cannot link the module — see "Reader side").
====

=== The six gates

[cols="1,3",options="header"]
|===
| StagingGate | Law

| `RECORD_PURITY`
| A `type=record` bundle may export only records, enums, and sealed ADT roots — a pure-data bundle,
  never behaviour. (Read by `RecordPurity`.)

| `SPEC_COVERAGE`
| Every type a bundle exports must be named in a `docs/` architecture spec, or carry
  `@Transitional` (a traced migration whose spec describes the successor). A type in neither is
  code-out-of-spec. (Read by `SpecCoverage`.)

| `INSTANCE_DISCIPLINE`
| A bundle's exported types must not publish `public static` behaviour helpers (the instance-passing
  discipline — pass instances through the call graph, no `XxxHelper.staticMethod()`). The *target is
  zero*. Factory methods (`of`, `from*`, `parse`, `valueOf`, `builder`, `create`, `defaults`, `new*`,
  or a method returning its own declaring type) are part of the rule, not exceptions — they are
  construction, not behaviour. Constants (fields) are not inspected. Anything else that must stay
  static is an EXPLICIT exception, annotated `@Exempt` (see below) — never widened into the
  heuristic. (Read by `InstanceDiscipline`.)

| `REALM_BOUNDARY`
| A class may reference only types REACHABLE in its own classloader realm — the build-time guard of
  the host↔OSGi boundary the link:world-gateway-spec.adoc[world gateway] defines. The two realms:
  the *flat realm* (the host exec classes + the flat dependency tail + the system-exported `type=seam`
  ports — one classloader) sees everything flat but NOT a bundle-side export; a *bundle realm* (one
  per `isDomain()` bundle: `model`/`edge`/`record`) sees its own packages + its wired
  `Import-Package` + the system packages. A reference that leaves the realm is a leak. Read by
  `RealmBoundary` (see below). (Target zero; the gate the `doctor.records`-into-the-host drift would
  have caught.)

| `DUPLICATE_REALM_CLASS`
| No class may be present in more than one realm's classpath — the guard against the two-realm
  linkage failure (the jackson `JavaTimeModule not a subtype` regression): a class loaded by two
  classloaders is two distinct types, and passing an instance across the seam throws. Legitimate
  dual-realm cases (a flat realm-library nested into a bundle, e.g. the cdk8s carrier or the document
  codec) are EXEMPT — the exemption is *derived from the seam surface*, not a hand-list. (Read by the
  duplicate-realm scan.)

| `SCHEMA_CONCORD`
| Under records-as-contract: every `Coordinate` (the closed set of document types the world gateway
  crosses) must have a `@DocumentContract` wire-record whose JSON Schema is *generated from the
  record* and checked for concord at build — a coordinate with no wire-record, or a schema that
  drifts from the record, fails. Locked at ERROR by the 2D increment. (Read by `SchemaConcord` /
  `DocumentContractScan` / `RecordSchemaProjector`.)
|===

==== `REALM_BOUNDARY` — the two-realm model, in detail

The other three gates judge a bundle's *exported* surface and read *signatures only*
(`ClassReader.SKIP_CODE`). `REALM_BOUNDARY` judges the *consumer* direction and must read *method
bodies* — the drift it catches is `Severity.parse()`, an `invokestatic` inside a body, not a
signature. It reads every referenced type (the constant pool's `CONSTANT_Class` entries + descriptors,
the jdeps technique) and keeps only those under our root (`io.nxmatic.rke2lab.*` — same jurisdiction
filter as its twins; a reference to a JDK or jackson type is not ours to police).

* *The forbidden set of the flat realm* — the union of `ourExportedPackages()` of every `isDomain()`
  bundle (model/edge/record) in the resolved set. For our drift this includes
  `io.nxmatic.rke2lab.doctor.records`. A flat-realm class that references a type in that set leaks: the
  flat host classloader cannot load a bundle-only package at runtime (`NoClassDefFoundError`).
* *The visible set of a bundle realm* — the bundle's own packages + its `Import-Package` (already read
  by `ResolvedBundle`) + the system packages. A bundle-realm class referencing one of OUR types
  outside that set is an OSGi-internal leak (one domain reaching into another it does not import).

*Auto-attribution.* Because the SAME law runs on BOTH realms, each violation is classified by the
realm it falls in: a flat-realm line is a *host/seam leak* (migrate the host), a bundle-realm line is
an *OSGi-internal leak* (fix the domain). The scanned realm IS the label — no separate heuristic. For
our drift the bundle realms come back clean (bnd derives `Import-Package` from the bytecode, so a
domain that uses `doctor.records` already imports it); the flat realm carries the worklist (the host
files + the two `-port` seams that import `doctor.records`).

*New input the extension must acquire.* The flat realm includes the exec-module's OWN compiled
classes (`ControlplanePolicy`, the host stages) — which live in the current project's
`target/classes`, NOT in any resolved dependency jar. The other gates only ever read resolved
dependency jars; `REALM_BOUNDARY`'s flat scan additionally reads the current project's build output
directory.

== Governance — `@GovernedBy(StagingGate, EnforcementLevel)`

Each gate reports at an `EnforcementLevel`, declared per-package on a `package-info`:

[cols="1,3",options="header"]
|===
| Level | Effect

| `ERROR` (default)
| A violation breaks the build. The *locked* state: once a bundle is clean, the default keeps it
  clean forever.

| `WARN`
| Violations are listed as a warning, build stays green. A visible, shrinking backlog — a bundle on
  its way to `ERROR`.

| `IGNORE`
| Violations are silent. Build infrastructure only (a module that powers a gate cannot be governed
  by it), never a way to hide a real domain's debt.
|===

`@GovernedBy` is `@Repeatable` and `@Target(PACKAGE)`: one pose per gate, each with its own level. A
gate with NO `@GovernedBy` for a package treats it at the default `ERROR` — so *governed by default*
is the standing guarantee; a package opts a single gate down to `WARN`/`IGNORE` explicitly.

[source,java]
----
@GovernedBy(StagingGate.SPEC_COVERAGE, EnforcementLevel.WARN)         // listed, build green
@GovernedBy(StagingGate.INSTANCE_DISCIPLINE, EnforcementLevel.ERROR)  // breaks the build
package io.nxmatic.rke2lab.netplan.port;
----

The annotations live in `osgi/domain-annotations` — a dependency-free bundle common to ALL domains,
so even a `type=record` leaf under the purity guard can be annotated without taking on a dependency,
and no domain depends on another's annotation module.

== Exemptions — `@Exempt(StagingGate, reason)`

`@GovernedBy` lowers the report level for a whole *package*; `@Exempt` removes a *single element* from
one gate, with a written reason. It is the precise opposite of widening the detection heuristic: the
gate stays strict (the `INSTANCE_DISCIPLINE` target is zero static helpers), and a member that must
legitimately stay static carries an explicit, reviewable exemption rather than being silently absorbed
by a broader name rule.

[source,java]
----
public final class ClusterNetworkBlueprint {
  @Exempt(value = StagingGate.INSTANCE_DISCIPLINE, reason = "pure topology projection, no collaborators")
  public static Topology topology(...) { ... }
}
----

`@Exempt` is `@Repeatable`, `@Target({TYPE, METHOD, FIELD})`, retention `CLASS` (the extension reads it
via ASM, like every other marker). The gate skips an element carrying `@Exempt(thatGate, …)`. Rules:

* the `reason` is mandatory and non-blank — an exemption with no justification is itself a smell;
* an exemption is per-gate, so exempting `INSTANCE_DISCIPLINE` does not touch `SPEC_COVERAGE`;
* it does NOT replace factory recognition: real factories (the verbs above) are part of the rule and
  need no annotation. `@Exempt` is for the residue the rule cannot recognise but review accepts.

Discovering an exemption that recurs across many elements is the signal to reconsider the rule (or the
design), not to keep stamping `@Exempt` — the annotation count is itself a backlog metric.

== Reader side — bytecode, not linkage

The extension is installed BEFORE the reactor that builds `domain-annotations`, so it CANNOT link
those types. It reads them from bytecode through ASM and maps them onto its OWN mirror enums
(`EnforcementLevel`, `StagingGate`) — exactly as it reads bnd header strings into its own `EmbedCapability`
view. The mirror constant NAMES must stay in step with the annotation module's enums.

A `@Repeatable` annotation posed once is stored as `@GovernedBy`; posed twice or more, Java wraps the
poses in the container `@GovernedByAll`. The reader handles BOTH shapes and yields a
`Map<StagingGate, EnforcementLevel>` for the bundle; each gate looks up its own level, defaulting to
`ERROR`.

== Fail-at-end

`enforceGates` runs every law over the whole resolved bundle set (plus, for `REALM_BOUNDARY`, the
current project's own `target/classes`), *collecting* all violations, then fails ONCE with the
complete list. A per-bundle throw would surface only the first offender and force a fix-rebuild-repeat
loop; accumulating shows the whole debt in a single run so it can be cleared in one pass. `WARN`-level
violations are logged (build green); `ERROR`-level violations are what make the single aggregated
failure. This is the mechanism a debt is paid down through: a gate set `WARN` on a package lists its
violations as a shrinking backlog, and dropping the `@GovernedBy` returns it to the locked `ERROR`
default once clean — exactly the lifecycle `REALM_BOUNDARY` follows while the host↔OSGi surface is
migrated to Documents.

== Anti-patterns

[cols="1,1",options="header"]
|===
| ❌ Don't | ✅ Do

| Add a boolean opt-out flag per gate
| One `@GovernedBy(StagingGate, level)` per gate — graduated, not on/off

| Name the level after "drift" (collides with the doctor domain's drift detection)
| `EnforcementLevel` — neutral, gate-agnostic

| Make the extension depend on `domain-annotations`
| Read annotations via ASM into the extension's mirror enums (build-order safe)

| Leave a cleaned bundle at `WARN`
| Drop the `@GovernedBy` for that gate so it returns to the `ERROR` default (locked)

| Widen a gate's heuristic to silence a false positive (e.g. add a name prefix so one static stops
  being flagged)
| Keep the rule strict; annotate the single element `@Exempt(gate, reason)` — explicit, reviewable,
  countable

| Stamp `@Exempt` on a pattern that recurs across many elements
| Treat the recurring exemption as a signal to fix the rule or the design — the `@Exempt` count is a
  backlog metric
|===
