= control-plane → OSGi — migrating the domains, populating the frontier
:toc: left

[NOTE]
====
*Status:* SPEC (2026-07-07). Design of record for migrating the host-side `controlplane/` logic into
OSGi domain services the host CALLS. Converged from the brainstorm on `feature/cluster-seed-scenario`
and a file-by-file placeability verification (this document's §<<verification>>). The reference pattern
is the shipped link:cluster-edge-spec.adoc[cluster-edge] (port + core + edge/fake); the frame lives in
`.claude/claude-preview.adoc` and the memory `controlplane-to-osgi-migration-frame.md`.

This is a *before / after* document, read from the code (the surface inventory of 2026-07-07), not
imposed on it.
====

== Scope — we migrate the DOMAINS, not the pipeline split

Two chantiers; this spec is ONLY the first.

* *Ours — birthing the services.* Create the missing OSGi domains (incus, bbox), extract the
  Pulumi-free logic (config, policy, readiness-verifier, the bdd fragments) into their domains as
  callable services with tests and a fake. Result: the OSGi frontier is populated and correct; the old
  host path stays wired.
* *Not ours — the pipeline split (later).* Re-wiring `ClusterSeedScenario` so a stage CALLS the OSGi
  service instead of the old host code, and deciding which phase lives where. That is *consumption* of
  what we birth, tracked in the migration plan, out of scope here.

The one fuzzy seam: extracting `IncusResourceBootstrap`'s flat decision into an incus `@Component` is
 OURS (the service is born); re-pointing the host to call it is the split (not ours). The old host code
stays in place until the split unwires it.

== The cut line — the two-worlds invariant decides

`grep -ri pulumi osgi/ == 0` ⇒ `com.pulumi` CANNOT enter Felix. So migration is not "move packages",
it is cutting along the plan/render seam. Verified inventory (2026-07-07):

* `controlplane/` = *104 files*; exactly *17 import `com.pulumi.*`* → they ARE the edge (resource
  registration + `Output<T>` wiring), STAY host.
* the other *87 are Pulumi-free* → migrate to OSGi.

The host is a *midwife*: `Pulumi.run(ctx)` crosses the frontier first, calls OSGi through the gateway,
receives a flat value, materialises `com.pulumi.*` resources, then its job is done. One direction only
(host → OSGi via `awaitService`); OSGi never calls back, it returns a flat `Document`. The frontier is
a *birth canal*: crossed once at master's seed, then sealed. The current gateway suffices; no new
machinery.

== Verification — the 87 are all placeable (no dead-end)

File-by-file (5 parallel passes over the 22 files with a host touch). Result: *no host dead-end*. One
hard edge only (`RuntimeCommandPreflight`: `PATH` probe + `ProcessBuilder`, all-static, no seam); the
rest is PLACEABLE or MIXED-healthy (a flat decision core + a host seam already parameterised by an
injected `Path`/`BootstrapPaths`/`Function`, liftable behind a port). The cluster-edge law — *the host
owns the file/loop, the bundle owns the decision* — covers 100% of cases.

The four seam types:

[cols="1,3",options="header"]
|===
| Seam type | Files
| ① HARD — host exec (→ stays host as edge)
| `RuntimeCommandPreflight` (irreducible). `SeedSystemdAdapterEndpointGate` = FALSE alarm: cut already
  made (4 injected collaborators, `@Transitional`).
| ② SOFT — absolute host path (→ lift behind a port)
| `IncusIdentityMaterialAssembler`, `GitMetadataExtractor`, `DeploymentMetadata`, `BboxSecretsReader`,
  `EntryGatePolicyEnforcer`, `ClusterBootstrapReadinessVerifier`, `SeedNodeBootstrapWatcher`.
| ③ SINK — artifact write (flat-out law → trivial edge)
| `ClasspathTreeCopier`, `SystemdTarget`, `MedicalRecordDump`, `RunbookRenderer`,
  `RecordInterventionCommand`, `ClusterSeedTopic` (runbook dir).
| ④ ENV — trivially injectable
| `SeedLog` (log-level at init); `HostSeeder` (JUnit session + system props → stays host, test support).
|===

The verification revealed *four cross-cutting ports* to extract once, shared across domains — the
common prerequisite (increment-0):

[cols="1,1,3",options="header"]
|===
| Cross-cutting port | Domains served | What it isolates
| `HostPathResolver` | config | NFS-automount topology `/net`↔`/private`, `toAbsolutePath()` on CWD
| `GitFactsReader` | policy, incus | jgit worktree (dirty, commit) → flat facts
| `SecretsSource` | bbox, incus | `.secrets` read → bytes/InputStream
| `ArtifactSink` | bdd (×3), incus | rendered-artifact write → the host persists
|===

== Three strata — engine, scenarios, domains

`bdd/` is NOT a domain. Its 33 files split three ways:

* Each triple `XxxStage` + `XxxProbe` + `Simulated/LiveXxxProbe` JOINS its domain (the `Stage` is how
  the domain enters the scenario; `SimulatedXxxProbe` is its fake).
* The engine already EXISTS in OSGi — `osgi/runtime/scenario-engine` (`JUnitLauncherCore`,
  `InContainerJUnitRunner`, `IsolatedWorld`, `OsgiConnection`). It is the *après* that replaces
  `osgi/foundation/pipeline` (`Topic`/`FluentTopicRunner`, in dissolution). It STAYS in `runtime/`:
  `foundation/` never depends on `runtime/`, and scenario-engine depends on `framework-launcher` +
  `junit-testkit` (runtime siblings) — moving it to foundation would invert the layering.
* The remaining spine (`ClusterSeedScenario`, `StageContext`, `SeedProbes`, `Outputs/ResourcesStage`,
  record/render) is the *scenario = the assembly* that runs ON the engine and composes the domains. Its
  "no owner" is normal — owner is the seeding-scenario concern, not a leaf domain.

== The migration mechanism is already proven — the stage gradient

The bascule is not a design; it is *already happening in the code*. A stage migrates by turning
`import controlplane.xxx.ConcreteClass` (direct host call) into `connection.awaitService(XxxPort.class)`
(the OSGi service via the gateway). Read from the imports (2026-07-07):

[cols="1,2,1",options="header"]
|===
| Stage | How it calls its logic | State
| `SystemdAdapterStage` | `awaitService(SystemdRuntimeProbe)`, `ReadinessAuthority`, `ConsultingService` — ports only | ✅ migrated
| `ClusterReadinessStage` | `awaitService(SystemdRuntimeProbe)` + `cluster.port.*` BUT still `import controlplane.readiness.ClusterBootstrapReadinessVerifier` | 🟡 half
| `IncusStage` | `import controlplane.incus.IncusResourceBootstrap` direct, zero awaitService | 🔴 blocked (no service yet)
| `BboxStage` | `import controlplane.bbox.BboxReconciliationOrchestrator` direct | 🔴 blocked (no service yet)
|===

The stages that are NOT migrated are exactly incus and bbox — the two domains with no OSGi module. You
cannot migrate `IncusStage` to `awaitService(IncusPort)` until the incus service exists. *Each domain we
birth unblocks its stage's bascule.* That is the proof the decomposition holds.

=== config — the cleanest entry (one seam)

*Before:* `Rke2labConfig`/`BootstrapConfig` carry the DTO + `from()` derivation (placeable) mixed with
`pathOn`/`normalizeAbsolutePath` — NFS-automount host topology and a `toAbsolutePath()` CWD read.
*After:* the record becomes placeable; the path rewriting moves behind a `HostPathResolver` port (core =
the pure `/net`↔`/private` mapping given an injected base; fake = a fixed-root resolver).

=== policy — most host-anchored (git facts)

*Before:* `EntryGatePolicyEnforcer` opens a real jgit repo at `worktreePath.toAbsolutePath()`
(`enforceCleanWorktree`, `enforceFlakeLockCoherence`); the flake/manifest parsing underneath is pure.
*After:* the flake reasoning is a placeable core; the worktree inspection moves behind a `GitFactsReader`
port returning flat facts (dirty?, HEAD commit). `enforceManifestUpdateGate` already reads the OSGi
registry — fine as-is.

=== readiness — already cluster-edge, one file poll left

*Before:* `ClusterBootstrapReadinessVerifier` already delegates API/controller checks to the injected
`ClusterReadinessContact` (kubectl mechanism gone). The residue is `waitForKubeconfigPublished` reading
`config.kubeconfigRef().toAbsolutePath()`. *After:* the poll uses `HostPathResolver`; the verdict
construction is already flat. This domain is nearly done — it validates the pattern.

=== bdd fragments — dispersed to their domains

*Before:* `bdd/` holds per-domain triples plus the scenario spine. *After:* each `XxxStage`/`XxxProbe`/
`SimulatedXxxProbe` joins its domain (readiness, systemd already; bbox, incus on creation); the artifact
writers (`MedicalRecordDump`, `RunbookRenderer`, `RecordInterventionCommand`) keep their flat rendering
core and write through an `ArtifactSink`; `HostSeeder` stays host (JUnit session + system props).

=== bbox — new domain

*Before:* `BboxReconciliationOrchestrator` is a flat decision (a `pulumiMode` branch forwarding a
`Path`); `BboxSecretsReader` resolves `worktreePath/.secrets` (host path) then parses in-memory.
*After:* `bbox-port` (reconcile contract + `SecretsSource` seam), `bbox-core` (the parse/validate +
reconcile decision `@Component`), `bbox-*-fake` (in-memory YAML). The `com.pulumi` reconciler component
stays host. Unblocks `BboxStage`.

=== incus — the hub (four ports, the heaviest)

*Before:* 15 files. Two are already pure (`ProvisioningTarget`, `ProvisioningTargetRegistry`); the rest
are MIXED-healthy — each pairs a flat core (SHA-256 checksum + foreign-descendant exclusion in
`TargetChecksumPipeline`; YAML key-block parse + classpath cert read in the assembler; build-id
formatting in `GitMetadataExtractor`) with an injected host edge (`Path`/`BootstrapPaths`). The fat
class `IncusResourceBootstrap` interlaces the flat provisioning decision with `Output<T>` wiring.
*After:* `incus-port` (provisioning-plan contract), `incus-core` (the checksum/identity/target-plan
`@Component`, consuming `GitFactsReader` + `SecretsSource` + `ArtifactSink` + `HostPathResolver`),
`incus-*-fake`. The flat plan crosses back to the host, which wires `com.pulumi.incus.*` with `Output<T>`
(that wiring is the split, not ours). Unblocks `IncusStage`.

== What stays host

`RuntimeCommandPreflight` (irreducible exec edge; a thin flat veneer — build-ssh-argv, interpret
exit-code — may be lifted, the substance stays). `PreflightStage`/`Probe`. The 17 `com.pulumi` files
(resource registration + `Output<T>`). `HostSeeder` (test-session coupling). `scenario-engine` stays in
`runtime/` (already OSGi, correct layer).

== Build order — each increment green before the next

0. *cross-cutting ports* — `HostPathResolver`, `GitFactsReader`, `SecretsSource`, `ArtifactSink` as seam
   modules (`type=seam`), with in-memory fakes. The shared prerequisite.
1. *config* — record placeable; path rewriting behind `HostPathResolver`. Green.
2. *policy* — flake core; worktree behind `GitFactsReader`. Green.
3. *readiness* — kubeconfig poll via `HostPathResolver`; fold in its bdd Stage/fake. Green.
4. *bdd split* — disperse remaining fragments; artifact writers behind `ArtifactSink`. Green.
5. *bbox* — new port/core/fake; unblock `BboxStage`. Green.
6. *incus* — new port/core/fake, the four ports consumed; extract the flat plan from
   `IncusResourceBootstrap` (wiring stays host); unblock `IncusStage`. Green.

Each domain migrated only BIRTHS the service (tests + fake). Re-pointing the stage to
`awaitService(port)` is the split — tracked separately.

== The SPEC_COVERAGE ratchet during migration

The gate requires every type a bundle EXPORTS to be named in some `docs/` spec. It is a code-first
ratchet, not a violation counter: while `pipeline-port` still exports `Topic`/`FluentTopicRunner`
(because live code — seed AND boot — still uses them), the gate DEMANDS they stay documented. They leave
the specs only when the CODE stops exporting them — when the last pipeline has migrated and
`pipeline-port`'s exports shrink. Migration progress is tracked in the migration plan, not by a gate
count.
