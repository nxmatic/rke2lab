= World exchange 2B — the consult path crosses as a Document
:toc: left
:icons: font

*Status:* DESIGN (converged 2026-06-27, NOT yet built). The second implementation increment of the
world-exchange migration (link:world-exchange-spec.adoc[design of record]), following
link:world-exchange-2a-document-foundation-spec.adoc[2A] (the Document foundation + the readiness
verdict crossing).

2B closes the *consult path*: the host stops producing `Observation`/`Symptom`, stops calling the
record-typed `consult(Symptom,Observation)`, and stops rendering the diagnosis from a
`RemediationPlan`. The doctor's reasoning and rendering move fully OSGi-side; the host transports a
checkpoint Document in and reads strings out.

== Why 2B exists

The `REALM_BOUNDARY` gate's WARN worklist (41 flat `seed-master` classes referencing
`doctor.records` after 2A) is the migration backlog. 2B clears the *consult-path* slice of it: the
two consult stages (`SystemdAdapterStage`, `ClusterReadinessStage`), their probes, their jGiven
scenarios, and the runbook diagnosis render. After 2B, no host class on the consult/failure path
loads `Symptom`, `Observation`, `RemediationPlan`, `ReferralReply`, or `ConsultationReport`.

The remaining worklist families — medical-record reconstruction (`*Reader`, `MedicalRecordRegistry`,
`InterventionLedger*`, `DriftReview`) and the Pulumi-resource egress (`*Resource`,
`ResourceCreationPipeline`) — are later increments (2C/2D), tracked by the same gate.

== The end state (what 2B converges to)

The load-bearing invariant (from the design of record), advanced by 2B on the consult path:

[quote]
Every host↔OSGi seam crossing is a structured, schema-bearing Document. The host TRANSPORTS — it
builds the ingress Document from host-native facts and reads strings / one control field from the
egress Document. It holds NO doctor type and performs NO doctor reasoning or rendering.

After 2A the host reads the readiness *verdict* (action) as a Document. After 2B the host also gets
the *consultation* (narration + the rendered diagnosis) as a Document, and the probes emit a
*checkpoint* Document instead of an `Observation`.

== The cut — by zone, the shared seam first

2B is decomposed *by zone* (the user's choice), but the two consult stages share one seam
(`ConsultingService`, the same three verbs), so the seam migrates ONCE, first, as zone-0; the host
zones then consume it.

[cols="1,4",options="header"]
|===
| zone | what it does

| *zone-0 — the consult seam + the rename*
| `ConsultingService` gains `consult(Document checkpoint) → Document consultation` (the Document
  twin of 2A's `assess`). The OSGi authority (`Generalist`, assembled by `DoctorGraph`) produces the
  consultation Document: the narration strings AND the rendered AsciiDoc diagnosis block (it owns the
  `RemediationPlan`). `DoctorGraph` is renamed `ConsultationDag` (it is the producer of the
  consultation DAG). The three old verbs (`consult(Symptom,Observation)`, `consultedLine`,
  `cohortFinding`) are removed once both host zones stop calling them; the two reconstruction verbs
  (`recordForCurrentPatient`, `reviewOpenProblems`) stay untouched (zone-3 / 2C).

| *zone-1 — systemd-adapter*
| `SystemdAdapterStage` calls `consult(checkpoint)`, logs `consultation.narration`, and the runbook
  reads `consultation.diagnosisAdoc`. Its `SystemdAdapterProbe` returns a checkpoint Document instead
  of an `Observation`; `SeedSystemdAdapterEndpointGate` + the simulated probe stop building
  `Observation.failed(Symptom)`. The stage loads zero `doctor.records`.

| *zone-2 — cluster*
| `ClusterReadinessStage` + `ClusterReadinessProbe` (`Live`/`Simulated`) + the cluster jGiven
  scenario migrate identically. After zone-2 both consult stages are doctor-free.
|===

The order is NOT free: zone-0 MUST precede 1 and 2 (the seam is shared). Zones 1 and 2 are
independent of each other once zone-0 lands.

== The consultation Document (the new coordinate)

A new document type under the existing `doctor` domain, coordinate `consultation`. The host produces
the *checkpoint* (2A's coordinate, EXTENDED — see below) and reads the *consultation* back. Both
carry only strings.

[IMPORTANT]
.The checkpoint must be extended — 2A's is insufficient for routing
====
2A's checkpoint carries `scenarioId`, `failed`, `override` — enough for `assess` (the verdict). But
`consult` today routes on the `Symptom` (the key into the specialists) and reasons over the
`Observation` (summary + details). So the checkpoint 2B feeds `consult` must additionally carry, as
strings/JSON, the *symptom kind* (e.g. `connection-refused`, `timeout` — the `Symptom` slug, not the
enum) and the observation `summary` + `details`. The probe — which today PRODUCES the `Symptom` — now
writes that slug into the checkpoint Document instead. OSGi maps the slug back to its `Symptom`
internally (it owns the enum). Reuse the same checkpoint instance for `assess` and `consult`: the host
builds it once, both verbs read it.
====

The consultation Document the host reads back carries only strings:

[cols="1,1,3",options="header"]
|===
| field | type | meaning

| `checkpointId` | string | the jGiven join key (already a string today); echoed back for the runbook
  scenario join.
| `narration` | string | the `⚕ consulted… / cohort finding` line(s) the host LOGS. Rendered OSGi-side
  (was `consultedLine` + `cohortFinding`).
| `diagnosisAdoc` | string | the `⚕ Diagnosis / 🔬 Assessment / ℞ Mitigation` block as AsciiDoc TEXT,
  produced OSGi-side by `ConsultationDag` from the `RemediationPlan`. The host inserts it verbatim via
  `ScenarioModel.setExtendedDescription` — no doctor type, no render engine.
|===

[IMPORTANT]
====
`diagnosisAdoc` is AsciiDoc *markup* (a `StringBuilder` of text), not rendered HTML. The runbook flow
produces `.adoc` files (jGiven `AsciiDocReportGenerator`) and never converts them — so 2B adds NO
asciidoctor / jruby / graphviz dependency. The diagnosis block's ~18 lines of string-building move
from `RunbookRenderer` (host) to `ConsultationDag` (OSGi), where the `RemediationPlan` lives.
====

These two coordinates (`readiness-checkpoint` from 2A, `consultation` from 2B) get their JSON Schemas
+ the build-time concord check in the schema increment (2D), not here. 2B's own tests round-trip the
Documents its code produces/consumes.

== The typed vocabulary — closed domains are seam enums, not catalog strings

`ExchangeCatalog` from 2A had begun to flatten three different natures into one list of `String`
constants: *coordinates* (a closed set), *enumerated field values* (`stop`/`continue-degraded` — a
closed set), and *payload field keys* (the schema). The first two are closed value domains; carrying
them as loose strings reopens exactly the `clusterApi`-class drift the catalog discipline exists to
prevent — and 2B would have added a third loose domain (the symptom kind the host needs once it drops
`doctor.records.Symptom`).

2B lifts the closed domains into typed seam enums in `osgi/exchange/exchange-port`, each with
`String slug()` + `static Optional<E> parse(String)` (mirroring `Severity.parse`/`Symptom.parse`):

* `Coordinate` — `READINESS_CHECKPOINT`, `READINESS_VERDICT`, `CONSULTATION`.
* `Action` — `STOP`, `CONTINUE_DEGRADED`.
* `SymptomKind` — the five slugs of `doctor.records.Symptom`, host-flat. The host writes
  `SymptomKind.X.slug()` into the checkpoint; `Generalist` maps `SymptomKind`→`Symptom` via an
  exhaustive `switch` (OSGi owns `Symptom`; the seam carries only the flat twin). The no-`default`
  switch is the anti-drift filet — a new symptom forces both enums and the map to update together.

`ExchangeCatalog` slims to its sound role: the single source for *payload field keys* (`DOMAIN_DOCTOR`
+ the `FIELD_*` schema keys). `Document` STAYS the neutral envelope `(String domain, String
coordinate, JsonNode payload)` — the coordinate is NOT typed into it, so the transport never couples
to the (today doctor-only) coordinate vocabulary; call sites write `Coordinate.X.slug()` into the
`String coordinate` slot. This typing is done in zone-0 (Task 1) and migrates the 2A call sites
(`DefaultReadinessAuthority`, `SystemdAdapterStage`) in the same change, for uniformity.

== What moves where (the consult-path units)

[cols="1,3",options="header"]
|===
| unit | change

| `ConsultingService` (doctor-port seam, modified)
| add `Document consult(Document checkpoint)`; remove `RemediationPlan consult(Symptom,Observation)`,
  `String consultedLine(Symptom)`, `String cohortFinding(Symptom)` once unused. Keep
  `recordForCurrentPatient` + `reviewOpenProblems` (reconstruction path, 2C). The seam stops importing
  `Symptom`/`Observation`/`RemediationPlan` on the consult verbs.

| `Generalist` (doctor-core internal, modified)
| implement `consult(Document)`: parse the checkpoint, route to specialists as today, synthesize the
  `RemediationPlan` internally, and render BOTH the narration string and the `diagnosisAdoc` block;
  return them in the consultation Document. The `RemediationPlan` never leaves OSGi.

| `DoctorGraph` → `ConsultationDag` (doctor-core internal, renamed)
| pure rename (sealed factory `assemble(...)`), plus it now hosts the moved `diagnosisBlock` renderer.
  Update the 1 host reference (`ResourceCreationPipeline`) and the doctor-core-test references.

| `SystemdAdapterProbe` / `ClusterReadinessProbe` (host interfaces, modified)
| `probe(...)` returns a checkpoint `Document` instead of `Observation`. The live + simulated impls
  build the Document from host-native facts (status, detail string, the failure kind as a string),
  never `Observation.failed(Symptom)`.

| `SystemdAdapterStage` / `ClusterReadinessStage` (host, modified)
| `consultDoctor` calls `consult(checkpoint)`, logs `narration`. The checkpoint feeds both `assess`
  (2A) and `consult` (2B). Drop the `doctor.records` imports.

| `SeedSystemdAdapterEndpointGate` (host, modified)
| stop producing `Observation`/`Symptom`; emit the checkpoint fields (status + detail) as host-native
  values folded into the Document.

| `RunbookRenderer` (host, modified)
| `injectDiagnosis` reads `consultation.diagnosisAdoc()` (a string) and calls
  `setExtendedDescription` — drop the `RemediationPlan`/`ReferralReply`/`ConsultationReport` imports;
  keep the jGiven `ReportModel`/`ScenarioModel` shell host-pure. The `checkpointId`→scenario join
  stays (jGiven identity, not doctor).

| the jGiven consult scenarios (`SystemdAdapterScenario`, `ClusterReadinessScenario`, host, modified)
| stop asserting on `Observation`/`Symptom`; assert on the checkpoint/consultation Document fields.
|===

== What "green" means per zone

Per the design's graduated-green rule (build-green + a shrinking gate worklist; `pulumi preview`
boots green only at the LAST increment):

* *zone-0* compiles and the doctor in-container tests pass, but the host worklist does NOT shrink yet
  — the host still calls the old verbs until zone-1/2. zone-0 is green at the build + OSGi-test level,
  not the worklist level. (This is expected, not a regression: zone-0 migrates the seam + the OSGi
  authority, which the host worklist does not measure.)
* *zone-1* and *zone-2* each shrink the worklist visibly as their host classes drop `doctor.records`.
* `pulumi preview` is unaffected by 2B at the boot level (2A already closed the boot parse); the green
  preview still arrives only when the whole worklist reaches zero (2D).

== Scope boundary — where 2B stops

2B migrates the consult/failure path ONLY. It does NOT touch:

* the *reconstruction* path — `DriftReview`, the `*Reader` classes, `MedicalRecordRegistry`,
  `InterventionLedger*`, and the `recordForCurrentPatient`/`reviewOpenProblems` seam verbs they use.
  That is zone-3 / increment 2C.
* the *Pulumi-resource egress* — `SystemdAdapterResource`, `ClusterReadinessResource`,
  `ResourceCreationPipeline` (the `toOutputMap` family). That is the egress increment.
* the JSON Schemas + the `REALM_BOUNDARY` → ERROR flip — increment 2D, when the worklist is zero.

During 2B the `ConsultingService` seam transitionally carries BOTH the new `consult(Document)` and the
two reconstruction verbs (still record-typed) — expected; the gate worklist tracks the residue.
