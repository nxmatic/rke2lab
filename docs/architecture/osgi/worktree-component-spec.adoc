= Worktree component spec (the worktree as an OSGi domain)
:toc: macro
:toclevels: 3

Status: the domain *as built* is ✅ Complete (committed `eb50886f` + `079ce552`); the realm
refinement in <<refinement>> is 📋 Planned (the Q1+Q2 session's target — see the handoff).

This spec discharges the `SPEC_COVERAGE` obligation of the worktree contract packages by naming every
exported type: `Worktree`, `WorktreeFacts`, `WorktreeCoordinate`, `Provenance`, `WorkingState`.

toc::[]

== Overview — the worktree KNOWS its own git facts

The seed process runs *inside* the git worktree it cultivates. Worktree access used to be a static
helper (`Worktree.locatedFrom/at/openRepository`) that leaked a jgit `Repository` to its callers —
and jgit had begun to *spread*: a `GitProvenanceReader` in incus-core, the entry gate, and a
flake-lock policy each reached for git directly, duplicating the same walk for zero benefit. It is
now a proper OSGi domain that mirrors `incus` exactly: one `@Component` that self-locates its root
(walking up to `.git`) and answers the facts that root carries — *jgit sealed behind it, never
exposed*, so a consumer couples to the worktree's facts, not to a git library. It is *the one place*
the "is the worktree clean?" and "what did we provision from?" knowledge lives.

The domain has four modules:

[cols="1,3",options="header"]
|===
| Module | Role

| `worktree-contract` (`type=contract`, pkg `io.nxmatic.rke2lab.worktree`)
| The jgit-free `Worktree` service interface. OSGi consumers `@Reference` it (the incus scion).

| `worktree-contract-host` (`type=library`, dual-realm, pkg `io.nxmatic.rke2lab.worktree.host`)
| The cellar-harvested wire types: `WorktreeFacts`, `WorktreeCoordinate`, `Provenance`,
`WorkingState`. See <<refinement>> — this dual-realm face is slated to fold into `worktree-contract`.

| `worktree-core` (pkg `io.nxmatic.rke2lab.worktree.internal`)
| `JgitWorktree` `@Component` — self-locates the root at activation; jgit lives only here.

| `worktree-bdd`
| `WorktreeScenario` — the worktree SOIL, and `WorktreeRunbookHandler` (extends
`GenericRunbookHandler`).
|===

== The exported types

* **`Worktree`** (contract) — the service: `root()` (the absolute, normalised anchor every
  provisioning path derives from), `provenance()`, `workingState()`. jgit-free — only JDK types and
  the `worktree.host` records cross it.
* **`WorktreeFacts`** (`@SeedContract("worktree-facts")`) — the snapshot the soil harvests into the
  cellar: `root` (as a String path; the reader re-hydrates a `Path`), the HEAD `Provenance`, and the
  `WorkingState`. No jgit type and no service reference crosses the seam — only the serialized
  payload, decoded per realm into its own copy.
* **`WorktreeCoordinate`** — the cellar coordinate (`FACTS`, slug `worktree-facts`, domain
  `worktree`). A `SeedCoordinate` enum. The `Cellar` keys on the slug/domain *strings*, not object
  identity, so it works across the seam exactly as `IncusGrowCoordinate.INSTANCE_GROW_PLAN` does.
* **`Provenance`** — the HEAD provenance: the commit `sha` (the key; the rest is recoverable via
  `git show`) and whether it is `dirty` (the one bit the sha cannot carry). An empty sha is a
  legitimate first run.
* **`WorkingState`** — `clean` plus `uncommittedPaths` when it is not. *The worktree owns the fact;
  the gate owns the policy (which paths matter)* — a neutral facts record with no consumer-specific
  knowledge.

== The soil crossing — harvest, not push

`WorktreeScenario` (`@SeedScenario`, an OSGi bundle) is the worktree SOIL, played in-container by the
seeding engine like every other crossing, via a seam `RunbookCoordinate("worktree")` (broker routing
needs a shared value-coordinate). Its whole job: read the `Worktree` `@Component` (injected by the
`@OsgiService` bridge) and *harvest* a `WorktreeFacts` into the cellar at `WorktreeCoordinate.FACTS`
(WHEN fabricates, THEN seals). It is *not* survey-inert — reading git facts is a pure deterministic
read (no live system contacted), so the harvest runs in preview too, exactly as the incus grow plan
is projected in both modes.

The consumers read the harvest *from the cellar* (fetch-not-push), the same discipline the incus
`InstanceGrowPlan` rides — a domain-owned coordinate keyed by its wire slug crosses the realm through
the cellar, without the broker ever routing a domain enum.

== Realm model — as built

Today `worktree-contract-host` is a dual-realm `type=library` (the twin of `incus-contract-host`), so
the *flat host* can decode `WorktreeFacts` into its own copy. Two host-side consumers drive that:

== Realm refinement (📋 Planned — the Q1+Q2 target)

=== The principle it rests on

*A domain needs a dual-realm `-host` library iff the host ACTUALISES its harvest.* `incus` is
host-actualised (the host runs `pulumi up` to create the instance), so `incus-contract-host` is
legitimately dual-realm. The worktree is *not* actualised by the host — the worktree already exists;
the domain only reads facts off it. So once nothing host-side consumes those facts, the worktree
contract is OSGi-only, and `worktree-contract-host` folds into `worktree-contract`.

=== What removes the two host consumers

Two changes (owned by the Q1+Q2 session, code delegated) remove both host-side reads above, and with
them the reason for the dual-realm face:

. **The grow plan becomes self-contained (Q1).** The `InstanceGrowPlan`
  (`incus-contract-host`) carries neither the worktree root nor the mount specs; the host GROW does a
  *separate* `WorktreeCoordinate.FACTS` fetch for `root()` and computes the 17 mounts host-side. The
  target: the incus scion (which already `@Reference`s `Worktree`) projects the worktree root — or,
  fuller, the resolved mounts — *into* the plan, so the host GROW actualises the plan alone. Removes
  the GROW's worktree fetch.
. **The entry gate moves OSGi-side (Q2).** `EntryGatePolicyEnforcer` is host-flat and hardcodes a
  manifests-path predicate (`isEmbeddedManifestResourcePath`). `WorkingState` is already neutral, so
  the only coupling is that literal. The target: `enforceAll(WorkingState, cleanRequired,
  toleratedPaths)` — the tolerated-path policy *injected* — so the gate becomes a domain-neutral
  scenario step OSGi-side that reads `WorkingState` from the cellar and applies a caller-supplied
  policy. Removes the gate's worktree fetch.

=== The consequence

With both gone, `WorktreeFacts`/`WorktreeCoordinate`/`WorkingState`/`Provenance` are consumed *only*
OSGi-side → `worktree-contract-host` dissolves into an OSGi-only `worktree-contract`. The worktree
root still reaches the host, but *inside the incus `InstanceGrowPlan`* (an incus dual-realm type),
never as a worktree type. The `SPEC_COVERAGE` obligation on these exports travels with them into
`worktree-contract` (the default `ERROR`, covered by this spec).

[NOTE]
====
`SPEC_COVERAGE` on `worktree.host` is held at `WARN` until this dissolution lands: this spec pays the
documentation debt, but the `WARN`→default-`ERROR` relock is a one-line follow-up the Q1+Q2 session
applies on the *final* (OSGi-only) package, rather than churning a package about to move.
====

== Open questions (from the working session)

* **Naming `worktree` vs `row`** — resolved: keep `worktree` (concrete, truthful). `ROW`/planche is
  the gardening *role* (the SOIL), which applies at the role level without renaming the domain;
  introduce `row` as an abstraction only if a second soil appears (YAGNI today).
* **Entry-gate placement** — resolved: OSGi-side with an *injected* path policy (see <<refinement>>);
  keeping the manifests literal out of the worktree domain was the real constraint, and injection
  satisfies it.
* **flake-lock gate** — *not dead, disabled-by-debt* — resolved: resurrect it. The old
  `enforceFlakeLockCoherence` short-circuited with `if (true) return` under the comment "temporarily
  disable until we have a better story", but its intent is a real, *distinct* check: over the latest
  commit (a `HEAD~1` tree-diff) it fails when `flake.nix` inputs changed without a matching
  `flake.lock` change — a coherence a clean worktree does NOT catch (a clean tree can still commit an
  incoherent lock). The "better story" now exists, so resurrect it in the Q1+Q2 session, in three
  clean parts: the *check* as a worktree-domain capability (the jgit `HEAD~1` diff, sealed behind the
  component); the *enforcement* as the OSGi gate step; the *enable/disable* as a stack-config toggle
  (like `bbox.failOnError`) — replacing the hardcoded short-circuit. NOT a revival of the old host
  code.
