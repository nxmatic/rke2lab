== Why this atlas exists

The atlas's *function* — prove the specification models hold together via a monotone-before/after
additivity test, reopened at every design activity — is **cross-subsystem, not subsystem-specific**.
This placement (`docs/architecture/integration-atlas.adoc`) reflects that transverse structure. The
content today is **doctor-only** (the first per-subsystem view below); honest caveat: transverse in
structure, doctor-only in content until a second subsystem adopts the ritual.

Each new model risks silently contradicting or duplicating the others. This atlas is the antidote: a
single view that lists every model, draws how they connect, and — when a model is added — *proves it
is additive* by a simple visual test.

*The test of "additive" is MONOTONE before/after.* Draw the model constellation without the new
model (before), then with it (after). Additive means: *no box erased, no arrow rewired, only
additions.* If "after" cannot be drawn without rubbing out a line of "before", the model is not
additive — and the figure says so out loud. This operationalizes the project principle that *a
well-integrated spec is itself the proof we are on the right path.*

Legend used throughout: thin/blue = IMPLEMENTED (built); thick/green = the model under design;
dashed/amber = EXPLORATION (not built, future); grey = cross-cutting foundation.

== The two spaces — OSGi and host

Every model on this atlas sits in one of two spaces, and the line between them is the application's
deepest seam. This framing is the *purity axis* made structural: it is the backdrop each per-subsystem
view is read against.

* *OSGi space* — pure models that *describe*: the resolution oracle (`UnitResolver`), the
  manifests universe, the doctor record model, the config records. No `com.pulumi`, no `io.grpc`.
* *Host space* — code that *actualises* the description over the Pulumi engine: orchestration, the
  ledger write-side, `ConfigLoader`. This is where the engine imports live.

The only edge that legitimately crosses is the *bundle/host contract*: a bundle declares a need
(`Require osgi.extender`), the host satisfies it (`Provide` + the `SectionReader` SPI for values). A
pure model reaching directly into host code — as `Rke2labConfig → ConfigLoader` does today — is a
crossing in the WRONG direction, a decomposition defect to invert.

[NOTE]
.Terminology — `system`, `space`, `world`, `universe`, and where `exec/` fits
====
These words are used precisely throughout the atlas and specs; this is the glossary.

* *system* — THE WHOLE: the two spaces (OSGi + host) joined into one thing that runs. The spaces are
  *parts of the system*; the system is not a third space.
* *space* — a top-level LAYOUT directory, sorted by the purity + nature axes: `osgi/` (pure, describes),
  `host/` (actualises over Pulumi), `exec/` (the *nature* axis — executables). "Two spaces" names the
  PURITY seam (osgi↔host); `exec/` is the orthogonal nature axis, not a third purity space — so the
  two-spaces frame above stays exactly right.
* *world* — a RUNTIME classloader region: the OSGi world (bundle classloaders, no gRPC) vs the HOST
  world (one flat classloader, holds gRPC). Same osgi/host line as the spaces, seen at runtime.
* *`exec/` MATERIALISES the system* — an `exec/` module (`seed-master`) embeds both worlds into one
  launchable artifact: the OSGi bundles (describe) + the host adapters (actualise), composed into a
  self-contained jar that boots Felix inside `Pulumi.run` (the R4 view below). That is the role the
  terminology was missing: osgi *describes*, host *actualises*, `exec/` *materialises*.
* *universe* — RESERVED for the resolver sense (`UnitResolver`'s candidate set, `ManifestsUniverse`); it
  is NOT a synonym for "system". Kept distinct on purpose.
====

collaborator (`Prescription.humanHint` shrink) is honest and isolated.

=== The ritual — how this atlas stays alive

Reopen this atlas at the START of every design activity (doctor or another subsystem), before
writing a new model's spec:

. *Add the new model* as a green box in a fresh before/after pair (or extend Diagrams A–C).
. *Prove monotone:* confirm no existing box or arrow is erased or rewired. If you must erase one,
  STOP — the new model is not additive; rework the seam until it is, or record explicitly why a
  breaking change is justified.
. *List honest edits:* any changed collaborator (not just additions) is named in the verdict, as
  the two edits above are.
. *Flip green→blue* when a model ships, and update its inventory status.
. *Update the inventory table* with the new model and its links.

This keeps "a well-integrated spec is the proof we are on the right path" a standing practice, not a
one-time exercise.

=== Verdict — does it hold?

An honest reading:

. *Monotone: yes.* No built box erased or rewired from BEFORE to AFTER. The three boxes
  (`InfraDomain` loop, `InfraConfigRegistry`, `Rke2labConfig`) are unchanged because the bench is
  separate scaffolding — it proved the contract without touching production. The three green
  additions (the Require/Provide extender pair + the Metatype OCD) are NEW, not rewrites.

. *Honest scope:* only the *schema/resolution* half is proven here. The `Require osgi.extender` +
  `Provide osgi.extender` contract is resolved by the REAL Felix framework (P1:
  `ExtenderContractSpikeTest`), and the Metatype `ObjectClassDefinition` is introspectable by PID
  (P2: `MetatypeIntrospectionSpikeTest`). The *value* channel (`SectionReader`, inverting
  `Rke2labConfig → ConfigLoader`) is stage 3, and Config Admin delivery / DS activation are stages
  3–4, deferred.

. *The proof is on the REAL engine, not asserted.* Both tests run on the real embedded Felix
  framework (via `FelixFrameworkExtension`, a JUnit5 extension), installing real bundles built by
  `bnd-maven-plugin`. P1 proved the framework refuses to resolve when the host is absent
  (`BundleException`). P2 proved typed access (no reflection) by having the framework export
  `org.osgi.service.metatype` from the system bundle (`system.packages.extra`) so the test and
  felix.metatype share one API copy.

. *Metatype is a NEW box.* The atlas previously defined the crossing contract as `Require
  osgi.extender` + `SectionReader` (value channel); Metatype (schema) is the new addition this slice
  introduced. Its additivity is proven above: it connects to the existing `InfraConfigRegistry` by
  describing its shape, but does not rewrite any existing box.

Conclusion: the config constellation holds, and the extender + Metatype additions are monotone. The
bench is disposable scaffolding that graduates these principles to the durable atlas.

its `Pulumi.run` callback and consumes the pure-model services from the registry. The migration spec is
`wip/specs/2026-06-18-osgi-runtime-migration-design.adoc` (slices R1–R7); this view is the GRADUATION of
that spec's §7 atlas (Diagrams G/H) into the durable atlas, as the spec itself directed — plus the two
decisions taken AFTER the spec was frozen (named below so the two documents do not silently diverge):
the *API-extraction* prerequisite (the osgi/ ports) and the *proof reframe* (R4 by `pulumi preview`, not
`-Plive`).

=== The refinement this view makes to the two-spaces frame

The top-of-atlas frame draws ONE generic edge: the *bundle/host contract* (`Require osgi.extender` +
`SectionReader`). The runtime work refines that single edge into a typed model — *named honestly here
because the ritual requires every changed collaborator to be called out, not silently redrawn:*

* The crossing is now a RUNTIME *service registry*, not only a build-time *resolution*. Once Felix is
  launched (R4), SCR publishes `@Component` services and consumers bind by `@Reference` (in-bundle) or
  `getServiceReference` (at the host seam).
* The typed boundary splits by NATURE — the name follows the relation the module holds with whoever
  depends on it (the `-port`/`-spi`/`-api` taxonomy). Note this is NOT the *bundle/host contract* of the
  config view (`Require osgi.extender`, a capability seam) — that keeps the word "contract"; what used to
  be loosely called "the contract" as a typed model crossing the frontier is now the *port*:
  ** *port* — a boundary the HOST calls and an OSGi bundle implements. It is a PURE model (interfaces +
     records, zero engine imports), so by the purity axis its nature is osgi/ and it lives in
     `osgi/<domain>/<domain>-port` (e.g. `manifests-port`, `netplan-port`, `systemd-port`). The name is
     reduced to bare `-port`, not `osgi-port`, because the osgi/ belonging is already carried by the
     space. In hexagonal terms the port belongs to the DOMAIN, not the adapter — BOTH the host (adapter)
     and the impl bundle depend on it (DIP), neither world depends on the other's impl. It is a versioned
     bundle at BUILD time but is NOT installed into Felix: at runtime it is system-exported FLAT via
     `system.packages.extra` and host-loaded (osgi port ← system-exported ← host-loaded), so host and
     bundle share one copy of the interface — the same typed-access trick the config view's P2 proved for
     Metatype. (A port is BOTH api and spi at once — the host calls it, the impl implements it — so it is
     named by concern, never `.api`/`.spi`.)
  ** *intra-OSGi spi* — a boundary resolved ONLY inside the OSGi world (e.g. `unitrepo-handler-spi`, an
     extender SPI) → stays an spi bundle in the OSGi world, never crosses the host↔osgi frontier.

This does not erase the old contract box — it types it. The `Require/Provide osgi.extender` resolution
(config view) and the service registry (this view) are the two halves of the same seam.

=== Verdict — does it hold?

. *Monotone through R4: mostly — with one honest exception.* The SPI impls are unchanged and the
  `@Component` annotations decorate the SAME impl classes (R2) without rewriting them; R1–R4 + the ports
  are GREEN additions. The exception: once R4 booted Felix, the HOST seam's `ServiceLoader` path was CUT
  to a single registry path (`awaitService`, fail-fast) — not kept beside it. That was deliberate
  (`pulumi preview` proved the deployed exec-jar always embeds the bundles, so the flat half was dead,
  not deferred — the no-fallback discipline). So `ServiceLoader` survives ONLY in the two un-migrated
  CLIs (and the 8 orphaned `META-INF/services` they still need); R5 deletes that last remnant. The
  registry and the static path no longer "both live at once" in seed-master — only in the CLIs.

. *The ONE deliberate erasure is R5, and it is named.* R5 deletes `ServiceLoader`/`META-INF/services` —
  the single non-additive step in the whole migration. It is drawn amber (exploration), gated behind
  R4, and called out here precisely because the ritual forbids erasing a box silently. Until R5 the
  surface is strictly additive; R5 is the conscious, justified breaking change (uniformity: one
  consumption mechanism, not registry + static cousin).

. *The ports are NEW osgi/ boxes, not a rewrite.* They lift the boundary models OUT of the OSGi impl
  modules into `osgi/<domain>/<domain>-port`; the impls then depend on them (DIP), and the host compiles
  + host-loads them (system-exported). The host's current direct imports of impl classes
  (`NodeEnvContributorRegistry`, `ManifestYaml`, `FloxRuntimeAssets`) are wrong-direction crossings the
  atlas already flags — inverted at R4, not lifted into the port.

. *Honest scope.* R1–R3 are proven on embedded Felix (surefire, no `-Plive`). R4's proof is a real
  `pulumi preview` (a dry-run that boots Felix without mutating master) — the `-Plive up` is an optional
  final confirmation, the user's gesture. gRPC stays on the flat host classloader throughout (issue
  #1565); no gRPC type crosses into a bundle.

. *Two evolutions of the spec's §7, named (not silent redraws).* The frozen spec §7 (Diagrams G/H) did
  not yet carry (a) the API-extraction prerequisite — the ports were decided 2026-06-19, so this
  view ADDS the `osgi/<domain>-port` boxes that G/H lacked; and (b) the proof reframe — §7 gated R4/R5 on
  `-Plive`, but `pulumi preview` (a dry-run) boots Felix for real without mutating master, so R4's proof
  is in-scope and the `-Plive up` is an optional final confirmation. Both are refinements the graduating
  view records on top of G/H, leaving G/H intact as the design-time origin.

Conclusion: the runtime migration is additive through R4, with R5 the one named, deferred erasure. The
static `ServiceLoader` surface and the live registry coexist until every caller boots under Felix.

== Unit repository — per-subsystem view

The fourth subsystem to adopt the ritual. The unit-repository vision — an OSGi-resolution plus
peer-to-peer provisioning and history layer — was developed in the standalone `docrepo-dag-wip` repo
while rke2lab was not yet ready to host it. The runtime view's framework now boots in production, so
the vision is folded in here. It does not sit beside the others: it is the GENERALIZATION of which the
doctor's medical-record substrate is one instance (a ledger-backed specialist's stack is a unit-DAG).
The full design is link:unit-repository/model-overview.adoc[the unit-repository model overview]; this
view holds the inventory, the additivity proof, and the capability map.

=== Glossary remediation (the reserved words — see the "two spaces" note)

Folding the unitrepo docs in reconciles their vocabulary with the atlas's reserved words:

* *World-A* (the unitrepo durability regime, pull=own) collides with `world` = the runtime classloader
  region. Renamed *the pull-own regime*.
* *node* — the unitrepo peer-node is disambiguated from rke2lab's cluster/env node (`NodeEnvContributor`):
  say *unit-node* vs *cluster-node* where both are in scope.
* *name-space* (schema-name space, class space) — kept hyphenated, never bare `space` (which is a layout
  dir).
* *universe* is a happy coincidence: the unitrepo `RepositoryView` candidate-set IS the reserved sense,
  embodied by `ManifestsUniverse`.
* *Unit* and *Visit* were chosen to align with rke2lab's `ManifestsUnit` / `Visit` — safe anchors.
* module layout adopts the `-port` / `-core` / `-spi` taxonomy; `unitrepo-pulumi` is the host-world ACL.
