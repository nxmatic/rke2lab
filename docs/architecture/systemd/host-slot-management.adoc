== Overview

The host asset directory structure uses a **slot rotation** mechanism to maintain deployment history, enable rollback, and preserve audit trails. Each deployment creates a numbered slot, and the active `host/` directory is synced from the most recent slot.

**Key benefits:**

* **History preservation** - Each slot preserves its own manifest showing what was deployed
* **Rollback capability** - Previous slots can be restored if needed
* **Audit trail** - Git metadata, policy flags, and discovered resources tracked per slot
* **No-op detection** - Identical deployments don't rotate slots (saves disk space)

[source,text]
----
.local.d/bioskop/master/

├── cloud.d/                         # Cloud-init NoCloud datasource
│   ├── meta-data
│   ├── network-config
│   └── user-data
├── host/                            # Active host assets (synced from latest slot)
│   ├── .rke2lab-manifest.yaml       # Current deployment manifest
│   ├── manifests.d/                 # Synthesized manifests
│   ├── systemd.d/                   # Systemd units/scripts
│   └── k8s-daemonset.d/             # DaemonSet scripts
├── host.0.staging.d                   # Slot 0 (staging before activation)
│   └── .rke2lab-manifest.yaml       # Slot 0 manifest
├── host.1.staging.d                   # Slot 1
│   └── .rke2lab-manifest.yaml       # Slot 1 manifest
├── host.2.staging.d                   # Most recent slot
│   └── .rke2lab-manifest.yaml       # Slot 2 manifest
├── host.backup.0                    # Backup of host/ before slot 0 sync
├── host.backup.1                    # Backup of host/ before slot 1 sync
└── host.backup.2                    # Backup of host/ before slot 2 sync
----

=== Slot Types

* **`host/`** - Active directory, bind-mounted to master instance as `/srv/host`
* **`host.N.staging.d`** - Numbered slots (0-2), each preserving a deployment's content and manifest
* **`host.backup.N`** - Paired backups of what `host/` contained before slot N was synced
* **`MANIFEST.yaml`** - Non-hidden symlink to `host/.rke2lab-manifest.yaml` for operator visibility

=== Stage Breakdown

1. **Materialize to scratch** - Seed-master builds host assets into a temporary `host.preview` directory
2. **Identity check** - If scratch is byte-for-byte identical to `host/`, discard scratch (no-op)
3. **Allocate slot** - Pick next slot number (0-2 round-robin), evict oldest if retention full
4. **Promote to slot** - Move scratch → `host.N.staging.d`
5. **Write manifest** - Generate `.rke2lab-manifest.yaml` in the slot (git info, policy, resources)
6. **Backup active** - If `host/` exists, copy it to `host.backup.N` (paired with slot N)
7. **Sync to active** - Copy slot content to `host/` (preserves mount point inode)
8. **Symlink manifest** - Create `MANIFEST.yaml` → `host/.rke2lab-manifest.yaml` at master level

== Slot Manifest Structure

Each slot contains a `.rke2lab-manifest.yaml` (Kubernetes ConfigMap format) describing what was deployed:

[source,yaml]
----
apiVersion: v1
kind: ConfigMap
metadata:
  name: rke2lab-host-slot-manifest
  namespace: rke2lab-system
  labels:
    rke2lab.io/slot-type: staging
    rke2lab.io/build-id: 20260531-070129-ff5b3d16
data:
  manifest.yaml: |
    slotType: staging
    slotSequence: 2
    timestamp: 2026-05-31T07:01:29.189457Z
    buildId: 20260531-070129-ff5b3d16
    git:
      commit: ff5b3d16
      commitFull: ff5b3d16639bff706f5ca25885a91cb6602e5503
      branch: main
      dirty: false
      commitMessage: "fix(manifests): use RKE2 auto-deploy for image-state ConfigMap"
      author: nxmatic
      commitDate: 2026-05-31T06:28:31Z
    policy:
      manifestDomain:
        cluster: true
        storage: true
        clusterApi: false
      debug:
        mesh: true
        networking: true
    floxEnvironments:
      - category: networking
        name: kdns
        hasManifest: true
    stagedManifests:
      - domain: clusterapi
        subpath: staged
        description: Image-state ConfigMap for Cluster API
    source:
      type: fresh-build
      scratchPath: /path/to/.local.d/bioskop/master/host.2.staging.d
----

=== Manifest Sections

* **Metadata** - slotType, slotSequence, timestamp, buildId
* **Git** - Commit hash, branch, dirty state, author, message, date
* **Policy** - Which manifest domains are enabled, debug flags
* **Flox environments** - Discovered flox environments with manifests
* **Staged manifests** - Post-cluster resources (synthesized during Output.applyValue)
* **Source** - Provenance (fresh-build, restored-from-backup, rolled-back)

== Operator Workflows

=== Check Current Deployment

[source,bash]
----
# Read manifest at master level (symlink)
cat .local.d/bioskop/master/MANIFEST.yaml

# Or directly from host/
cat .local.d/bioskop/master/host/.rke2lab-manifest.yaml
----

=== Compare Slot History

[source,bash]
----
# List all slots with timestamps
ls -ltr .local.d/bioskop/master/host.staging.*

# Compare manifests across slots
for slot in .local.d/bioskop/master/host.staging.*; do
  echo "=== $slot ==="
  grep "commit:" $slot/.rke2lab-manifest.yaml
  grep "timestamp:" $slot/.rke2lab-manifest.yaml
done
----

=== Find Staged Resources

[source,bash]
----
# Extract stagedManifests from MANIFEST.yaml
yq '.data."manifest.yaml" | from_yaml | .stagedManifests' \
  .local.d/bioskop/master/MANIFEST.yaml
----

Output:
[source,yaml]
----
- domain: clusterapi
  subpath: staged
  description: Image-state ConfigMap for Cluster API
----

Then navigate to: `host/manifests.d/clusterapi/staged/`

=== Rollback to Previous Slot

[source,bash]
----
# Identify target slot
cat .local.d/bioskop/master/host.1.staging.d/.rke2lab-manifest.yaml

# Sync slot to active (manual recovery)
rsync -a --delete \
  .local.d/bioskop/master/host.1.staging.d/ \
  .local.d/bioskop/master/host/

# Update symlink to reflect rollback
ln -sf host/.rke2lab-manifest.yaml .local.d/bioskop/master/MANIFEST.yaml
----

== Implementation Details

=== No-Op Detection

When scratch content is byte-for-byte identical to `host/`, the deployment is a **no-op**:

* Scratch directory is deleted (not promoted to slot)
* No slot rotation occurs
* No backup is created
* Saves disk space for repeated `pulumi up` with no changes

[source,java]
----
if (Files.exists(hostAssetRoot) && directoriesAreIdentical(stagingRoot, hostAssetRoot)) {
  deleteRecursively(stagingRoot);
  return false; // No rotation
}
----

=== Slot Retention

* **Maximum slots**: 3 (configurable via slot allocation logic)
* **Eviction**: Oldest slot by mtime is deleted when retention is full
* **Pairing**: Each slot N has a paired backup `host.backup.N`

[source,java]
----
private int allocateSlot(Path hostAssetRoot) throws IOException {
  final int MAX_SLOTS = 3;
  // Round-robin through 0, 1, 2, evicting oldest when full
}
----

=== Inode Preservation

The `host/` directory is bind-mounted to master instance as `/srv/host`. To avoid remount, the sync preserves the directory inode:

* **Sync content** - `rsync -a --delete host.N.staging.d/ host/`
* **NOT move** - ~~`mv host.N.staging.d host/`~~ (would break mount)

=== Symlink Relative Path

The master-level symlink uses a **relative path** so it works regardless of absolute location:

[source,java]
----
final Path relativeTarget = masterManifest.getParent().relativize(hostManifest);
Files.createSymbolicLink(masterManifest, relativeTarget);
// Result: MANIFEST.yaml -> host/.rke2lab-manifest.yaml
----

== Troubleshooting

=== Symptom: MANIFEST.yaml missing or broken

**Check:**
[source,bash]
----
ls -la .local.d/bioskop/master/MANIFEST.yaml
----

**Expected:**
[source,text]
----
MANIFEST.yaml -> host/.rke2lab-manifest.yaml
----

**Fix:** Recreate symlink manually:
[source,bash]
----
cd .local.d/bioskop/master
ln -sf host/.rke2lab-manifest.yaml MANIFEST.yaml
----

=== Symptom: Slot manifest is stale

**Cause:** No-op deploy detected, slot wasn't rotated

**Check:**
[source,bash]
----
# Compare scratch to active (manually simulate no-op check)
diff -r .local.d/bioskop/master/host.preview \
        .local.d/bioskop/master/host
----

If identical, deployment was a no-op and slot wasn't updated.

=== Symptom: Lost slot history

**Recovery:** Slot backups are paired - restore from `host.backup.N` if needed:

[source,bash]
----
# Restore backup to host/
cp -a .local.d/bioskop/master/host.backup.1 \
      .local.d/bioskop/master/host.1.staging.d.restored
----

== Design Decisions

=== Why slots instead of git history?

* **Speed** - No git operations during deployment (faster than commit/checkout)
* **Flexibility** - Can store non-git artifacts (discovered flox envs, image fingerprints)
* **Operator-friendly** - Standard filesystem navigation, no git knowledge required
* **Provenance** - Manifest captures what was deployed, not just source state

=== Why hidden manifest in host/ but visible symlink at master level?

* **Hidden in host/** - Doesn't clutter bind-mounted `/srv/host` on master instance
* **Visible at master level** - Operators navigating `.local.d/` see it immediately
* **History in slots** - Each slot preserves its own manifest for comparison
* **Single source of truth** - Symlink always points to active `host/` manifest

=== Why paired backups?

* **Recovery** - If slot rotation corrupts `host/`, backup N can restore pre-slot-N state
* **Debugging** - Compare "before" (backup) vs "after" (slot) to isolate changes
* **Pairing** - Backup N corresponds to slot N, making relationships explicit
