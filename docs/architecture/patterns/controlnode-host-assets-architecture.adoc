= Control Node Host Assets Architecture

== Status: DISSOLVED

[NOTE]
====
This was a *design* note for a single contract-driven model of control-node host
assets — a "runtime filesystem contract" of logical aliases (`env`, `scripts`,
`systemd`, `rke2Config`, `cloudNoCloud`, …) mapping to `/srv/host/*` destinations,
a layer contribution API, a script-interface layer, and a materialisation
pipeline that rendered those assets onto the node.

The whole premise — that the control node consumes host assets delivered under
`/srv/host/*` (mounted by `controlplane`, materialised from manifest synthesis) —
is gone. The node moved to a declarative NixOS substrate: its config, systemd
units, scripts, identity, PKI and toolbox are baked by the `nixos/` modules, so
there is no `/srv/host` asset root to own, alias, or materialise. See
link:../nixos-substrate/substrate-model.adoc[the NixOS node-substrate model].

What survives on the manifests side is only the Kubernetes payload: the runtime
domain units (contributed by `RuntimeDomainRegistrar`) synthesise k8s manifests
delivered to the node's `server/manifests` tree — no `/srv/host` scattering, no
runtime path aliases. The one host-mutating workflow that legitimately begins in
a pod and completes on the node (the flox runtime install) is the *daemonset*
delivery, documented separately in
link:daemonset-host-assets-architecture.adoc[Daemonset Host Assets].
====
