= Manifests Architecture: CDK8s Extension and Systemd Integration
:toc: left
:toclevels: 3

== Overview

The manifests module extends CDK8s (Cloud Development Kit for Kubernetes) to synthesize **both** Kubernetes manifests and systemd units in a unified workflow. This document explains:

1. How we extend CDK8s's Construct pattern
2. How systemd units integrate with K8s manifest synthesis
3. The relationship between ManifestsUnits, LayerDomains, and systemd services

== Core Concepts

=== ManifestsUnit (Plural)

A `ManifestsUnit` is a CDK8s `Construct` that synthesizes **multiple** K8s manifests and their corresponding systemd installation service.

**Why plural?** One unit generates multiple K8s resources:

[source,java]
----
// Example: CiliumConfigManifestsUnit creates 2 K8s resources
new ApiObject(this, "helmchartconfig-rke2-cilium", ...);  // 1
new ApiObject(this, "configmap-clustermesh-remote-users", ...);  // 2
----

**Dual responsibility:**

1. **K8s synthesis** (constructor): Creates `ApiObject` instances as children of `this`
2. **Systemd synthesis** (`synthesizeSystemdUnits()`): Creates a systemd service that **installs** those manifests

=== LayerDomain

A `LayerDomain` groups related `ManifestsUnits` that share a concern (networking, gitops, cluster-api, etc.).

- Contains 1+ `ManifestsUnit` instances
- Declares dependencies on other domains
- Optionally synthesizes domain-level systemd units (e.g., a single installer service for all units in the domain)

=== CDK8s Extension Strategy

We extend CDK8s by:

1. **Inheriting `Construct`**: `AbstractManifestsUnit extends Construct implements ManifestsUnit`
2. **Using CDK8s App/Chart**: K8s synthesis happens via standard CDK8s `App.synth()`
3. **Adding parallel systemd synthesis**: Custom `SystemdChart` construct for systemd units

**Result**: One synthesis call produces **two** output trees:

- `manifests.k8s.yaml` (via CDK8s)
- `systemd/*.service` files (via `SystemdChart`)

== How ManifestsUnits Extend Construct

=== Two Constructors Pattern

`AbstractManifestsUnit` has **two constructors** for backward compatibility during migration:

[source,java]
----
// Old constructor - for units not yet merged with Component
protected AbstractManifestsUnit(
    String manifestUnitId,
    List<String> dependsOnManifestsUnitIds) {
  super(null, manifestUnitId);  // null scope - created via apply()
  this.manifestUnitId = manifestUnitId;
  this.dependsOnManifestsUnitIds = List.copyOf(dependsOnManifestsUnitIds);
}

// New constructor - for merged ManifestsUnits
protected AbstractManifestsUnit(
    Construct scope,
    String id,
    String manifestUnitId,
    List<String> dependsOnManifestsUnitIds) {
  super(scope, id);  // Proper CDK8s parent-child relationship
  this.manifestUnitId = manifestUnitId;
  this.dependsOnManifestsUnitIds = List.copyOf(dependsOnManifestsUnitIds);
}
----

**New pattern (post-refactor):**

[source,java]
----
public final class CiliumConfigManifestsUnit extends AbstractManifestsUnit {

  public CiliumConfigManifestsUnit(Construct scope, String id) {
    super(scope, id, MANIFEST_UNIT_ID, List.of());

    // Create K8s resources directly - 'this' is the parent Construct
    new ApiObject(this, "helmchartconfig-rke2-cilium", ...);
    new ApiObject(this, "configmap-clustermesh-remote-users", ...);
  }
}
----

**Why this works:**

- `AbstractManifestsUnit extends Construct` → ManifestsUnit IS-A Construct
- Constructor receives `scope` (the parent Chart)
- `new ApiObject(this, ...)` → ManifestsUnit becomes parent of ApiObjects
- CDK8s traverses tree: `App → Chart → ManifestsUnit → ApiObject`

**Phase 2 - Systemd Synthesis:**

[source,java]
----
@Override
public void synthesizeSystemdUnits(
    SystemdChart systemdChart,
    SystemdSynthesisContext context) {

  var installService = systemdChart.findUnit("rke2lab-install");

  new SystemdService(systemdChart, "rke2lab-cilium-config-manifests")
      .description("Install RKE2Lab Cilium config manifests before server start")
      .after("local-fs.target", installService.getUnitFileName())
      .before("rke2-server.service")  // ← Special case: runs BEFORE server
      .type(ServiceType.ONESHOT)
      .execStart(
          "/srv/host/systemd-scripts.d/rke2lab-manifests-install.sh networking/cilium-config")
      .remainAfterExit(true)
      .wantedBy(context.rke2labTarget().getUnitFileName());
}
----

=== The Link: K8s Manifests → Systemd Installer

**The critical connection:**

1. ManifestsUnit constructor creates K8s resources → written to `manifests.k8s.yaml`
2. `synthesizeSystemdUnits()` creates a systemd service that **installs** those manifests
3. The installer script reads from `rke2-manifests.d/<domain>/<unit>/` directory
4. Manifests are materialized to that directory by `seed-master` bootstrap

**Flow:**

----
seed-master (bootstrap)
  └─> Synthesize manifests → manifests.k8s.yaml
      └─> Split into domain directories → rke2-manifests.d/networking/cilium-config/*.yaml
          └─> Materialize to container → /srv/host/rke2-manifests.d/
              └─> systemd service starts → rke2lab-cilium-config-manifests.service
                  └─> ExecStart= runs script → reads manifests from directory
                      └─> kubectl apply -f → Installs to cluster
----

== SystemdChart: Parallel Construct Tree

=== Design Rationale

**Why not use CDK8s Chart for systemd?**

CDK8s `Chart` synthesizes to **YAML**. Systemd uses **INI-style** unit files. We need a parallel construct tree that:

1. Reuses CDK8s's `Construct` pattern (tree structure, parent-child relationships)
2. Synthesizes to `.service`, `.target`, `.timer` files instead of YAML

**Solution: `SystemdChart`**

[source,java]
----
public class SystemdChart extends Construct {
  private final List<SystemdUnit> units = new ArrayList<>();

  // Children register themselves
  void registerUnit(SystemdUnit unit) {
    units.add(unit);
  }

  // Synthesize to INI files
  public void synthesize(Path outdir) throws IOException {
    for (SystemdUnit unit : units) {
      Path unitFile = outdir.resolve(unit.getUnitFileName());
      try (Writer writer = Files.newBufferedWriter(unitFile)) {
        unit.writeUnitFile(writer);
      }
    }
  }
}
----

=== SystemdUnit: CDK8s Construct for Systemd

[source,java]
----
public abstract class SystemdUnit extends Construct {

  protected SystemdUnit(Construct scope, String id, String unitFileName) {
    super(scope, id);  // CDK8s Construct constructor
    this.unitFileName = unitFileName;

    // Auto-register with parent SystemdChart
    if (scope instanceof SystemdChart chart) {
      chart.registerUnit(this);
    }
  }

  // Fluent API for systemd directives
  public SystemdUnit description(String desc) { ... }
  public SystemdUnit after(String... units) { ... }
  public SystemdUnit requires(String... units) { ... }

  // Synthesize to INI format
  abstract void writeUnitFile(Writer writer) throws IOException;
}
----

**Key insight**: `SystemdUnit extends Construct` → it's a CDK8s construct, just like `ApiObject`.

    .before("rke2-server.service")
    .type(ServiceType.ONESHOT)
    .execStart("/srv/host/systemd-scripts.d/rke2lab-manifests-install.sh networking/cilium-config")
    .remainAfterExit(true)
    .wantedBy("rke2lab.target");
----

**Fluent API** (builder pattern) makes systemd unit creation readable and type-safe.

=== Synthesis Flow Comparison

[cols="1,1,1",options="header"]
|===
| Aspect | K8s Chart | SystemdChart

| Base class | `org.cdk8s.Chart` | `SystemdChart extends Construct`
| Child type | `ApiObject` | `SystemdUnit` (Service, Target, Timer)
| Synthesis trigger | `App.synth()` | `systemdChart.synthesize(outdir)`
| Output format | YAML (K8s manifests) | INI (systemd unit files)
| Output location | `outdir/manifests.k8s.yaml` | `outdir/systemd/*.service`
| Registration | Automatic (CDK8s tree) | Manual (`chart.registerUnit()`)
|===

== ManifestSynthesisService: Orchestration

The `DefaultManifestSynthesisService` orchestrates both synthesis phases:

[source,java]
----
@Override
public ManifestSynthesisResult synthesize(ManifestSynthesisRequest request) {
  // 1. Create CDK8s App (root of construct tree)
  final App app = new App(AppProps.builder().outdir(synthOutdir.toString()).build());

  // 2. Create parallel charts
  final Chart chart = new Chart(app, "manifests");            // K8s
  final SystemdChart systemdChart = new SystemdChart(app, "systemd");  // systemd

  // 3. Build domain registry (groups ManifestsUnits by concern)
  final LayerDomainRegistry domainRegistry = buildDomainRegistry(policy);

  // 4. Phase 1: K8s synthesis
  //    Apply all ManifestsUnits → creates ApiObjects as children of chart
  for (ManifestsUnit unit : manifestUnits) {
    domainRegistry.applyManifestsUnitWithDomainDependencies(unit.manifestUnitId(), applier);
  }

  // 5. Phase 2: Systemd synthesis
  //    Create systemd targets first (referenced by services)
  final SystemdTarget rke2labTarget = new SystemdTarget(systemdChart, "rke2lab")
      .description("RKE2 Lab Bootstrap Target")
      .wantedBy("multi-user.target");

  final SystemdTarget manifestsTarget = new SystemdTarget(systemdChart, "rke2lab-manifests")
      .description("RKE2 Lab Manifest Installers")
      .after("rke2-server.service")
      .wantedBy("rke2-server.service");

  // Create synthesis context (shares targets with ManifestsUnits)
  final SystemdSynthesisContext systemdContext =
      new SystemdSynthesisContext(rke2labTarget, manifestsTarget, ...);

  // Synthesize systemd units for each domain
  for (LayerDomain domain : domainRegistry.domains()) {
    domain.synthesizeSystemdUnits(systemdChart, systemdContext);
  }

  // 6. Finalize and write files
  app.synth();  // → manifests.k8s.yaml
  systemdChart.synthesize(systemdOutdir);  // → systemd/*.service

  return new ManifestSynthesisResult(synthManifestFile, systemdOutdir, ...);
}
----

**Key orchestration steps:**

1. Create App (CDK8s root)
2. Create parallel Chart (K8s) and SystemdChart (systemd)
3. Build domain registry (groups ManifestsUnits)
4. **Phase 1**: Apply ManifestsUnits → K8s ApiObjects
5. **Phase 2**: Create systemd targets, then synthesize ManifestsUnit systemd services
6. Write both K8s and systemd files

== Patterns and Best Practices

=== When to Override synthesizeSystemdUnits()

**Override when:**

- The ManifestsUnit needs a systemd service to **install** its K8s manifests
- Special ordering required (BEFORE or AFTER rke2-server)
- Custom installation logic (not just `kubectl apply`)

**Don't override when:**

- The ManifestsUnit only creates K8s resources (no installation service needed)
- The domain handles systemd synthesis (domain-level installer service)

=== Special Ordering: Before vs After rke2-server

**BEFORE server** (`before("rke2-server.service")`):

- Cilium config (network CNI must be configured before K8s starts)
- RKE2 config (server configuration files)

**AFTER server** (`after("rke2-server.service")`):

- Most manifest installers (require K8s API to be available)
- GitOps (Flux needs K8s to bootstrap)
- Cluster API operators (need CRDs installed)

=== Dependency Resolution

**K8s dependency**: via `dependsOnManifestsUnitIds()`

[source,java]
----
public FluxInstanceManifestsUnit() {
  super(
      MANIFEST_UNIT_ID,
      List.of(FluxOperatorManifestsUnit.MANIFEST_UNIT_ID)  // ← depends on operator
  );
}
----

**Systemd dependency**: via `.after()` and `.requires()`

[source,java]
----
new SystemdService(systemdChart, "rke2lab-flux-instance-manifests")
    .after("rke2lab-flux-operator-manifests.service")  // ← systemd ordering
    .requires("rke2-server.service");
----

**Both are necessary:**

- K8s dependency ensures manifests are applied in order
- Systemd dependency ensures services start in order

== Anti-Patterns

=== ❌ Don't: Create ApiObjects outside ManifestsUnit constructor

[source,java]
----
// WRONG: ApiObjects created in helper method, not during construction
public void apply(Chart chart) {
  createResources(chart);  // ← Parent is 'chart', not 'this'
}

private void createResources(Construct parent) {
  new ApiObject(parent, "resource", ...);  // ← Wrong parent!
}
----

**Why wrong:** CDK8s tree doesn't include ManifestsUnit → loses construct hierarchy.

**Correct:**

[source,java]
----
public CiliumConfigManifestsUnit(Construct scope, String id) {
  super(scope, id, MANIFEST_UNIT_ID, List.of());

  // ApiObjects created during construction, parent is 'this'
  new ApiObject(this, "resource", ...);  // ← Correct parent
}
----

=== ❌ Don't: Create systemd units in constructor

[source,java]
----
// WRONG: Systemd synthesis in constructor
public CiliumConfigManifestsUnit(Construct scope, String id) {
  super(scope, id, MANIFEST_UNIT_ID, List.of());

  // ❌ SystemdChart doesn't exist yet during K8s synthesis!
  new SystemdService(???, "my-service");
}
----

**Why wrong:** SystemdChart is created separately; systemd synthesis happens AFTER K8s synthesis.

**Correct:**

[source,java]
----
@Override
public void synthesizeSystemdUnits(SystemdChart systemdChart, SystemdSynthesisContext context) {
  // ✅ Systemd synthesis in dedicated method
  new SystemdService(systemdChart, "my-service");
}
----

=== ❌ Don't: Hardcode systemd target names

[source,java]
----
// WRONG: Hardcoded target name
new SystemdService(systemdChart, "my-service")
    .wantedBy("rke2lab-manifests.target");  // ❌ Magic string
----

**Why wrong:** Target might be renamed; typo causes silent failure.

**Correct:**

[source,java]
----
// ✅ Use context accessor
new SystemdService(systemdChart, "my-service")
    .wantedBy(context.manifestsTarget().getUnitFileName());
----

== Migration from Old Pattern

=== Before: Component + ManifestUnit (2 files)

**Component.java:**

[source,java]
----
public final class CiliumConfigComponent extends Construct {
  public CiliumConfigComponent(Construct scope, String id) {
    super(scope, id);
    new ApiObject(this, "helmchartconfig", ...);
  }
}
----

**ManifestUnit.java:**

[source,java]
----
public final class CiliumConfigManifestUnit extends AbstractManifestsUnit {
  public CiliumConfigManifestUnit() {
    super(MANIFEST_UNIT_ID, List.of());
  }

  @Override
  public void apply(Chart chart) {
    new CiliumConfigComponent(chart, "layer-networking-cilium-config");  // ← delegation
  }
}
----

**Problems:**

- 2 files for 1 logical unit
- Delegation via `apply()` hides construct hierarchy
- Unclear who owns the ApiObjects (Component or ManifestUnit?)

=== After: Merged ManifestsUnit (1 file)

[source,java]
----
public final class CiliumConfigManifestsUnit extends AbstractManifestsUnit {

  public CiliumConfigManifestsUnit(Construct scope, String id) {
    super(scope, id, MANIFEST_UNIT_ID, List.of());

    // ApiObjects created directly, 'this' is the parent
    new ApiObject(this, "helmchartconfig", ...);
  }

  @Override
  public void synthesizeSystemdUnits(SystemdChart systemdChart, SystemdSynthesisContext context) {
    new SystemdService(systemdChart, "rke2lab-cilium-config-manifests")
        .execStart("...");
  }
}
----

**Benefits:**

- 1 file, 1 class
- Construct hierarchy clear: `ManifestsUnit → ApiObject`
- Both K8s and systemd synthesis in same class

== Troubleshooting

=== ApiObject parent is null

**Symptom:**

----
java.lang.NullPointerException: Cannot invoke "software.constructs.Construct.getNode()" because "scope" is null
----

**Cause:** ApiObject created with null parent.

**Fix:** Ensure ManifestsUnit uses new constructor:

[source,java]
----
public MyManifestsUnit(Construct scope, String id) {
  super(scope, id, MANIFEST_UNIT_ID, List.of());  // ← Pass scope, not null
  new ApiObject(this, "resource", ...);
}
----

=== Systemd service not created

**Symptom:** Expected `.service` file missing in `systemd/` directory.

**Cause:** `synthesizeSystemdUnits()` not called or not overridden.

**Fix:** Override method and create SystemdService:

[source,java]
----
@Override
public void synthesizeSystemdUnits(SystemdChart systemdChart, SystemdSynthesisContext context) {
  new SystemdService(systemdChart, "rke2lab-my-manifests")
      .execStart("...");
}
----

=== Systemd service ordering broken

**Symptom:** Service starts before dependencies ready.

**Cause:** Missing `.after()` or `.requires()` directives.

**Fix:** Use context accessors for targets:

[source,java]
----
new SystemdService(systemdChart, "rke2lab-my-manifests")
    .after(context.bootstrapTarget().getUnitFileName())  // ← Use context
    .requires("rke2-server.service")
    .wantedBy(context.manifestsTarget().getUnitFileName());
----

=== Manifests not installed to cluster

**Symptom:** K8s resources missing despite systemd service running successfully.

**Cause:** Manifests not materialized to expected directory.

**Fix:** Check:

1. Manifests exist in `rke2-manifests.d/<domain>/<unit>/`
2. ExecStart path matches materialized location
3. systemd service runs after `rke2lab-install.service` (which copies files)
