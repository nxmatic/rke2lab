= Systemd Dependency Structure Review and Improvements
:toc: left
:toclevels: 3

== Current Issue

Running `systemctl list-dependencies rke2lab.target` shows a flat structure rather than reflecting the hierarchical target organization:

[source,bash]
----
rke2lab.target
● ├─rke2-server.service
● ├─rke2lab-bootstrap-env.service
● ├─rke2lab-cilium-config-manifests.service
● ├─rke2lab-dbus-tcp-system-bus.service
● ├─rke2lab-install.service
● └─rke2lab-bootstrap.target
●   ├─rke2lab-bootstrap-env.service
●   ├─rke2lab-config-install.service
●   ├─rke2lab-containerd-zfs-mount-config.service
●   ├─rke2lab-install.service
●   └─rke2lab-systemd-link.service
----

Expected: services should be grouped under their logical targets (`rke2lab-bootstrap.target`, `rke2lab-manifests.target`, `rke2lab-secrets.target`, `rke2lab-network.target`, `rke2lab-tools.target`).

Additionally, `rke2lab-manifests.target` exists but isn't properly integrated into the dependency tree (it has `WantedBy=rke2-server.service` and `WantedBy=rke2lab.target` but these don't create the intended hierarchy).

== Current Architecture

=== Target Hierarchy (designed)

[source,text]
----
multi-user.target
  └─ rke2lab.target (main target)
       ├─ rke2lab-tools.target (Nix, Flox install)
       ├─ rke2lab-network.target (network config, wait)
       ├─ rke2lab-bootstrap.target (pre-server: env, config, install)
       ├─ rke2-server.service
       ├─ rke2lab-manifests.target (post-server: manifest installers)
       └─ rke2lab-secrets.target (post-server: secret installers)
----

== Systemd Directives Explained

=== PartOf=

**Purpose**: Defines stop/restart propagation (NOT start propagation).

**Behavior**: When the target unit stops or restarts, units with `PartOf=` are also stopped/restarted.

**Use case**: Services that should be lifecycle-bound to a target. If `rke2lab.target` stops, all services that are `PartOf=rke2lab.target` should also stop.

**Does NOT affect**: Start ordering or dependency visualization.

=== Also=

**Purpose**: Enable/disable multiple units together (systemctl enable/disable synchronization).

**Behavior**: When you run `systemctl enable foo.service`, systemd also enables units listed in `Also=`.

**Use case**: Targets that should automatically enable their prerequisite targets.

**Example**: `rke2lab.target` could have `Also=rke2lab-bootstrap.target rke2lab-manifests.target` so that enabling `rke2lab.target` automatically enables the sub-targets.

**Does NOT affect**: Runtime dependencies or start/stop behavior.

=== WantedBy= vs Requires=/Wants=

**WantedBy=** (in [Install] section):

* Creates symlinks in `/etc/systemd/system/<target>.wants/` during `systemctl enable`
* Defines "this service should start when the target starts"
* Does NOT define ordering (need `After=` for that)
* Does NOT appear in `list-dependencies` unless combined with `Requires=` or `Wants=` in the target

**Requires=/Wants=** (in [Unit] section of the TARGET):

* Runtime dependency: target pulls in the service when starting
* Shows up in `systemctl list-dependencies`
* `Requires=` is strict (failure propagates), `Wants=` is weak (failure ignored)

**Current Problem**: Our services have `WantedBy=<target>` but the targets don't have corresponding `Wants=` or `Requires=`, so `list-dependencies` doesn't show the hierarchy.

== Proposed Solution

=== Strategy

1. **Use `PartOf=` in services**: Bind service lifecycle to their logical target
2. **Use `Wants=` in targets**: Targets explicitly pull in their services (makes hierarchy visible)
3. **Use `Also=` in targets**: Auto-enable prerequisite targets together
4. **Keep `WantedBy=` in services**: For enable/disable symlink creation (systemctl enable behavior)

This creates:

* Clear lifecycle binding (PartOf)
* Visible dependency tree (Wants)
* Convenient enable/disable (Also + WantedBy)

=== Implementation Pattern

==== For sub-targets (e.g., rke2lab-bootstrap.target)

[source,systemd]
----
[Unit]
Description=RKE2 Lab Early Bootstrap (pre-server)
PartOf=rke2lab.target

[Install]
WantedBy=rke2lab.target
Also=rke2lab-network.target rke2lab-tools.target
----

`PartOf=rke2lab.target`: If `rke2lab.target` stops, this target stops too.

`Also=...`: When enabling this target, also enable prerequisite targets.

==== For services (e.g., rke2lab-bootstrap-env.service)

[source,systemd]
----
[Unit]
Description=RKE2Lab bootstrap environment
After=... (existing dependencies)
Requires=... (existing dependencies)
PartOf=rke2lab-bootstrap.target

[Service]
Type=oneshot
...

[Install]
WantedBy=rke2lab-bootstrap.target
----

`PartOf=rke2lab-bootstrap.target`: Lifecycle-bound to the target.

`WantedBy=rke2lab-bootstrap.target`: Creates enable symlink.

==== For targets (add Wants= for their services)

[source,systemd]
----
[Unit]
Description=RKE2 Lab Early Bootstrap (pre-server)
Wants=rke2lab-bootstrap-env.service
Wants=rke2lab-config-install.service
Wants=rke2lab-install.service
Wants=rke2lab-systemd-link.service
Wants=rke2lab-containerd-zfs-mount-config.service
PartOf=rke2lab.target

[Install]
WantedBy=rke2lab.target
----

`Wants=<service>`: Target explicitly pulls in services (visible in `list-dependencies`).

**Note**: Use `Wants=` not `Requires=` because failure of one bootstrap service shouldn't kill the entire target (we want best-effort startup with individual service failure visibility).

=== Special Cases

==== rke2lab-manifests.target

Current issue: It uses `WantedBy=rke2-server.service` which is unusual (targets normally don't use WantedBy on services).

Proposed fix:

[source,systemd]
----
[Unit]
Description=RKE2 Lab Manifest Installers (post-server)
After=rke2-server.service
Requires=rke2-server.service
PartOf=rke2lab.target
Wants=rke2lab-cluster-manifests.service
Wants=rke2lab-storage-manifests.service
Wants=rke2lab-replication-manifests.service
... (all manifest installer services)

[Install]
WantedBy=rke2lab.target
----

Remove: `WantedBy=rke2-server.service` (targets don't belong in service .wants/ dirs).

Add: `PartOf=rke2lab.target` + explicit `Wants=` for all manifest services.

==== rke2lab-cilium-config-manifests.service

Special case: runs BEFORE rke2-server (not after like other manifest installers).

Current:
----
WantedBy=rke2lab.target
Before=rke2-server.service
----

Proposed: Keep current behavior but clarify grouping:

[source,systemd]
----
[Unit]
...
Before=rke2-server.service
After=rke2lab-install.service
PartOf=rke2lab.target  # Direct member, not in manifests-target

[Install]
WantedBy=rke2lab.target  # Direct member
----

Rationale: `rke2lab-manifests.target` is for post-server installers. Cilium config is pre-server, so it's a direct member of `rke2lab.target`.

==== rke2-server.service

Not our unit (RKE2-owned), but we can make it a member of `rke2lab.target` via drop-in:

[source,systemd]
----
# /etc/systemd/system/rke2-server.service.d/rke2lab.conf
[Unit]
PartOf=rke2lab.target

[Install]
WantedBy=rke2lab.target
----

This makes `rke2-server.service` stop when `rke2lab.target` stops.

=== Collect Service Names for Target wants()

Challenge: Targets need to know which services belong to them, but services are created after targets.

Solution: Two-pass approach.

**Pass 1**: Create targets (current code).

**Pass 2**: After all services are synthesized, walk the systemdChart and register services with their targets.

Add to `DefaultManifestSynthesisService.synthesizeInContext()` after line 192:

[source,java]
----
// After domain synthesis completes, register all services with their targets
LOG.debug("Registering services with targets for dependency visualization");
registerServicesWithTargets(systemdChart, systemdContext);
----

New method:

[source,java]
----
private void registerServicesWithTargets(
    SystemdChart systemdChart,
    io.nxmatic.rk2lab.manifests.layers.common.SystemdSynthesisContext context) {

  // Collect all service unit names by iterating systemdChart
  List<String> allServiceNames = new ArrayList<>();
  for (var unit : systemdChart.findAllUnits()) {
    String name = unit.getUnitFileName();
    if (name.endsWith(".service")) {
      allServiceNames.add(name);
    }
  }

  // Filter services by their WantedBy target and register them
  for (String serviceName : allServiceNames) {
    if (serviceName.startsWith("rke2lab-bootstrap-") ||
        List.of("rke2lab-config-install.service",
                "rke2lab-install.service",
                "rke2lab-systemd-link.service",
                "rke2lab-containerd-zfs-mount-config.service").contains(serviceName)) {
      context.bootstrapTarget().wants(serviceName);
    } else if (serviceName.startsWith("rke2lab-nix-") ||
               serviceName.startsWith("rke2lab-flox-") ||
               serviceName.startsWith("rke2lab-cachix-")) {
      context.toolsTarget().wants(serviceName);
    } else if (serviceName.startsWith("rke2lab-network-") ||
               serviceName.equals("rke2lab-route-cleanup.service")) {
      context.networkTarget().wants(serviceName);
    } else if (serviceName.matches("rke2lab-.*-manifests\\.service") &&
               !serviceName.equals("rke2lab-cilium-config-manifests.service")) {
      context.manifestsTarget().wants(serviceName);
    } else if (serviceName.matches("rke2lab-.*-secrets\\.service")) {
      context.secretsTarget().wants(serviceName);
    } else if (List.of("rke2lab-dbus-tcp-system-bus.service",
                       "rke2lab-vip-kubeconfig.service",
                       "rke2lab-cilium-config-manifests.service").contains(serviceName)) {
      context.rke2labTarget().wants(serviceName);
    }
  }

  // Also make rke2labTarget want its sub-targets
  context.rke2labTarget()
      .wants(
          context.bootstrapTarget().getUnitFileName(),
          context.manifestsTarget().getUnitFileName(),
          context.secretsTarget().getUnitFileName(),
          context.networkTarget().getUnitFileName(),
          context.toolsTarget().getUnitFileName(),
          "rke2-server.service");
}
----

**Better approach**: Make services register themselves with targets during creation (observer pattern).

Add to `SystemdChart`:

[source,java]
----
private final Map<String, List<String>> targetServiceRegistry = new LinkedHashMap<>();

public void registerServiceWithTarget(String serviceName, String targetName) {
    targetServiceRegistry.computeIfAbsent(targetName, k -> new ArrayList<>()).add(serviceName);
}

public void finalizeTargetDependencies() {
    for (var entry : targetServiceRegistry.entrySet()) {
        String targetName = entry.getKey();
        List<String> services = entry.getValue();

        var target = findUnit(targetName);
        if (target instanceof SystemdTarget systemdTarget) {
            systemdTarget.wants(services.toArray(String[]::new));
        }
    }
}
----

Then in `SystemdService.wantedBy()`:

[source,java]
----
public SystemdService wantedBy(String... targets) {
    addInstallDirective("WantedBy", targets);

    // Auto-register with target for Wants= directive
    for (String target : targets) {
        if (getChart() instanceof SystemdChart systemdChart) {
            systemdChart.registerServiceWithTarget(getUnitFileName(), target);
        }
    }

    return this;
}
----

Then call `systemdChart.finalizeTargetDependencies()` after all synthesis.

== Lifecycle Benefits

=== Stopping rke2lab.target

[source,bash]
----
systemctl stop rke2lab.target
----

With `PartOf=rke2lab.target` in all services and sub-targets:

* All `rke2lab-*` services stop
* All sub-targets stop
* `rke2-server.service` stops (if using drop-in with `PartOf=`)

Without `PartOf=`, you'd have to stop each service individually.

=== Restarting rke2lab.target

[source,bash]
----
systemctl restart rke2lab.target
----

With `PartOf=`:

* All bound services restart in dependency order
* Clean slate for troubleshooting

=== Enabling/Disabling

[source,bash]
----
systemctl enable rke2lab.target
----

With `Also=` in targets:

* Automatically enables `rke2lab-bootstrap.target`, `rke2lab-manifests.target`, etc.
* No need to manually enable each sub-target

== Summary of Changes

[cols="1,2,2",options="header"]
|===
|Component |Current Behavior |After Changes

|Targets
|Isolated, no service visibility
|Explicitly `wants()` their services → visible hierarchy

|Services
|`WantedBy=<target>` only
|`WantedBy=<target>` + `partOf=<target>` → lifecycle-bound

|Target relationships
|Flat WantedBy links
|`PartOf=` parent + `Also=` prerequisites → proper tree

|rke2lab-manifests.target
|`WantedBy=rke2-server.service` (odd)
|`WantedBy=rke2lab.target` + `PartOf=rke2lab.target` (correct)

|list-dependencies
|Flat, duplicated services
|Hierarchical tree matching design

|Stop propagation
|None
|Stopping `rke2lab.target` stops all bound services

|Enable propagation
|Manual per target
|`systemctl enable rke2lab.target` enables all sub-targets via `Also=`
|===
