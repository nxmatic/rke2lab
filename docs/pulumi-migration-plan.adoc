= Pulumi Migration Plan: Make → Java Pulumi IaC
:toc:
:toclevels: 3
:sectnums:

== Executive Summary

Replace GNU Make-based infrastructure orchestration with **Java Pulumi** for improved maintainability, type safety, and dependency management. Focus migration on highest-pain, highest-benefit components: Incus provisioning and systemd choreography.

**Expected Benefits:**
- Eliminate hard-to-maintain Makefile conditionals and shell arithmetic
- Type-safe infrastructure definitions (catch errors at compile-time, not deploy-time)
- Explicit dependency DAGs (no hidden Make target ordering)
- Parallel task execution (replace sequential systemd targets where safe)
- Reproducible cluster deployments with state tracking
- Better IDE support and refactoring capabilities
- Reduce ~1500 LOC of Make recipes to ~400 LOC of typed Java code

**Timeline:** 4-6 weeks (phased approach, non-blocking to current RKE2 operations)

=== Pain Points (Code Examples)

**Problem 1: Template Variable Binding**
Current approach (make.d/incus/incus-instance-config.yaml):
```yaml
profiles:
  - $(CLUSTER_PROFILE)  # Make variable substitution
devices:
  lan0:
    hwaddr: $(LAN_HWADDR)  # Must compute before template render
  vmnet0:
    hwaddr: $(VMNET_HWADDR)  # Order-dependent
```

Hardcoded in cluster-specific config (rke2.d/bioskop/master/incus-instance-config.yaml):
```yaml
config:
  limits.cpu: 4  # Duplicated from 3 places
  limits.memory: 8GB  # Not DRY
```

→ **Becomes:** Strongly-typed Java config with composition, no duplication.

**Problem 2: Systemd Target Dependencies**
Current (implicit Make target order):
```makefile
$(TARGET_DEPLOY_BIOSKOP_START): $(TARGET_DEPLOY_BIOSKOP_SETUP_CNI)
	systemctl start rke2-kubelet

$(TARGET_DEPLOY_BIOSKOP_SETUP_CNI): $(TARGET_DEPLOY_BIOSKOP_SETUP_NETWORK)
	ssh $(MASTER_IP) 'systemctl start rke2-cni'

# 7 levels deep, hard to visualize, race conditions if any target fails
```

→ **Becomes:** Explicit DAG with error handling and optional parallelization.

**Problem 3: Network Allocation Logic**
Current (split-rules.mk + ipcalc + awk):
```makefile
$(NETWORK_HOST_SUBNETS) := $(shell ipcalc -p $(NETWORK_HOST) $(NETWORK_HOST_PREFIX) | awk '{print $$2}')
$(NETWORK_NODE_SPLIT) := $(shell echo "$(NETWORK_HOST_SUBNETS)" | awk -F'/' '{print $$2 - 3}')
```

Fragile, non-testable, results stored in files.

→ **Becomes:** Testable Java code with proper IP library.

== Migration Phases

=== Phase 1: Foundation (Weeks 1-2) ⭐ Highest ROI

**Scope:** Incus provisioning + systemd choreography

**Deliverables:**
- New `rke2lab-pulumi/` subdirectory with Java Pulumi project
- Incus instance provisioning (replaces `make.d/incus/scripts/`, templates)
- Systemd target orchestration (replaces 7-stage `@bioskop` targets)
- Export cluster state for manual Porch/Tekton integration
- Make targets `provision-incus` + `start@bioskop` call Pulumi instead

**Files to Create:**
```
rke2lab-pulumi/
├── pom.xml
├── Pulumi.yaml
├── Pulumi.yml (stack config)
└── src/main/java/com/rke2lab/
    ├── Infra.java                      # Pulumi program entry point
    ├── configs/
    │   ├── IncusInstanceConfig.java    # Template config (replaces YAML)
    │   ├── NetworkConfig.java          # Shared subnet allocations
    │   └── ClusterConfig.java          # Load from rke2.d/bioskop/config.yaml
    ├── provisioners/
    │   └── IncusProvisioner.java       # Instance lifecycle
    ├── choreography/
    │   └── SystemdChoreography.java    # 7-stage target DAG
    └── utils/
        └── PulumiUtils.java            # Common helpers
```

**Effort:** 40-60 hours
- Infra.java scaffold + Pulumi setup: 4 hours
- IncusInstanceConfig (replace templates): 8 hours
- IncusProvisioner (create instances): 12 hours
- SystemdChoreography (DAG + error handling): 16 hours
- Testing + debugging: 8-12 hours

**Success Criteria:**
- ✅ `pulumi up` creates master + 3 nodes (same config as Make)
- ✅ Systemd stages execute in correct order with proper dependency tracking
- ✅ Instance teardown via `pulumi destroy` (no orphaned Incus instances)
- ✅ Cluster boots and accepts kubectl connections
- ✅ `pulumi export` outputs cluster IPs for downstream tooling

**Integration with Make:**
```makefile
# In Makefile, provision target becomes:
provision-incus:
	cd rke2lab-pulumi && pulumi up --yes

start@bioskop:
	cd rke2lab-pulumi && pulumi exec choreography.start

# Migrate fully to Pulumi later (Phase 4)
```

**How it fits Porch/Tekton/Flux:**
```
Tekton Task: pulumi up → Pulumi exports {masterIP, nodeIPs, kubeconfig}
            ↓
Porch receives cluster connectivity info → KPT packages updated
            ↓
Flux syncs RKE2 manifests to live cluster
```

=== Key Classes (Pseudo-code)

**Infra.java** (Pulumi entry point)
```java
public class Infra {
    public static void main(String[] args) {
        Pulumi.run(ctx -> {
            // Load cluster config from rke2.d/bioskop/config.yaml
            var clusterCfg = ClusterConfig.load("rke2.d/bioskop/config.yaml");
            
            // Allocate subnets
            var networks = NetworkAllocator.allocate(clusterCfg.getNetworkRange());
            ctx.export("networks", networks);
            
            // Provision Incus instances
            var provisioner = new IncusProvisioner(clusterCfg, networks);
            var instances = provisioner.provisionCluster();
            ctx.export("instances", instances);
            
            // Orchestrate systemd stages
            var choreography = new SystemdChoreography(instances);
            choreography.executeDeploymentStages();
            ctx.export("kubeconfig", instances.getMaster().getKubeconfig());
        });
    }
}
```

**NetworkAllocator.java**
```java
public class NetworkAllocator {
    public static SubnetAllocation allocate(String baseNetwork) throws IllegalArgumentException {
        IPAddressString base = new IPAddressString(baseNetwork);
        List<IPAddressString> splits21 = base.getAddress().getPrefixBlock().split(21);
        
        return new SubnetAllocation(
            host = splits21.get(0),  // 10.80.0.0/21
            nodes = splits21.get(0).split(23),  // 8x /23 subnets
            lb = splits21.get(2).split(26),  // 64x /26 subnets
            vip = splits21.get(1).split(24)   // 8x /24 subnets
        );
    }
}
```

**SystemdChoreography.java** (explicit DAG)
```java
public class SystemdChoreography {
    private final List<IncusInstance> instances;
    
    public void executeDeploymentStages() {
        var setupNet = stage("setup-network",
            instances.forEach(i -> i.runCommand("systemctl start rke2-network-setup")),
            DependsOn.master()
        );
        
        var setupKubelet = stage("setup-kubelet",
            instances.getMaster().runCommand("systemctl start rke2-kubelet"),
            DependsOn.after(setupNet)
        );
        
        var cniSetups = instances.stream()
            .map(i -> stage("cni-" + i.getName(),
                i.runCommand("systemctl start rke2-cni"),
                DependsOn.after(setupKubelet)
            ))
            .toList();
        
        // Wait for all parallel stages, then continue
        var apiServer = stage("api-server",
            instances.getMaster().runCommand("systemctl start rke2-api-server"),
            DependsOn.after(cniSetups)
        );
    }
}
```

== Integration Points

=== With Porch/Tekton/Flux

**Current flow:**
```
Incus (Make) → RKE2 → KPT manifests → (manual Porch/Flux)
```

**After Phase 1 (Pulumi + Porch):**
```
Tekton Task: pulumi up
    ├─ Provisions Incus instances
    ├─ Orchestrates systemd stages
    └─ Exports {masterIP, kubeconfig} → pulumi stack export

Porch:
    ├─ Reads cluster IPs
    ├─ Updates KPT package set resources
    └─ Commits updated manifests to Git

Tekton (validation):
    ├─ Validates KPT packages
    ├─ Runs tests against kubeconfig
    └─ Approves for Flux

Flux:
    ├─ Syncs Git manifests
    ├─ Reconciles running state
    └─ Cluster converges
```

**Tekton task definition:**
```yaml
apiVersion: tekton.dev/v1beta1
kind: Task
metadata:
  name: provision-cluster
spec:
  params:
  - name: cluster-name
    default: bioskop
  steps:
  - name: pulumi-up
    image: pulumi/pulumi-java:latest
    workingDir: /workspace/rke2lab-pulumi
    script: |
      pulumi stack select $(params.cluster-name)
      pulumi up --yes
      pulumi export > /workspace/cluster-state.json
```

== Risk Mitigation

=== Risk: Pulumi State Loss
**Mitigation:**
- Commit `Pulumi.yml.lock` file to Git (stack state)
- Store Pulumi backend in versioned S3/Azure (not local)
- Test `pulumi destroy` + `pulumi up` cycle before production

=== Risk: Incus API Incompatibility
**Mitigation:**
- Verify Pulumi Incus provider version against Incus release
- Test against current Incus version early (Phase 1)
- Keep Make provisioning as fallback during Phase 1-2

=== Risk: Java Build/Runtime Issues
**Mitigation:**
- Pin Maven/Java versions in `pom.xml`
- Test builds in CI/CD environment
- Use Maven Wrapper (`mvnw`) for reproducibility

=== Risk: Systemd Stage Execution Fails
**Mitigation:**
- Add verbose logging to each stage (capture stdout/stderr)
- Implement rollback (restore previous snapshot on failure)
- Test systemd stages in isolated environment first

=== A. Comparison: Make vs Pulumi

[cols="1,2,2,1"]
|===
| Aspect | Make | Pulumi | Winner

| **Readability** | Low (DSL learning curve) | Medium (Java, IDE support) | Pulumi
